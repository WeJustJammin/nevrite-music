## Split Group

- **Shared identifiers only**: `partyId`, source identity/version, request/correlation IDs and event envelope metadata.
- **No shared writable tables**: 02a owns claim/ownership state; 02b owns profile/EPK projection; 02c owns qualification and trader state.
- **Cross-split handoff**: an ownership/control change invalidates credential/trader authorization and viewer projections through an outbox event; companions never mutate 02c tables.

All request and response objects below are `z.strictObject`; unknown keys are `422 VALIDATION_FAILED`. IDs, actor identity, classification, verified state and rule-pack results are server-owned. `DecimalVersion` is the lossless positive PostgreSQL `bigint` range `1..9223372036854775807`, serialized as a canonical decimal string. `ApiError` is exactly the four fields above: `code` matches `^[A-Z][A-Z0-9_]{0,63}$`, `message` is safe Unicode of length `1..500`, `requestId` is a UUID, and `details` is always present, valid JSON, at most 16 top-level keys, at most four nested levels, and at most 8 KiB serialized. No RFC 9457 top-level fields are admitted.

`Cursor` is an opaque authenticated token, never a client-decoded offset. Its signed claims are `AuthenticatedCursorClaims`: route, normalized filter digest, sort, deterministic unique tie-breaker, audience, actor, acting party, acting-context version, contract version, issued-at and expiry. The server rejects tampering, expiry beyond 24 hours, route/filter/sort/tie-breaker/audience/actor/acting-context/contract mismatch, or cross-context reuse as `400 CURSOR_INVALID` with `{}` details. Lists remain limited to `1..50` items (default `25`).

### Field validation and refusal matrix

| Schema field / predicate | Exact rule | Error |
|---|---|---|
| every body/query/path | strict declared keys; correct media type; bounded body | `400 INVALID_REQUEST`, `413 PAYLOAD_TOO_LARGE`, `415 UNSUPPORTED_MEDIA_TYPE`, or `422 VALIDATION_FAILED` with safe JSON pointers |
| `partyId`, resource IDs | canonical lowercase UUID; route/body identity cannot disagree | `422 VALIDATION_FAILED`; disclosure-safe `404 RESOURCE_NOT_FOUND` after authz |
| `jurisdiction` | uppercase alpha-2; must have an active authored profile for a hard gate | syntax `422`; absent/expired policy `409 POLICY_UNAVAILABLE` with no borrowed fallback |
| dates | ISO dates; `expiresOn >= issuedOn`; future issue date refused; policy expiry after effective start | `422 DATE_RANGE_INVALID` |
| `evidenceRefs` | unique, governed-object syntax, caller may reference each object, object is ready/non-quarantined and evidence class is allowed by policy | `422 EVIDENCE_INVALID` or disclosure-safe `404` |
| adapter/profile codes | registered lower-snake case and admitted for exact policy version | `409 ADAPTER_UNAVAILABLE` or `422 PROFILE_TYPE_UNSUPPORTED` |
| credential state | transition is in the closed state machine; verified requires current independent adapter/reviewer evidence | `409 STATE_CONFLICT` / `422 VERIFICATION_INSUFFICIENT` |
| trader answers | each required code appears once, type/choices match pinned pack, no unknown code | `422 ANSWER_SET_INVALID` |
| rule-pack confirmations | both literal `true` after exact public fields/copy were disclosed | `422 DISCLOSURE_NOT_CONFIRMED` |
| mismatch metrics | maximum 12 allowlisted bounded numeric keys; no buyer/content/order identity or text | `422 SIGNAL_PAYLOAD_FORBIDDEN` |
| version headers/source versions | decimal string; exact canonical/current version; monotonically increasing producer version | missing CAS `400 INVALID_REQUEST`; stale/conflicting `409 VERSION_CONFLICT`; older observation `200 stale_ignored` |
| idempotency | 8–128 printable ASCII; same actor/operation/key/body digest replays first response | malformed `400 INVALID_REQUEST`; body mismatch `409 IDEMPOTENCY_MISMATCH` |
| policy publish | immutable version, schema/evaluator digest, counsel approval active and scoped, no overlapping effective active version | `409 POLICY_VERSION_CONFLICT` / `403 COUNSEL_APPROVAL_REQUIRED` |

### IA core field mapping

The three canonical IA models use the same required core fields: `owner_id`, `state`, `version`, `created_at`, and `updated_at`. In `credential_record`, `owner_id = subject_party_id`; in `trader_assessment` and `trader_mismatch_signal`, `owner_id = party_id`. Each `owner_id` is a foreign key to the Shard 01 party boundary, each `state` is constrained by the state machine below, each `version` is a positive signed-bigint CAS counter, and the timestamps are UTC `timestamptz` values maintained by the owning RPC. No request may supply or override these fields.

Every mutation RPC atomically writes canonical rows, expected-version transition, idempotency result, append-only audit and outbox rows. Foreign keys use `restrict` for active policy/evidence dependencies and retained tombstones for privacy deletion; no cascade may erase verification or case evidence under hold.

### State machines

| Aggregate | Allowed transitions and invariants |
|---|---|
| Credential | `submitted → reviewing → verified\|rejected\|unknown`; `verified → expired\|revoked\|reviewing`; `reviewing → rejected\|unknown\|verified`; terminal `rejected` may be superseded only by a new record. Expiry is deterministic; provider failure never produces verified. |
| Verification operation | `planned → pending → confirmed\|failed\|manual_review`; ambiguous provider outcome remains pending, is reconciled once, and never blind-retries a distinct provider operation. |
| Evidence observation | `received → accepted_private\|duplicate\|stale_ignored\|unsupported_profile\|withdrawal_applied`; a later monotonic source version may supersede, never mutate, an accepted observation. |
| Trader assessment | `undetermined → private\|trader\|review_required`; `private\|trader → review_required` on rule/signal change; review resolves to `private\|trader\|undetermined`; prior assessment becomes superseded atomically. Seller cannot choose classification. |
| Trader review | `open → resolved\|withdrawn`; only current assigned lease and exact assessment version resolves; withdrawal is system-only for invalidated source and restores no eligibility by itself. |
| Policy version | `scheduled → active → expired\|revoked`; immutable after publication; exactly one effective version per jurisdiction/profile/time. Missing/expired is unavailable, never fallback. |

## Middleware & Policies

### Privacy, evidence and abuse rules

- Credential public projection contains only approved issuer label, profile type, state, method class, issue/expiry and provenance treatment. It excludes identifier/reference, evidence, reviewer, legal identity and exact adapter response.
- Trader answers, address/jurisdiction evidence, mismatch metrics and operator notes are protected and structurally absent from profiles. Commerce receives only pinned classification, rule versions, approved disclosure fields and reason code.
- Credential verification and trader review cannot be self-approved. Same human, active organization co-member, mandate relation or conflicting assignment is refused and audited.
- Limits combine IP, authenticated human, acting party, target party, credential/review and producer. Replays do not consume business quota; distinct failed attempts do.
- Enumeration-safe lookup returns `404` after authentication/assignment boundary. `403` is used when the resource is known through an already-authorized collection but the requested action is denied.
- Evidence objects are malware-scanned, ready, retained by record-class policy and served only by short-lived authorized object access. URLs and bytes never enter events or logs.
- Known/suspected minor evidence uses the stricter safeguarding gate and cannot be published until the approved minor policy exists.

### Credential submission and verification

1. Resolve person, party, acting context and current ownership/mandate version. A provisional owner may only create a private proposal.
2. Resolve the exact active jurisdiction/profile policy. `US` is the only authored launch jurisdiction; any absent profile returns unsupported/unknown without borrowing terminology.
3. Validate issuer, dates, evidence-object authorization/readiness and requested visibility. Commit record, evidence links, idempotency, audit and `profile.credential.changed.v1` outbox atomically.
4. For verification, commit a canonical provider operation and BE00 job before provider I/O. Worker refetches state/version and adapter admission, sends the minimum payload with operation ID, then records a normalized result.
5. Signed callbacks enter BE00 webhook receipt/dedupe, map to the canonical operation, and transition only the expected credential version. Ambiguous/timeouts remain pending or manual review.
6. Reviewer decisions require current assignment/lease, capability, MFA, policy version, independent evidence and reason. Verified state and profile visibility are separate: verified private stays private.
7. Expiry/revocation commits state, audit, outbox and projection invalidation. Consumers refetch the viewer-safe/current qualification projection and apply their own predeclared consequence.

### External evidence ingestion

The producer commits its own fact first. Its outbox adapter calls QUAL-08 with sufficient bounded versioned evidence; 02c does not read the producer store. Self-reported education evidence remains private/unverified. Issuer-verified evidence may create or update a private submitted record only under an active exact policy; a withdrawal revokes the linked evidence and re-evaluates state. Duplicate and stale delivery is a successful no-op.

### Trader declaration, mismatch and eligibility

1. A registered commerce producer detects first-sale need and calls TRD-09. Missing assessment/policy returns a fail-closed business result, never a protocol error or guessed label.
2. The seller fetches TRD-01, sees exact fields/copy that will become public, confirms both, and submits versioned situational answers. The evaluator—not the seller—computes classification in the transaction.
3. TRD-02/04 commits the new current assessment, supersedes the prior version, audits only answer-field names/digest, and publishes `profile.trader-status.changed.v1`.
4. A producer sends only allowlisted bounded mismatch metrics through TRD-05. The transaction dedupes the source, moves assessment to `review_required`, opens one review and publishes the event. Commerce pauses public listings while preserving drafts and orders.
5. The assigned operator resolves under lease/MFA/rule version. A disposition sets a valid classification or `undetermined`; it never adjudicates law. Any stale rule pack requires seller redeclaration.
6. TRD-09 rechecks seller and buyer jurisdiction rule/disclosure versions at listing publication. Ineligible is a typed `200` business result so retries cannot accidentally publish.

### BE00 event-envelope inheritance

Every 02c outbox event and Queue message uses the BE00 lossless envelope. The owning transaction writes the envelope with the canonical aggregate version; `correlationId` is the command/request trace and `causationId` is the initiating event ID or `null` for a direct command. These fields are immutable after commit.

```ts
type PlatformEvent<T extends JsonValue> = {
  eventId: string;
  eventType: string;
  schemaVersion: number;
  occurredAt: string;
  aggregateType: string;
  aggregateId: string;
  aggregateVersion: string; // positive bigint decimal
  correlationId: string;
  causationId: string | null;
  actorId: string | null;
  actingPartyId: string | null;
  payload: T;
};

type QueueEnvelope = {
  eventId: string;
  eventType: string;
  schemaVersion: number;
  aggregateType: string;
  aggregateId: string;
  aggregateVersion: string; // required for stale/out-of-order checks
  causationId: string | null;
  correlationId: string;
};
```

The exact `(eventType, schemaVersion)` pair is authoritative. `profile.credential.changed.v1`, `profile.trader-status.changed.v1`, and `profile.projection.invalidated.v1` carry `schemaVersion: 1`; their payloads remain the bounded identifiers shown above. Queue delivery is Cloudflare at-least-once with explicit acknowledgement, `max_retries = 3`, bounded backoff, and a configured DLQ. Each consumer persists an inbox key `(consumer, eventId)`, dedupes before applying work, and CAS-checks `aggregateVersion`; duplicates replay the durable result and stale/out-of-order versions are acknowledged as no-ops. Envelope plus payload is strict and at most 8 KiB. It contains no raw PII, request bodies, provider payloads, evidence or media bytes/URLs, secrets, authority claims, buyer/order identity, or operator notes.
