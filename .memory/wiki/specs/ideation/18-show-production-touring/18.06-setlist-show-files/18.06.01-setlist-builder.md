# Feature: Setlist Builder

> **Number**: 18.06.01
> **Parent**: [Setlist & Show Files](./18.06-setlist-show-files-index.md)
> **Status**: [PARTIAL]
> **Last updated**: 2026-07-17

## Overview

The versioned, timed, keyed running order for a show: songs in sequence with durations, keys,
tempos, segues, and per-member cues. It looks like a list and behaves like the show's spine —
every downstream time in the domain (set end, curfew margin, changeover) is arithmetic on this
object.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Builds and edits the set — this is *their* document in a way nothing else in the domain is. Sees keys and tempos, adds their own cues, and argues about the running order. Band members share edit rights. |
| Producer | Full | Uses it as the timing source for the run of show, ensures the set fits the slot, and manages cue accuracy against show files. On a bigger act the MD/production lens owns the structure while the band owns the content. |
| Operator | None | **No access.** The venue needs the *duration*, which reaches them via the run of show (18.07.01). They do not need to know the songs, and a leaked encore is a real (if small) harm. |
| Fan | None | Not before the show. After it, the *performed* setlist (18.06.04) may be published — a different object with a different truth status. |

## Behavior

Songs are ordered with per-song durations that roll up to a set duration, which the run of show
consumes. Versions exist because setlists change per night on a tour and the act needs last night's
back. Per-member cues attach to songs and render into each performer's stage view (18.06.02).

**Scope (Q-02, resolved D-05)**: a setlist is **tour-scoped** — it belongs to a tour/run, not to
the band in the abstract, because the version chain (Night 1 → Night 2 → …) is a property of a
tour and would be meaningless spanning two unrelated tours. The **song catalogue it draws from is
band-scoped** (owned by the act, domain 01), so the same catalogue feeds every tour the band plays.
Edit rights follow the band's membership: every current band member can edit any of the band's
tour setlists. A one-off show is modelled as a tour of length one.

### Happy Path

1. Musician creates a setlist for the tour from the act's song catalogue.
2. Songs are ordered; durations default from measured or estimated values.
3. Set duration rolls up; the run of show shows it against the slot length.
4. Per-member cues are added ("Jo: switch to acoustic before track 6").
5. The night's variant is versioned; tomorrow's set starts from tonight's.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Set overruns the slot | Flagged against the slot, and against curfew via 18.07.02 | "Set runs 52 min — your slot is 45" |
| Durations are estimates | Marked as such; downstream times inherit the uncertainty | "Set: ~52 min (7 of 14 songs never measured)" |
| Encore uncertainty | Encores are conditional items with their own duration | "Set 45 min + encore 8 min = 53 if played" |
| Segues/medleys | Duration isn't the sum of parts; the segue is the item | "3-song segue: 11 min (not 4+4+4)" |
| Different set per night | Versioning, not copies | "Night 3 — derived from Night 2, 2 changes" |
| Band members disagree mid-edit | Concurrent editing on a shared band document | "[Name] is editing — 2 changes since you opened" |
| Song not in the catalogue (cover, new song) | Ad-hoc entry allowed; breaks the rights linkage (Q-03) | "Not in your catalogue — won't link to a work" |
| Non-band member opens the setlist link | No access — the setlist is band-private (D-04); shared links resolve to membership, not to the URL | "You're not a member of this act" / 404 |
| Catalogue song deleted while it sits in a setlist | The setlist keeps a snapshot (title, duration, key) so the running order and downstream times survive; only the live rights link is severed | "This song was removed from the catalogue — kept as a plain entry" |
| Member rolls back to an earlier night's version | Prior versions are immutable snapshots; a rollback derives a *new* version from the old one rather than mutating history | "Restored from Night 2 as a new version — Night 4" |
| Two songs given the same running-order position | Order is a total sequence, not free-form; the second insert pushes, it does not collide | Rows renumber automatically |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | A setlist is a trivial list and barely warrants a feature | First-pass instinct | ❌ REJECTED — it is the **timing source for the entire show day**. Set duration → set times → changeover → curfew margin → whether the venue gets fined. Every one of those numbers is arithmetic on this object, and today every one of them is a TM's guess because the setlist lives on paper. Cheap object, wide blast radius. |
| DT-02 | Durations can be estimated and that's fine | Naive modelling | ❌ REJECTED — an estimated set duration produces an estimated curfew margin, and curfew breaches cost real money and licences. The uncertainty must propagate visibly (18.06 D-04). "~52 min, 7 songs unmeasured" is honest; "52 min" is a fabrication with legal consequences downstream. |
| DT-03 | The venue should see the setlist | Transparency instinct | ❌ REJECTED — they need the duration, not the songs. The setlist is the act's creative property and the encore is deliberately a surprise. Exposing it buys nothing and leaks something. This is the clearest "explicit None" in the domain. |
| DT-04 | Duration is the sum of song durations | Naive modelling | ❌ REJECTED — segues, medleys, banter, tuning breaks and encores all break the sum. A 14-song set is not 14 durations added up, and the gap between the sum and reality is exactly the margin a curfew check needs. Structural items (segue, break, encore-conditional) are required. |
| DT-05 | A setlist is band-scoped — one living document the band reuses | Scope modelling (Q-02) | ❌ REJECTED — the version chain (Night 1 → Night 2 → …) is inherently tour-scoped; a chain spanning two unrelated tours is nonsense. **Tour-scoped setlist, band-scoped catalogue** is the split that holds: the songs are reused, the running order is not. Edit rights ride band membership, which is why a departing member cleanly loses access (D-05). |
| DT-06 | Versions can be edited in place to fix a mistake | Convenience instinct | ❌ REJECTED — a version is a snapshot of intent for a specific night; editing it retroactively destroys the very "what we meant to do" record the thesis (D-18) exists to protect. Rollback derives a new version; history is immutable. This mirrors 18.06 D-01 (plan vs performance) one level down, inside the plan itself. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | The setlist is the show day's timing source | Every downstream time is arithmetic on it; today they're all guesses |
| D-02 | Duration uncertainty propagates visibly downstream | An estimated curfew margin causes a real fine |
| D-03 | Structural items (segue, break, conditional encore) are first-class | A set is not the sum of its song durations |
| D-04 | No venue access | They need the duration; the songs are the act's property |
| D-05 | Setlist is tour-scoped; song catalogue is band-scoped (resolves Q-02) | The version chain is a tour property and is meaningless across tours; the catalogue is reused across every tour. Edit rights follow band membership; a one-off show is a tour of length one. |
| D-06 | Versions are immutable snapshots; rollback derives a new version | Editing a night's version in place destroys the intent record the thesis protects — the plan-vs-fact split (18.06 D-01) applies inside the plan too |
