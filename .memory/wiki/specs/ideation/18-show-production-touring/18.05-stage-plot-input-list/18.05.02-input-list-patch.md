# Feature: Input List & Patch Sheet

> **Number**: 18.05.02
> **Parent**: [Stage Plot & Input List](./18.05-stage-plot-input-list-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The channel-by-channel list of what plugs into the console: source, mic or DI, phantom, stand, and
the venue-assigned physical patch. It is the single most-used document at load-in, the one most
often out of date, and the only document in this domain that both the act and the venue legitimately
write to — the act owns the sources, the house engineer owns the patch.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Config (own inputs) | Declares their own sources — "bass: DI + mic on the cab, both". Rarely reads the whole list; cares that their DI exists. |
| Producer | Full | Owns the list, sets mic/DI preferences per source, and reads it against the room's channel count. The FOH lens is the primary author and consumer. |
| Operator | **Full (patch column)** | The house engineer assigns each source to a physical input on their stage box and returns the patched list. This column is theirs — the act cannot know which input is free in a room they've never seen. Read-only on every other column. |
| Fan | None | Never visible. |

## Behavior

Rows derive from the plot's sources (18.05.01), so the counts cannot disagree. Each row carries
source, mic/DI preference (with an acceptable-substitutes rule), phantom, stand type, and a patch
number the venue fills. Total channel count is diffed against the room's console and stage box
capacity — the most consequential number in the whole diff.

### Happy Path

1. Plot is built; input rows auto-generate from its sources.
2. Producer sets mic/DI preferences and marks which are hard vs substitutable.
3. Channel count is diffed against the venue's console — 28 inputs into a 32-channel desk: match.
4. House engineer fills the patch column and returns it in the advance.
5. The patched list is in the frozen pack; load-in works from one document both sides wrote.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Channel count exceeds the console | Shortfall — the show cannot run as specified | "34 inputs into a 32-ch desk — 2 must be dropped or submixed" |
| Venue has the channels but not the stage box lines | Two different numbers; both diffed | "Desk has 32; stage box has 24 lines" |
| Requested mic unavailable | Substitution — needs the act's acceptable-substitutes rule, or it's a redline | "No Beta 52 — house offers D6. Acceptable?" |
| Plot changes after the patch was assigned | Patch invalidated where sources changed; venue re-notified | "3 sources changed since the venue patched — re-send?" |
| Act uses their own console/digital split | Patch is theirs; the venue supplies lines only | "Act brings console — venue supplies split only" |
| Support acts share the list | Shared rows + per-act rows; changeover implications | "12 shared channels, 6 headline-only" |
| Wireless/RF frequencies | Coordination is a real and legally regulated problem | `[PENDING — /ideate-discover Step 5 deepening]` — RF coordination not modelled |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | List opened | Row skeleton |
| Empty | No plot sources | "Build the plot first — rows come from it" |
| Populated | Rows exist | Channel table with count, diff status, patch column state |
| Error | Save failed | "Couldn't save — retry" |
| Partial | Patch not returned | "Venue hasn't patched — 0 of 28 assigned" |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | The input list is authored independently of the plot | Incumbent behaviour (they're separate files) | ❌ REJECTED — this is the origin of the industry's most common production error: the plot shows three vocal mics, the input list has two. Deriving rows from plot sources makes the contradiction **structurally impossible** rather than something to check. This is the sub-domain's justification. |
| DT-02 | Channel count is the diff's most consequential number | Domain expert lens | ✅ CONFIRMED — most rider shortfalls are inconvenient (wrong mic, no towels); exceeding the console's channel count means the show *cannot run as written*, and it's discovered at load-in. It is also a pure integer comparison — the easiest check in the domain with the highest consequence. |
| DT-03 | The venue should not write into the act's document | Ownership instinct | ❌ REJECTED — the patch is genuinely the venue's knowledge. Forcing the act to guess, or making the venue maintain a parallel copy, reproduces the two-documents problem this feature exists to end. **Column-level co-authorship is the correct model**, and it is the only instance of it in the domain — which is itself worth noting for whoever specs the permission layer. |
| DT-04 | One channel count is enough | Naive modelling | ❌ REJECTED — a room can have a 32-channel desk and only 24 stage box lines, or a desk at FOH with no monitor desk at all. The act's 28 sources fail against the stage box, not the console. Modelling one number hides the failure that actually happens. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Rows derive from plot sources — never authored independently | Makes the plot/input-list contradiction structurally impossible |
| D-02 | The patch column is venue-writable; every other column is act-owned | The house engineer holds knowledge the act cannot have; the alternative is two documents |
| D-03 | Console channels and stage box lines are separate diff targets | A 32-ch desk with 24 stage lines fails a 28-source act, and only one of those numbers reveals it |
