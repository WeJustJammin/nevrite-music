# Feature: Stage Plot Builder

> **Number**: 18.05.01
> **Parent**: [Stage Plot & Input List](./18.05-stage-plot-input-list-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Where everything and everyone physically goes on stage: performers, backline, amps, risers, DI
boxes, wedges, power drops. It is the source document for the input list and the monitor spec, and
the thing a house crew reads at 09:00 to know how to set the room before anyone arrives.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Config (own position) | Places themselves and their own gear — "I'm stage left, amp behind me, two DIs, wedge at my feet". Sees where they'll be standing tonight. |
| Producer | Full | Owns the plot. Assembles it, resolves conflicts between members, and is the person who knows whether it fits the room. |
| Operator | Read-only | Reads it to set the stage before load-in. Cannot edit — but *can* report that it won't fit their stage, which becomes a shortfall in the diff (18.03.02), not an edit of the act's document. |
| Fan | None | Never visible. |

## Behavior

The plot is structured data (positioned, typed items) that renders as a drawing — not a drawing
with labels. Each item has a type, position, and attributes; items that produce sound produce input
list rows (18.05.02). The plot's footprint is diffable against a venue's stage dimensions, which is
how "we don't fit" surfaces weeks out rather than at load-in.

### Happy Path

1. Producer creates the plot, starting from the act's default or a template.
2. Members are placed with their instruments; backline items are added.
3. Sources auto-generate input list rows; the count updates live.
4. The plot's footprint is diffed against each venue's stage dimensions.
5. A venue with a stage too shallow for the drum riser flags at advance, not on the day.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Plot doesn't fit the stage | Footprint vs stage dimensions shortfall in the diff | "Stage is 4m deep — your plot needs 5.2m" |
| Venue has no stage dimensions listed | `unknown`, not `match` (18.03.02 D-01) | "No stage dimensions for this room" |
| Two members claim the same position | Conflict at authoring | "[Name] is already stage-left-front" |
| Act plays a shared-backline festival slot | Plot must express what's theirs vs shared/house | "Mark items as: ours / house / shared" |
| Support act's plot overlaps the headliner's | Multi-act plot layering (18.02) | "Support kit conflicts with headline riser position" |
| Plot is a JPEG the act already has | Import as an attachment, explicitly undiffable | "Uploaded image — can't be checked against venues" |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Plot opened | Canvas skeleton |
| Empty | No plot | "No stage plot" + template / import CTAs |
| Populated | Items placed | Rendered plot + derived input count + footprint |
| Error | Save failed | "Couldn't save — retry" |
| Partial | Some items unpositioned | "3 items not placed — they won't appear on the plot" |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | The plot is a drawing, so this is a drawing tool | Incumbent behaviour (every plot is a JPEG or a PowerPoint) | ❌ REJECTED — a drawing is an *output*. If the plot is pixels, it cannot generate the input list, cannot be diffed against stage dimensions, and cannot flag that the riser doesn't fit. Structured-first, rendered-second — the same hinge as 18.04.01 DT-01. The industry's plots are JPEGs and that is exactly why they contradict the input list. |
| DT-02 | Stage dimensions are a nice-to-have diff | Scope lens | ✅ CONFIRMED as high value — "we don't fit" is discovered at load-in with a truck outside and a curfew running. It is a purely geometric check the platform can do weeks out, and it requires only two numbers from the venue. Cheap check, expensive failure. |
| DT-03 | A spatial editor is required for this to be useful | Product instinct | ⚠️ CHALLENGED — see 18.05 Q-01. The *diffable value* (footprint, source count, item inventory) lives entirely in the structured data. A drag-and-drop canvas is a large build that may be mostly cosmetic. A structured list with a generated rendering might deliver 90% of the value. Flagged rather than assumed — this is a real build-cost decision. |
| DT-04 | The plot is act-level and stable | Naive modelling | ❌ REJECTED — the plot changes per *set type* and per *room size* (fly date with backline hire vs the full production). It varies on a different cadence to the rider, which is why 18.05 Q-03 asks whether they version together. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Structured positioned items first; the drawing is a render | A JPEG plot can't generate an input list or be diffed — which is why plots and input lists contradict each other today |
| D-02 | Footprint is diffed against stage dimensions | Two numbers from the venue prevent a discovery made at load-in with the truck outside |
