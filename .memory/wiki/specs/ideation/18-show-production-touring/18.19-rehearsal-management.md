# Feature: Rehearsal & Production Rehearsal Management

> **Number**: 18.19
> **Parent**: [Show Production & Touring](./show-production-touring-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The rehearsal block before a tour, modelled as an event subtype rather than a separate object: a
date, a room, a call time, a setlist to run, and a readiness checklist. Production rehearsal is
where the show is actually assembled — the setlist gets timed, the plot gets built, the show files
get tested — so it is where most of this domain's objects reach first contact with reality.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Sees rehearsal dates, room, call time and the setlist to learn; marks their own readiness ("I know these 12, not the new one"). This is the persona rehearsal exists for. |
| Producer | Full | Books the block, schedules what gets run, uses rehearsal to time the setlist for real, test show files and validate the plot. Signs off production readiness before day one of the tour. |
| Operator | Config | As a rehearsal-space operator: receives the booking (via 16/17), sees the technical needs and call times, supplies the room and backline. Sees nothing of the tour beyond this block. |
| Fan | None | Rehearsals are private. Any fan-facing rehearsal content (behind-the-scenes clips) is a promotion artifact in domain 21, not a production record. |

## Behavior

A rehearsal is an event with `type = rehearsal`: it has a venue (a rehearsal room from 16), a
schedule, a crew call, and a backline manifest — but no bill, no ticketing, no settlement. Its
distinguishing capability is the **readiness checklist**: which songs are run, which show files are
tested, which plot items are verified, feeding a go/no-go before the first date.

### Happy Path

1. Producer creates a rehearsal block against the tour, booking a room from 16.
2. Setlist (18.06.01) is attached; the block schedules which songs are run when.
3. Songs are run; real durations captured and written back to the setlist's timings.
4. Show files and the plot are verified; readiness items tick off.
5. Producer signs off production readiness; unresolved items surface on the first show's advance.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Rehearsal room lacks the tour's backline | Same capability diff as a show (18.03.02), against a rehearsal room's spec | "Room has no bass rig — rent or bring?" |
| Setlist changes after rehearsal | Unrehearsed songs flagged on the show's readiness state | "2 songs in tonight's set were never rehearsed" |
| Rehearsal runs but no timings captured | Setlist keeps estimates; run of show inherits soft numbers | "Set times are estimates — not measured" |
| Band rehearses remotely | Out of scope here — routes to the real-time rooms cross-cut / domain 08 | "Remote rehearsal happens in a jam room" |
| No rehearsal at all (common for small acts) | Readiness checklist still exists, unticked; tour proceeds | "No rehearsal booked — 0/9 readiness items verified" |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Block opened | Schedule + readiness skeleton |
| Empty | No rehearsal booked | "No rehearsal on this tour" + book CTA |
| Populated | Block scheduled | Day schedule + readiness checklist with progress |
| Error | Room booking failed | "Couldn't hold the room — retry / choose another" |
| Partial | Some readiness items unverified | "6/9 verified — 3 items go into the tour unproven" |

| DT-01 | Rehearsal is just an event with a different type and needs no node | Node Classification Gate | ⚠️ PARTIALLY CONFIRMED — it *is* an event subtype (that's D-01 below), but the **readiness checklist** is a capability that exists nowhere else and is the only thing standing between "we booked a room" and "the show works". The node survives on that, not on the booking. |
| DT-02 | Rehearsal's real product value is capturing true setlist timings | Domain expert lens | ✅ CONFIRMED — every downstream number (run of show, changeover, curfew margin) is currently an estimate typed by a TM. | DT-03 | Booking the room belongs here | Boundary lens | ❌ REJECTED — the room is a space in 16 booked through 17, identically to a studio or a venue. Duplicating booking here would fork the calendar. This feature *consumes* a booking. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Rehearsal is an event subtype, not a separate record | It has a room, schedule, crew and manifest — no bill, tickets or settlement |
| D-02 | Room booking is consumed from 16/17, never duplicated here | Forking the space calendar would create two truths about a room's availability |
| D-03 | The node's justification is the readiness checklist, not the booking | Nothing else measures whether the show is actually assembled |
