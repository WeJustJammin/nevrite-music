# Feature: Green Touring & Carbon Reporting

> **Number**: 18.20
> **Parent**: [Show Production & Touring](./show-production-touring-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Derives a tour's carbon footprint from data the platform already holds — routing distances,
vehicle types, flights, hotel nights, freight weight — and reports it in the forms festivals,
funders and labels increasingly demand. The insight is that nobody will enter this data twice: the
only viable carbon report is one computed as a byproduct of logistics that already exist here.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only + Reports | Sees the tour's footprint and the biggest contributors; exports a report when a festival or funder asks. Some acts care deeply; most engage only when someone demands a number. |
| Producer | Full | Owns the inputs (vehicle types, freight, flights vs ground), sees where the footprint actually comes from, and can compare routing options on carbon alongside cost and drive time. |
| Operator | Config + Reports | Supplies venue-side facts (energy source, on-site power, waste) and can report their own venue's figures. Increasingly the party being asked by their own funders and local authority. |
| Fan | None | No fan surface here. Fan-facing sustainability claims are marketing (domain 21) and must not be generated from an unaudited internal estimate — that is a greenwashing risk, not a feature. |

## Behavior

Emission factors are applied to logistics data already captured elsewhere in the domain: distances
from routing (18.11.02), vehicles from ground transport (18.12.03), hotel nights from
accommodation (18.12.01), freight from the backline manifest (18.09.01). The output is an estimate
with a stated methodology and explicit gaps — never an unqualified number.

### Happy Path

1. Tour is routed and travel is booked; the footprint accrues automatically with no extra entry.
2. Producer opens the carbon view; the estimate breaks down by transport / freight / accommodation.
3. Producer sets a vehicle type (diesel splitter vs EV) and the estimate refines.
4. A festival requests a report; Producer exports it in the requested format with methodology stated.
5. On the next tour, the routing comparison shows carbon alongside drive time and cost.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Logistics data incomplete | Estimate is partial and says so, with coverage % | "Estimate covers 6 of 11 dates — 54% of travel" |
| Emission factors are out of date or region-wrong | Factor set and version are stated on every report | "Using DEFRA 2026 factors — UK/EU" |
| Off-platform travel (someone drove themselves) | Manual entry or explicit exclusion; never assumed zero | "3 legs unlogged — excluded, not counted as zero" |
| Report used as a public sustainability claim | Methodology + gaps travel with the export; not an audited figure | Footer: "Self-reported estimate. Not independently verified." |
| Venue and artist both count the same show's energy | Double-counting flagged at the boundary | "Venue energy is reported by the venue — excluded from your scope" |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Carbon view opened | Breakdown skeleton |
| Empty | No logistics data | "Nothing to calculate — route the tour first" |
| Populated | Logistics present | Breakdown by source with coverage % and factor set |
| Error | Factor set unavailable | "Can't calculate — factor data unavailable" |
| Partial | Some legs unlogged | Estimate with an explicit coverage bar and gap list |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | This is virtue-signalling scope and should be cut | Scope lens | ⚠️ PARTIALLY REJECTED — it is `wont` for now (see MoSCoW), but not because it is worthless. Festivals, arts funders and labels now *require* carbon data as a condition of booking and funding, and EU CSRD pushes reporting down the supply chain. It is a real gate on real money, just not for the beachhead audience. |
| DT-02 | Musicians will enter carbon data if asked | Naive modelling | ❌ REJECTED — nobody enters logistics twice. Every standalone tour-carbon tool has this failure mode. The *only* reason this feature is defensible on WeJammin is that the routing, vehicles, hotels and freight are already here. It is a derivation, not a data-entry product. This is a clean instance of the consolidation→byproduct pattern in D-18. |
| DT-03 | The platform should report a confident number | Product instinct | ❌ REJECTED — an unqualified carbon number from partial data is a greenwashing liability for the artist who publishes it. Coverage %, factor set version and exclusions must travel with the figure, and it must never be marketed as audited. |
| DT-04 | Venue energy belongs in the artist's footprint | Methodology lens | ❌ REJECTED — it is the venue's scope, and counting it on both sides double-counts. The scope boundary is a real methodological decision the feature must encode, not dodge. |
| DT-05 | Carbon should be a routing input, not just a report | Domain expert lens | ✅ CONFIRMED — the useful version is comparing route options on carbon *before* booking, alongside cost and drive time. A retrospective report changes nothing; a routing input changes the route. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Carbon is derived from existing logistics data — never separately entered | Nobody enters logistics twice; this is why standalone tour-carbon tools fail |
| D-02 | Every figure carries coverage %, factor set version and exclusions | An unqualified number from partial data is a greenwashing liability for the artist |
| D-03 | Venue-side energy is out of the artist's scope | Counting it on both sides double-counts |
