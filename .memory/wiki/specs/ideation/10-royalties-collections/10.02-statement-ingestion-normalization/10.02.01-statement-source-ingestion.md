# Feature: Statement Source Connection & Ingestion

> **Number**: 10.02.01
> **Parent**: [Statement Ingestion & Normalization](./10.02-statement-ingestion-normalization-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Getting statements **into the platform at all**: registering which sources a user has income from, receiving each statement (uploaded, forwarded, or fetched where a source permits it), and tracking arrival against the cadence that source is supposed to keep. A statement that never arrives is as much a finding as one that does.

This is the front door of the domain's ungated half. It requires no society relationship, no publisher standing and no accreditation — only a user with a PDF their distributor already emailed them.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Declares their income sources (PRS, DistroKid, their label, a sync agent) and feeds statements in. The value arrives before any parsing does: `personas.md` describes their money as living in "a spreadsheet" across six platforms, and a list of sources with arrival status is already more than they have. |
| Producer | Full | Same, at higher volume and for entities they administer — a producer with a label ingests statements about other people's earnings, which is where the privacy boundary (parent `Q-03`) becomes real rather than theoretical. |
| Operator | None | A venue pays a PRS licence; it does not receive royalty statements. |
| Fan | None | No surface. |

## Behavior

The model is a **source registry**: (source, kind, the party it pays, expected cadence, currency, last received, next expected). The registry exists independently of any statement having arrived — which is the point. Declaring "I am with PRS and I get paid quarterly" is what makes a missing distribution detectable, and missing distributions are `10.05.03`'s highest-confidence leakage input.

Three intake channels, in descending order of realism:

- **Upload** — the user drops the file. Universally available, works for every source that exists, and is the only channel that does not depend on a counterparty's cooperation.
- **Forward** — the user forwards the statement email to a platform address. Low friction at the moment the statement actually appears, which is when the user is already thinking about it.
- **Fetch** — the platform pulls it. Available from very few sources, and where it is available it usually means **holding the user's credentials for their PRO or distributor** — a security posture the platform should be reluctant about rather than eager for (see Q-01).

The parent's D-03 governs everything here: **an ingested statement is evidence, not truth.** The platform records that a source asserted something on a date, in a file it retains. It does not adopt the assertion.

### Happy Path

1. Musician declares a source and its expected cadence
2. Statement arrives — uploaded or forwarded
3. System records receipt against the source and the period it claims to cover, and retains the original file unchanged
4. Statement is handed to `10.02.02` for parsing
5. Arrival is reconciled against the expected cadence; the next expectation is set

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Statement never arrives | The finding this feature exists to produce. **Silence is the signal**, and only a declared cadence makes it visible | Overdue against the source's cadence — the same refusal-to-model-silence-as-progress as `10.01.03` D-03 |
| User has no idea what sources they have | Extremely common, and the honest starting state for the persona `personas.md` describes | The registry is a discovery exercise, not a settings form |
| Statement covers many people (label statement) | One user ingests a document about many parties' earnings. Parent `Q-03` | `[PENDING — /ideate-discover Step 5 deepening]` — a real privacy boundary, unresolved |
| Same statement uploaded twice | Duplicate income if not caught. A confident, doubled, wrong number | Deduplication by (source, period, content) — must be near-certain, because the failure is silent and monetary |
| Restated statement for a period already ingested | Not a duplicate — a **restatement**. The distinction is the whole of `10.03.04` | Both retained (parent D-04); never overwritten |
| Fetch credentials break / MFA | The connected channel degrades to upload, silently, exactly when nobody is watching | Must fail loudly; a stale connected source is worse than no connected source |
| Source pays in a currency the user does not think in | Normal for foreign income | → `10.02.04` |
| File is a scanned PDF of a printed statement | Real. Older labels and societies do this | `[PENDING — Step 5]` — parsing feasibility is `10.02.02`'s problem, intake is not blocked |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Declared | Source registered, nothing received | Expectation set; next-expected date |
| Received | Statement in, unparsed | Received, with the original retained |
| Parsed | `10.02.02` succeeded | Handed onward |
| Overdue | Cadence breached, nothing arrived | **A finding**, routed to `10.05.03` |
| Duplicate | Content matches a prior ingest | Rejected, with the prior named |
| Restatement | Same period, different content | Both kept; `10.03.04` engaged |
| Unreadable | Parse failed | Retained; the file is still evidence even when the platform cannot read it |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | The platform should connect to sources via API — manual upload is a stopgap that a serious product would outgrow | Standard product instinct; every fintech aggregator works this way | ❌ **REJECTED as the primary channel.** Almost no PRO or distributor offers a statement API. Where a "connection" exists it is usually credential-based scraping of a member portal, which means the platform holds a user's PRO login — a posture that is a standing breach liability (`security-first.md`) and that MFA breaks anyway. **Upload is not the stopgap; it is the durable channel**, because it is the only one that works for every source and depends on nobody's cooperation. The design consequence matters: build for the file, treat fetch as a per-source luxury, and never let the architecture assume a connection exists. |
| DT-02 | The feature's job is to receive statements | The name of the feature | ❌ **REJECTED as half the job — and the less valuable half.** The **source registry is the feature**, and its highest-value output is produced when nothing arrives. A declared source with a known cadence turns silence into an overdue event; without the registry a missing quarterly distribution is literally unobservable, because there was never a promise of a specific amount on a specific date. This is `10.01.04` DT-02's pattern in a second location: the domain's characteristic failure is an absence that produces no event, and the fix is always to declare an expectation first so the absence has something to violate. |
| DT-03 | Duplicate detection is a hygiene concern | Standard import handling | ✅ **CONFIRMED as necessary, but re-scoped as a money-safety control.** A duplicated statement does not produce a visible error — it produces a **doubled royalty, calculated confidently, paid out, and then clawed back** via `10.03.04`'s overpayment path, which is the nastiest flow in the domain. Meanwhile a *restatement* looks almost identical (same source, same period, different numbers) and must NOT be deduplicated. The two cases are one keystroke apart and have opposite handling. This is not hygiene; it is the boundary between correct money and a clawback. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | **Upload is the primary channel**; fetch is a per-source luxury | DT-01. No API exists for most sources, and credential-holding is a liability the platform should not seek. |
| D-02 | The **source registry exists independently of any statement** | DT-02. Only a declared expectation makes a missing distribution observable. |
| D-03 | Originals are **retained unchanged**, even when unparseable | A statement is evidence (parent D-03). `10.08` disputes read it; the platform's parse is an interpretation, not a replacement. |
| D-04 | Duplicate ≠ restatement, and the two are distinguished **before** anything is calculated | DT-03. One is a clawback, the other is a correction; they look identical on arrival. |
| D-05 | A broken fetch connection **fails loudly** | A silently stale connection reproduces exactly the failure the source registry exists to prevent. |
