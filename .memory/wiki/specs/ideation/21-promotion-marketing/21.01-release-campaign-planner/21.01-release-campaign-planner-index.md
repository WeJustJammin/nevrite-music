## Overview

The campaign grid: a release date is entered, and every dependent deadline is computed backward
from it — master delivered, artwork locked, metadata final, distributor delivery, DSP editorial
pitch, press embargo, announce, on-sale, release day. Labels run this artefact as a spreadsheet
called "the grid" and no indie tool provides it, yet backward planning is what prevents a
specific, common, unrecoverable loss: miss the DSP editorial pitch window and the cycle's
Release Radar placement is forfeit with no remedy at any price.

**Why this is a sub-domain, not a feature**: four capabilities that interact. The grid computes
deadlines; the asset readiness gate says whether the deliverables behind those deadlines exist;
the content calendar hangs marketing beats off the same spine; and the date-change cascade
re-derives all three when the release date moves — which it always does. Changing any one
changes the others.

## Decision Log

| # | Decision | Context | Source |
|---|----------|---------|--------|
| D-01 | The grid is a **derived** artefact, not a task list the user types | Every competing product ships a blank Trello board and calls it a campaign planner. The value is in knowing that the Spotify pitch is 4 weeks before release *because the platform knows what a Spotify pitch is* — deadlines are computed from channel rules, not authored. If the user has to type the deadlines, we have built a to-do app. | Agent, `/ideate-discover` Step 3 |
| D-02 | The Producer sees the grid **read-only, filtered to deadlines that bind them** | Per `meta/personas.md`, the Producer's work happens in a DAW and they will not use a marketing tool. But "final master due 2026-09-04" is *their* deadline and today it reaches them as a panicked WhatsApp message. Surfacing that one row to them is the whole of their relationship with this sub-domain. | Agent, `/ideate-discover` Step 3 |
| D-03 | Content Calendar (sweep candidate 09) **split**: the calendar half lands here; the publishing half becomes feature 21.06 | The calendar is a view of the grid — beats hang off release-relative offsets. Actually pushing a post to Instagram is a different, commodity, API-fragile capability with no dependency on the grid. Merging them would let the API-risky half hold the valuable half hostage. | Agent, `/ideate-discover` Step 3 |
