# Feature: Radio Plugging & Add Dates

> **Number**: 21.02.04
> **Parent**: [Pitching & Outreach](./21.02-pitching-outreach-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Pitching terrestrial and streaming radio — station music directors, specialist show producers,
college and community radio. Radio runs on its own clock (add dates, format panels, chart weeks)
and its own law: paying for airplay without disclosure is a federal offence in the US under the
sponsorship-identification and commercial-bribery provisions, not merely a terms-of-service
matter. This is the least certain feature in the domain and the most likely to be cut.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Targets stations and shows by format; sends service copy and a pitch against an add date; tracks adds and spins; sees the format-panel reality — that their record is or is not a fit for the formats that exist, which is usually the whole answer. |
| Producer | None | Not a radio function. Radio edits and clean versions are a deliverable that may land on the asset gate (21.01.02) as their row, but the pitching is not theirs. |
| Operator | None | No relationship to radio plugging. |
| Fan | None | Not a participant. Radio's audience is the listener, who is a Fan in the world but not a user of this feature. |

## Behavior

Low-volume, relationship-gated, format-driven, and paced by **add dates** — the day a station will
consider adding a record to rotation — which are set by the station, not by the artist. The
campaign grid must work backward from the add date, which sits at a different offset from the
release than any other channel, and for some formats sits *before* release.

**The honest assessment.** For most independent artists, terrestrial radio is not reachable and
not worth reaching; commercial format radio is a label-and-plugger function with real money behind
it. What is genuinely reachable is specialist, college and community radio, which is also where
some genres are actually broken. Building the full commercial-radio apparatus (format panels,
chart tracking, add-date campaigns) for an indie-first platform is likely mis-spent effort — but
the domain index explicitly names "radio plugger" as one of the three roles this domain serves,
which is why this is an open question (Q-04, sub-domain index) rather than a deletion.

### Happy Path

1. Musician targets stations/shows by format and territory from the directory (21.03.01).
2. Grid derives the add-date deadline for the format, which is not the same offset as the press or DSP deadlines and may precede release.
3. Sends service copy (the correct edit — radio edit / clean version, which is an asset row on 21.01.02) plus a pitch.
4. Tracks the add decision and, where observable, spins.
5. Adds become evidence for the next cycle and for the EPK.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| No radio edit / clean version exists | The pitch cannot be serviced; many formats will not consider an explicit track | Asset gate (21.01.02) blocks with the specific missing deliverable, not a generic "not ready" |
| Add date precedes release, and the artist planned backward from release | The deadline is already past before they started | Grid must derive the add date independently of the release offset. This is exactly the class of unrecoverable miss the domain exists to prevent |
| Artist offers payment for airplay | **Statutory exposure**, not a policy matter — US law requires sponsorship disclosure for consideration given for broadcast, and undisclosed payment for airplay is criminally exposed | Hard block. This is the one place in the domain where the guardrail defends against a criminal statute rather than a contract |
| Station's format has changed since the directory entry | Wasted pitch and a burned contact | Directory freshness (21.03.01); radio formats change more often than the directory will naturally learn |
| Spin data is not observable | Most spin/chart data sits behind paid monitoring services | `[PENDING — /ideate-discover Step 5 deepening]` — whether WeJammin sources this data is a cost decision that likely settles Q-04 |
| Artist's genre has no radio format | The truthful answer to the whole feature | Saying so plainly is more valuable than a functioning pitch tool aimed at nothing |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Radio's add date is **not derivable from the release date**, so it breaks the grid's core assumption that every deadline is a release-relative offset | Reasoning about how radio actually schedules: add dates are set by stations and format conventions, and for some formats precede release. The grid (21.01.01) assumes an anchor and offsets | ✅ CONFIRMED — and it has a consequence beyond this feature. The grid needs to support **externally-anchored deadlines** — dates that come from a third party's calendar and do not move when the release does. That is the same shape as an absolute-pinned beat (21.01.03 DT-01) and as a negotiated embargo lift (21.02.05). Three independent features converging on the same requirement is strong evidence the grid's model needs it. |
| DT-02 | Radio deserves a full feature because the domain index names "radio plugger" as one of the three roles served | Domain index rationale, taken at face value | ❌ REJECTED as a justification, though the feature survives as a node. The domain index's argument was that three roles *share one shape* — that is an argument for the shared pitch/CRM machinery, not for building commercial radio's format-panel and chart apparatus. For the indie-first user in `meta/personas.md` (a working musician with a portfolio of small income streams, not a star), commercial radio is unreachable and specialist/community radio needs little more than the generic press machinery already in 21.02.03. The node stays so the decision is explicit rather than accidental — but the honest MoSCoW proposal is `could`, and `wont` is defensible. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Radio add dates are **externally anchored**, not release-relative | See DT-01. Deriving them from the release date would produce confidently wrong deadlines for a format whose calendar we do not control. |
| D-02 | Payment-for-airplay is a hard block, distinct from the playlist payola guardrail | Radio payola carries statutory exposure in the US; playlist payola is a contract violation. Different severity, different treatment. |
| D-03 | The node exists so the scope decision is explicit | See DT-02. Deleting it silently would lose the reasoning; keeping it at `could` forces the owner to choose. |
