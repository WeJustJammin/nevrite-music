# Feature: Link Lifecycle & Retirement

> **Number**: 21.04.04
> **Parent**: [Smart Links, Pre-Save & Attribution](./21.04-smart-links-presave-attribution-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

A campaign link is born, changes meaning at release, stops counting when its attribution window
closes, and eventually should die. This feature owns those phases — and it is where the domain
index's boundary against Fanbase is enforced rather than merely asserted: **campaign instruments
have a lifespan; permanent infrastructure does not.**

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Sees every link they have ever made and which phase it is in; sees which are rotting (pointing at a delisted or dead destination) — the state no incumbent shows and where links quietly become lies; decides what a retired link does. Sees links that were supposed to be dead but are still receiving real traffic, which is the system admitting its retirement policy was wrong. |
| Producer | None | Not their artefact. |
| Operator | None | Event link lifecycle lives in 21.08 and has a genuinely different shape — a show link's natural death is the show. |
| Fan | Read-only | **The party who suffers a bad retirement.** A fan who clicks a two-year-old link shared by a friend is not doing anything wrong, and what they get is a product decision we owe them: a dead end, a redirect to the artist's permanent home, or the track. |

## Behavior

Phases: `draft → pre-release → live → in-window → out-of-window → rotting? → retired`.

**Retirement is not deletion.** A campaign link's URL exists in other people's posts, in a
journalist's published article, in a fan's saved message, forever. We do not control where it was
shared and we cannot recall it. So "retiring" a link is really deciding what it *becomes* — and
404 is a choice that punishes a fan for our tidiness.

**Rot detection is the feature's real contribution.** Destinations die: a release gets delisted, a
region loses availability, a DSP changes its URL scheme. The link keeps serving confidently and
nobody finds out, because the artist stopped looking at that campaign a year ago. Because
destinations derive from the release record (21.04.01 D-01), the platform can actually notice —
which is the consolidation dividend paying out again, in the most boring possible place.

### Happy Path

1. Link created against a campaign; enters pre-release.
2. Release event: mutates to live routing (CX-01); pre-saves fire.
3. Attribution window runs; clicks count toward the campaign (21.04.03).
4. Window closes; clicks still arrive but are recorded outside campaign figures.
5. Campaign ends. The link keeps working — because it is still in the world — but stops pretending to be a campaign instrument.
6. Destination dies eventually; rot is detected and the artist is told, once, rather than the link silently lying forever.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Retired link still receiving significant traffic | The retirement policy is wrong and the system should say so rather than serve a dead end to a live audience | "This retired link got 200 clicks last month." A link with an audience is not dead |
| Destination delisted (release taken down) | Link points at nothing; without derivation nobody would ever know | Rot detected via the release record; artist told; fan gets a fallback rather than a store error page |
| Fan clicks a long-dead link from an old post | They did nothing wrong | Redirect to the artist's permanent home in 20 — the fan wanted the artist, and the artist has a permanent home precisely because D-01 kept it out of this sub-domain. The boundary pays for itself here |
| Artist deletes a link | The URL exists in other people's posts and articles forever; deletion is not a thing we can actually do | Deletion must be reframed as retirement with a chosen behaviour. A hard delete breaks a journalist's published article |
| Release date moves; link is pre-release with pre-saves attached | Mutation follows the release *event*, not the stated date | Handled via CX-01 |
| Link outlives its window and keeps counting | Silent corruption of a dead campaign's numbers | Window close is a hard boundary on attribution (CX-04) |
| Campaign link becomes the artist's de-facto permanent link (they keep sharing it) | The boundary the domain index drew is being violated by the user's actual behaviour | Real signal — see Q-01. If it happens a lot, the taxonomy is ours and not theirs |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Draft | Created | Not shareable |
| Pre-release | Live, release future | Fan sees pre-save |
| Live | Released | Fan sees routing |
| In-window | Attribution window open | Clicks count toward the campaign |
| Out-of-window | Window closed | Link works; clicks recorded outside campaign figures |
| Rotting | A destination died | Surfaced to the artist; fan gets a fallback |
| Retired | Campaign over, retirement chosen | Behaviour per the artist's choice — never a bare 404 |
| Zombie | Retired but still trafficked | Flagged; the policy was wrong and the system should admit it |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | **Retirement is not deletion**, because the URL lives in other people's property — published articles, old posts, saved messages — and we cannot recall any of it | Reasoning about where a campaign link actually ends up. A premiere article from 2024 contains our link in a journalist's published work. Deleting it breaks *their* page, not ours. `meta/personas.md` notes the Musician's currency is relationships and proof they cannot re-prove; breaking a journalist's live article is a small, permanent version of that damage | ✅ CONFIRMED — so "delete" must be reframed as "choose what this becomes", and the default cannot be 404. The fan who clicks a two-year-old link wanted the artist; sending them to the artist's permanent home in 20 serves everyone, costs nothing, and is only *possible* because D-01 kept the permanent home out of this sub-domain. The boundary that looked like taxonomy pedantry turns out to be what makes the graceful answer available. |
| DT-02 | Link rot is unavoidable and is the user's problem to notice | The category's implicit position — incumbents do not surface rot, and their links quietly point at dead pages for years | ❌ REJECTED — rot is *detectable* here specifically because destinations derive from the release record (21.04.01 D-01) rather than being pasted. The platform holds the release; when it is delisted, the platform knows. Nobody else in this category can know that, because nobody else holds both objects. Declining to surface it would be discarding the one advantage the architecture hands us for free — and in the most unglamorous corner of the domain, which is exactly where competitors do not look. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Retirement is a behaviour choice, never a 404 by default | See DT-01. The URL is in other people's property; 404 punishes a fan for our tidiness and breaks a journalist's page. |
| D-02 | Rot is detected and surfaced | See DT-02. Only possible because destinations derive from the release record. |
| D-03 | Retired-but-trafficked links are flagged as policy errors | A link with an audience is not dead, and the system should notice its own mistake. |
| D-04 | Hard delete is not offered | It cannot achieve what the user thinks it achieves and it breaks third-party pages. |
