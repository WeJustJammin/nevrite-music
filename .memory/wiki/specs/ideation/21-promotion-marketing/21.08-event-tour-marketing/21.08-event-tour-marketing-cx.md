## Cross-Cut Details

### CX-01: Attribution ↔ Soft-Seat Response (the closed loop)

**Relationship**: Soft-seat detection spots a date underselling; targeted spend responds;
attribution measures whether the spend sold tickets; the result informs the next decision. This is
a genuine closed loop, and it is unique in this platform — everywhere else in domain 21 the
measurement step is unavailable (21.04.03 DT-01) because the conversion happens inside a DSP that
reports nothing back. Here we own the box office (19), so the conversion is a row in our own
database.

**Role scoping**:
- **Musician**: sees the loop across the whole run; decides where the tour's marketing money goes.
- **Operator**: sees and runs the loop for their own date; it is their revenue and their perishable Tuesday.
- **Producer**: not involved.
- **Fan**: the target of the spend — and the one being retargeted, which is a privacy fact (D-13).

**Synthesis questions answered**:
1. **Shared state conflict**: Ticket sales are owned by 19; both features read them. Neither writes. The spend record is owned by 21.05.01/23. No contention — this loop is a reader of other domains' truth.
2. **Trigger chain**: Sales signal → soft-seat detection → spend recommendation → spend → attribution → back to detection. The dangerous link is detection→spend: if it ever auto-spends, a bad signal spends real money with nobody watching. See 21.08.02 DT-02.
3. **Permission intersection**: Sharp and unresolved. The Operator sees their date; the artist sees the run. Does the Operator see the artist's spend on *their* date? Does the artist see the venue's? Both are spending on the same show and neither currently knows what the other is doing — which is the co-op problem (Q-04, sub-domain index).
4. **Notification fan-out**: A date going soft must reach whoever can act — and that is *both* parties, which is exactly what does not happen today. The artist finds out from the promoter, late.
5. **State transition conflict**: Sales data lags; attribution windows are short; a date can go from soft to sold-out in a day (a support act announcement, a review). Spending against stale softness is real money wasted on a solved problem.

### CX-02: Announce → Soft-Seat Response (the baseline)

**Relationship**: The announce establishes each market's baseline. Soft-seat detection is
meaningless without one — "underselling" is relative to an expectation, and the expectation comes
from what the announce achieved in that city relative to others.

**Role scoping**:
- **Musician**: sees the run's shape immediately after on-sale — which is when it is still fixable.
- **Operator**: sees their date against the run, which is information they have never had.
- **Producer / Fan**: not involved.

**Synthesis questions answered**:
1. **Shared state conflict**: The announce owns the baseline; detection reads it.
2. **Trigger chain**: On-sale → first-week sales → baseline → detection begins. First-week data is the best predictor available and it is also the point of maximum uncertainty, which is an uncomfortable combination.
3. **Permission intersection**: Per-date scoping for the Operator throughout.
4. **Notification fan-out**: A market that underperformed at announce should raise a flag in week one, not week six when nothing can be done.
5. **State transition conflict**: A date added after announce has no baseline and no comparable history — it cannot be assessed by the same rule as the rest.

### CX-03: Announce → Attribution (the retrofit trap)

**Relationship**: Attribution requires per-date, per-channel tagged links, and they must exist at
announce time. If the announce goes out with one untagged link, no attribution is possible for
that tour, ever — and it cannot be fixed afterwards, because the clicks already happened.

**Role scoping**:
- **Musician**: bears the cost of the omission and will not discover it until they ask a question they cannot answer.
- **Operator**: same, for their date.
- **Producer / Fan**: not involved.

**Synthesis questions answered**:
1. **Shared state conflict**: Links are created by the announce and read by attribution. One-way.
2. **Trigger chain**: Announce → links exist → clicks attributable. Missing the link creation is an **unrecoverable** data loss — the same class as the DSP pitch window (21.01.01 DT-01), and it deserves the same treatment: the system should create the tagged links rather than hope the artist remembers.
3. **Permission intersection**: None.
4. **Notification fan-out**: None.
5. **State transition conflict**: A date added post-announce needs its links created too, or it becomes the one date with no data.
