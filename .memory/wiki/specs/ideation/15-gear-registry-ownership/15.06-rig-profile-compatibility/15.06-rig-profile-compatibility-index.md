## Overview

A rig is a named, functional grouping of gear — a signal chain, a stage setup, a room's monitoring
path — and this sub-domain defines them, checks them against a target environment, and exports them
as the source data for a tech spec or a stage plot. It is what turns a registry from a list of
objects into something operationally useful: the answer to "will my setup actually work in that
room, in that country, on that stage?"

**Why this is a sub-domain, not a feature**: defining a rig, evaluating it against a target's
specs, and rendering it as a document are three distinct capabilities with different consumers —
and the oracle reads the definition while the spec sheet renders it, so they interact continuously.
