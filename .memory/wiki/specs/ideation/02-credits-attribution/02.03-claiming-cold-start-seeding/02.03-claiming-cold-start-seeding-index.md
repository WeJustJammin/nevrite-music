## Overview

How the graph gets populated with history that predates WeJammin, and how a human takes possession of the credits that are theirs. A capture-at-source graph starts empty, and an empty discography proves nothing — a musician with twenty years of work will not adopt a page that says they have done nothing. This sub-domain imports the industry's existing (reconstructed) record, then converts each imported credit into an acquisition event: "we think this is you."

**The tension this sub-domain must hold**: `problem-statement.md` identifies reconstruction as the root failure, and every source here — MusicBrainz, Discogs, DDEX, PRO data — *is* reconstruction. Seeding from them imports the exact defect the product exists to fix. That is acceptable only if imported credits are permanently and visibly distinguished from captured ones (`02.04.02`), and the import never rises to the tier that capture earns.

**Why this is a sub-domain, not a feature**: import creates candidate credits; the claim inbox routes them to humans; adjudication resolves the cases where two humans want the same one. Import volume drives inbox quality; inbox acceptance drives what adjudication sees; adjudication outcomes should feed back into import matching. Three capabilities, continuously interacting.

## Decision Log

| # | Decision | Context | Source |
|---|----------|---------|--------|
| D-01 | Imported credits can never reach the tier that captured credits reach | Import is reconstruction — the failure mode named in `problem-statement.md`. Seeding is legitimate for gravity, illegitimate as evidence. If an imported Discogs credit could look identical to a session-captured attested one, the tier system is decorative and the differentiator is gone. | Deep Think, this pass |
| D-02 | Sweep candidate "Provenance Tier Labelling" merged into `02.04.02` | It was listed under both claiming and counter-attestation. Tier is one model with several inputs (import, capture, attestation), not one per input. Duplicating it would guarantee two drifting definitions of the same thing. | Node Classification Gate, this pass |
| D-03 | The claim inbox is an acquisition surface as much as a data surface | Every unclaimed credit is a named professional with a page waiting for them. Import and roll-call shells (`02.02.01` DT-03) feed the same inbox. This is the platform's growth loop and it should be designed as one. | Deep Think, this pass |
