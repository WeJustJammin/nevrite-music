## Overview

Route product settings, deploy config, secrets, legal rule packs, and code invariants to distinct control planes.

**Internal authority:** full administration requires an explicit bounded staff capability, recent step-up for sensitive changes, server/RLS enforcement, and attributable acting context. Admin is an account role, not a fifth persona.

## Behavior

Secrets and authorization/ledger/legal-floor/state-machine invariants are rejected as ordinary settings.

### Happy Path

1. An authorized actor creates or opens a draft and sees current version, scope, owner, validation, dependencies, and effective permissions.
2. The actor changes typed values; the system previews effects and validates schema, authority, cross-references, accessibility, privacy, and publication policy.
3. Low-risk work saves as a new attributable version; high-risk work enters required review/step-up without taking effect.
4. Activation commits canonical state and a unique outbox event together; delivery/search/cache/notifications converge idempotently.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|---|---|---|
| An admin attempts to store a secret or change a protected invariant through CMS | Activation fails closed or transitions to an explicit blocked/degraded state; safe draft/history survives. | Exact blocker, affected records, owner, and recovery action. |
| Authority changes mid-operation | Server rechecks at commit and rejects partial privileged writes. | Preserved safe draft plus reauthenticate/request-access path. |
| Downstream convergence fails | Canonical version remains durable; retries are idempotent and exhausted work enters operations review. | Source version and honest pending/degraded status. |
| Dependency/validator unavailable | Drafting may continue safely; high-risk activation is blocked. | Unavailable state, retry, and last successful check time. |

### States

| State | Trigger | What User Sees |
|---|---|---|
| Draft | Create/edit | Private editable version with validation status. |
| Review | Submit or risk gate | Frozen candidate, reviewers, comments, blockers. |
| Scheduled | Approved future activation | Effective time/timezone and preflight state. |
| Active | Activation succeeds | Version and convergence status. |
| Superseded | New version activates | Read-only history with compare/restore. |
| Archived | Lifecycle action | Removed from normal delivery, retained by policy. |
| Blocked | Validation/permission/legal/dependency failure | Explicit reason and remediation. |
