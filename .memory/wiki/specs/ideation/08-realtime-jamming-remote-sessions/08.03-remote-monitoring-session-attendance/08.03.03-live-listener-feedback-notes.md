# Feature: Live Listener Feedback & Timestamped Notes

> **Number**: 08.03.03
> **Parent**: [Remote Monitoring & Session Attendance](./08.03-remote-monitoring-session-attendance-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Lets a remote listener say "that vocal is loud" at the moment it is loud, and have the note land on the
right moment rather than in a chat log nobody re-reads. It exists because live feedback currently
arrives as an interruption ("wait — go back") or as a message that has lost its referent by the time
anyone acts on it. The notes are captured here because only this domain has the stream; they live in
Projects (07), where every other note about the work already lives.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Producer | Full | Reads incoming notes anchored to positions in the session. Decides what to act on and what to ignore — with the listener's playback context (08.03.04) informing how much a given note is worth. Can respond, resolve, or push a note into the project's review timeline. |
| Musician | Full | Can leave notes as a listener (a bandmate attending a mix they are not playing on). Sees notes about their own performance — which is a sensitive surface: a note saying "the guitar is out of tune in bar 12" is about a person, and how and when they see it matters. |
| Operator | None | Not visible. Creative feedback on a session is not the room-provider's business. If an Operator is giving mix notes, they are acting as Producer or Musician — per `meta/personas.md`, personas are lenses on behaviour, not account types. |
| Fan | None | Not visible. No fan path into a monitor stream (parent D-04). |

## Behavior

The hard problem is time, and it is not obvious.

The listener hears the stream **late** — in a monitoring context that is seconds, not milliseconds
(08.03.01 is deliberately latency-tolerant). So a note stamped at the listener's "now" refers to a
moment already past for the room. Naively stamping at receipt time puts every note late by the stream
delay, which is enough to attach a comment about the vocal to the guitar part that followed it.

**The note must be stamped at the listener's perceived position, compensated for their stream delay** —
not at the room's clock when the note arrived. This is invisible if you get it right and quietly
poisons every note if you get it wrong, because the notes will be *nearly* right, which is worse than
obviously wrong.

The second design rule: **a note must never interrupt a performer mid-take.** Anything that pops up in
front of someone who is playing is a defect wearing a feature's clothes.

### Happy Path

1. Listener hears something at their position in the stream.
2. Listener leaves a note — a marker, a short text, or a category ("too loud", "tuning", "keep this").
3. System stamps it at the listener's perceived position, delay-compensated back to the room's timeline.
4. Note appears for the Producer, anchored to that moment, non-interrupting.
5. At take end, notes are collected against the take and handed to Projects (07) for their permanent home.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Stream delay unknown or unstable | Note is stamped with an uncertainty range rather than a false-precision point. A note that claims a precision it does not have is worse than one that admits a window. | Note anchored to a range: "somewhere around 1:22–1:25". |
| Note left about a moment already discarded (bad take) | Note dies with its take. Orphan notes referring to audio nobody kept are noise. | Note is dropped with the take; listener is not notified — telling them their note died is worse than the note dying. |
| Handoff to Projects (07) fails | Note survives locally and retries. Must not vanish. See parent CX-02. | Note stays visible with a sync indicator. |
| Note about a specific performer's playing | Sensitive. A remote critique of a person's performance, visible to them, in real time, while they play. | `[PENDING — /ideate-discover Step 5 deepening]` — this needs a real answer, not a default. |
| High note volume from an enthusiastic client | The Producer is running a session, not a ticket queue. Some collapsing or batching is needed. | `[PENDING — Step 5]` |
| Listener can hear but should not be able to comment | Roster grants listening; commenting may be a separate grant. See parent CX-02. | `[PENDING — Step 5]` |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Empty | No notes | Quiet. No empty-state furniture during a live session — the surface should be invisible until used. |
| Composing | Listener writing | Marker placed immediately at their current position; text attaches after, so the anchor is not lost while typing. |
| Anchored | Note stamped | Note on the session timeline at its compensated position. |
| Uncertain | Delay unknown | Note anchored to a range, visibly. |
| Syncing | Handoff to 07 in flight | Sync indicator. |
| Orphaned | Take discarded | Note removed with the take. |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | The note must be stamped at the **listener's perceived position, delay-compensated**, not at receipt time. Nobody raised this, and it is the feature's central correctness problem. | Domain reasoning: the monitor stream is deliberately latency-tolerant (08.03.01), so the listener is seconds behind. Receipt-time stamping puts every note late by exactly that much — enough to misattribute a comment to the next part. | ✅ CONFIRMED — and the danger is that the bug is *subtle*: notes land nearly right, so nobody notices the systematic offset, and the Producer slowly learns not to trust the anchors. A feature that quietly trains users to distrust it is worse than one that fails loudly. |
| DT-02 | Notes must be **non-interrupting to performers** — a live critique appearing in front of someone who is playing is destructive to the take and to the person. | Reasoning: the room's job during a take is protecting the performance. Every studio convention (talkback discipline, the control-room glass) exists to buffer performers from the room's chatter. A notification system that ignores this has imported a software convention into a room that spent a century learning otherwise. | ✅ CONFIRMED — non-interruption is a hard rule. The related question of whether performers see performance critiques *at all*, and when, is genuinely open (Q-02). |
| DT-03 | This belongs in Projects (07), which already owns review and annotation, and should not be a node here. | Adversarial: the invocation test — 07 has a review timeline; why duplicate it? | ❌ REJECTED — **partially, and the split is the interesting part.** 07 owns asynchronous review of a *rendered artifact*; the note has a stable timeline because the file is not moving. Here the referent is a live stream with per-listener delay and takes that may be discarded seconds later. The *capture* problem is genuinely domain 08's — only 08 knows the listener's delay. The *note* is genuinely 07's. Hence parent D-03: capture here, own there. Absorbing this into 07 would force 07 to model stream delay, which it has no reason to know about. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Notes are stamped at the listener's delay-compensated position | Receipt-time stamping is systematically wrong and subtly so. See DT-01. |
| D-02 | Notes never interrupt a performer mid-take | The room's job during a take is protecting the performance. See DT-02. |
| D-03 | Captured here, owned by Projects (07) | Only 08 knows the stream delay; only 07 should own a note's life. See parent D-03 and DT-03. |
| D-04 | When delay is unknown, anchor to a range rather than a false-precision point | A note claiming precision it lacks trains users to distrust all anchors. |
| D-05 | Notes die with their take, silently | Orphan notes about discarded audio are noise, and notifying someone their note died is worse than the note dying. |
