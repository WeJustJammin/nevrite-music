# Feature: Take Alignment & Clock Drift Correction

> **Number**: 08.05.02
> **Parent**: [Session Capture & Recall](./08.05-session-capture-recall-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Makes four independently-recorded tracks into one multitrack. Local-first capture (08.05.01) produces
pristine individual takes and a collective mess: each endpoint started at a different instant and runs on
its own crystal, so the tracks are misaligned at the start and drift apart as the session runs. This
feature establishes the canonical timeline, places every track on it, and corrects the drift — and
without it, local-first capture yields a pile of files rather than a session.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Producer | Full | Receives the aligned multitrack and owns the result. Sees alignment confidence per track, can nudge a track manually when the automatic result is wrong, and is the persona who discovers months later if it was never right. This is their deliverable. |
| Musician | Read-only | Sees whether their track aligned and with what confidence. Cannot re-align other people's tracks. Mostly does not want to think about this at all, which is the correct outcome — a working alignment is invisible. |
| Operator | None | Not visible. Alignment is post-session processing on someone else's creative material; the room provider has no role in it. |
| Fan | None | Not visible. No fan path into this domain. |

## Behavior

Two distinct problems that a naive implementation conflates:

**1. Offset** — the tracks have different zeros. Everyone hit record at a different moment. This is a
constant per track and is the easy half.

**2. Drift** — the tracks run at *different rates*. Two consumer interfaces nominally at 48 kHz are not
actually at the same 48 kHz; each free-runs on its own crystal. Over a few minutes this accumulates into
audible misalignment, and it is not fixable by sliding the track — the track has to be resampled to a
common rate.

**Correcting only the offset is the trap.** It produces a multitrack that is perfectly aligned at the
downbeat and progressively wrong thereafter — which sounds fine on a check of the first bar and falls
apart in the chorus. The failure is delayed, which is what makes it dangerous.

**Alignment is non-destructive** (parent CX-01): the output is an offset and drift model stored beside
the audio, never baked in. Alignment decisions get revised, and baking makes revision impossible.

**A failed alignment must never lose audio.** Unaligned tracks are recoverable by hand; lost tracks are
not.

`[PENDING — /ideate-discover Step 5 deepening]`: the alignment reference itself — whether it is a
recorded click (08.01.03 Q-03), an inaudible timecode/tone, correlation against the room's reference mix,
or wall-clock timestamps with a drift model. This is the feature's central unknown and each option has
different failure modes.

### Happy Path

1. All local tracks upload (08.05.01).
2. System establishes the canonical timeline from the session's reference.
3. Each track is placed against it — offset resolved, then drift measured across the take's length.
4. System publishes the aligned set with per-track confidence.
5. Producer spot-checks; nudges anything the automatic pass got wrong.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| A track has no usable reference | Cannot be aligned automatically. Must be presented as unaligned with a manual tool — never silently placed at zero, which looks aligned and is not. | "We couldn't align {track} — place it manually." |
| Drift is non-linear (thermal, power state changes) | A single linear rate correction is wrong. Real, and worse on laptops that throttle. | `[PENDING — Step 5]` |
| A participant paused/restarted their recorder mid-session | The track is now several fragments with different offsets. Common — someone's browser tab suspends. | `[PENDING — Step 5]` |
| Alignment succeeds but is wrong | The dangerous case: it looks done. Confidence must be exposed so a low-confidence alignment is checked rather than trusted. | Per-track confidence, prominently. |
| Not all tracks uploaded | Align what exists; show the gap explicitly. Waiting silently for a track that will never arrive is not a strategy. | Partial set with named missing tracks. |
| Offset corrected, drift ignored | The trap. Aligned at the top, wrong by the chorus. | Must not happen — drift correction is mandatory, not an option. |
| Session had no click or reference at all | A free jam with no timing reference. | `[PENDING — Step 5]` — correlation against the reference mix is the likely answer. |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Waiting | Uploads incomplete | Who is missing, by name. |
| Aligning | Processing | Progress. |
| Aligned (high confidence) | Clean reference, all tracks | Aligned multitrack + confidence. |
| Aligned (low confidence) | Weak reference | Aligned + explicit "check this" flag. Never silent. |
| Partial | Some tracks unalignable | Aligned set + unaligned tracks with a manual tool. |
| Failed | No usable reference | Tracks preserved, unaligned, downloadable. Audio is never lost to an alignment failure. |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | A domain expert expects **drift, not just offset** — independent interfaces on independent crystals do not run at the same rate, so alignment is a resampling problem rather than a sliding one. Nobody in the sweep raised alignment at all, let alone this. | Domain reasoning: two consumer interfaces nominally at 48 kHz free-run on separate crystals and diverge measurably over minutes. This is why studios distribute word clock — a solved problem in physical rooms that reappears the instant recorders are distributed. | ✅ CONFIRMED — and it is the feature's core difficulty. The naive implementation corrects offset only and produces a multitrack that is right at the downbeat and wrong by the chorus. |
| DT-02 | The offset-only failure is **dangerous precisely because it is delayed** — it passes every quick check and fails in the part of the song people care about. | Reasoning: failure analysis. Someone verifies alignment by playing the first few bars, which is exactly where offset-only correction looks perfect. The error grows with time, so it is largest where the work is most finished. | ✅ CONFIRMED — drives D-02: drift correction is mandatory, never an option or a "phase 2". A feature that passes its own smoke test and fails in production is the worst shape a feature can have. |
| DT-03 | Alignment is a post-production concern and belongs in Projects (07), which owns the multitrack. | Adversarial: 07 owns project assets; why does 08 process them? | ❌ REJECTED — alignment depends on *session-time* information that only exists here: which endpoint recorded which track, what the session's timing reference was, each endpoint's measured delay, when each recorder started. That context is gone by the time 07 sees files. 07 receives an aligned multitrack; it cannot manufacture one, because the facts required were only observable while the session was running. This is the same "present at the moment of truth" logic the thesis rests on, applied to time rather than credit. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Drift correction is mandatory, never optional | Offset-only alignment fails late and quietly. See DT-01, DT-02. |
| D-02 | Alignment is non-destructive — an offset/drift model beside the audio, never baked in | Alignment decisions get revised; baking makes revision impossible. |
| D-03 | A failed alignment preserves the audio, unaligned and downloadable | Unaligned tracks are recoverable by hand; lost tracks are not. |
| D-04 | Per-track confidence is always exposed | The dangerous failure is an alignment that looks finished and is wrong. |
| D-05 | Unalignable tracks are shown as unaligned, never silently placed at zero | Zero looks like a decision. It is not. |
