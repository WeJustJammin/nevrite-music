# Feature: Seller Fraud, Buyer Fraud & Return Abuse Controls

> **Number**: 24.03.03
> **Parent**: [Fraud & Risk Operations](./24.03-fraud-risk-operations-index.md)
> **Status**: [PARTIAL]
> **Last updated**: 2026-07-18

## Overview

Controls against the two-sided abuse patterns of a physical-goods marketplace — non-delivery, empty-box,
item-not-as-described (INAD) abuse, and return fraud. Used music gear makes all of them harder than
generic retail for one structural reason: **there is no SKU-level fungibility.** Every unit is one-of-one
(D-14: "qty=1 non-fungible stock with condition-as-price"), so proving *which item came back* is a real
problem, and "not as described" is a judgment about condition rather than a comparison to a catalog entry.

## Behavior

Signals are gathered across the order lifecycle: listing accuracy history, delivery proof, return rate,
INAD rate by seller and by buyer, serial-number continuity, and condition-evidence completeness at
listing time. Outputs are proposals — hold the payout, require signed delivery, require a serial check at
return, escalate to a claim (24.04.01).

**Serial-number continuity is the control this domain has and generic marketplaces do not.** If a listing
records the serial at publish and the return records it again, the swap scam becomes provable. That makes
[domain 15 (Gear Registry)](../../15-gear-registry-ownership/) a fraud control rather than a
nice-to-have, and it is the same move the product makes everywhere else: capture the fact at the moment
it is true, so it cannot be contested later (D-18).

Statutory returns rights (EU/UK distance selling, and only for Traders) constrain which refusals are
lawful at all — a control that refuses a legally-mandated return is not a fraud control, it is a
violation. That rule set is the Tax/Consumer-protection cross-cut's, invoked here.

**Identity control when there is no serial (Q-02, resolved at this level).** Most pedals, most
vintage instruments, and all hand-built gear have no usable serial. The control degrades but does not
vanish: the listing captures an **identity fingerprint** instead — 3+ close photos of distinguishing
marks (wear patterns, finish checking, hardware, solder joints, headstock/back-of-neck) plus declared
faults, all timestamped and stored as the same listing-time snapshot a serial would anchor. On return,
the same photo set is required and compared against the listing snapshot. This is weaker than a serial
match — it is human-adjudicated, not binary — but it is the same move: **capture the identifying fact
while it is true, so the swap becomes a comparison of two dated records rather than two memories.** The
strength of the fingerprint (how many marks, how distinctive) is a per-item quality signal that feeds
the payout-hold decision (24.02.01): a generic-looking pedal with no distinguishing photo evidence is a
higher-risk order than one with a chipped, uniquely-worn body on record.

### Happy Path

1. Seller lists with structured condition evidence: photos, serial, declared faults
2. Buyer purchases; escrow holds; delivery proof is captured
3. Buyer opens a return; the return records the serial and condition on receipt
4. Serial and condition match → refund; no case
5. Mismatch → claim (24.04.01) with both snapshots already in evidence (24.09)

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| **Swap scam** — buyer returns the amp with cheap tubes substituted for the NOS Mullards | Serial matches, condition does not. Caught only if the tubes were photographed at listing | Claim with both condition snapshots side by side |
| **Swap scam, harder** — buyer returns a *different* SM58 | Serial mismatch → provable, if the serial was captured. This is the strongest argument for domain 15 | Claim resolved on the serial |
| Seller never captured a serial | The control does not exist for that order. **Retroactive capture is worthless** — the seller's word against the buyer's | Nothing at listing time — per Q-01 the serial is prompted, never required (13.03.01 D-13). The absence is not blocked, it is priced: on used grades above the value threshold the missing unit media leaves no baseline, and a "not as described" dispute resolves against the seller (13.02.04 D-04) |
| Empty box / non-delivery | Delivery proof + weight from the carrier; the Shipping cross-cut's data | Claim |
| Honest INAD — the seller genuinely thought "excellent" | **Not fraud.** Condition is subjective and condition *is* the price in used gear (D-14). Most INAD disputes are honest disagreements | Mediation (24.04.02), never a fraud sanction |
| Buyer's return rate is high but every return was justified | Return rate alone is not a signal; a buyer who keeps receiving misdescribed gear is a victim, not an abuser | Nothing |
| Trader seller refuses a lawful EU/UK distance-selling return | The control must not permit it | Return proceeds regardless of the seller's policy |
| Serial-less gear (pedal, hand-built amp) returned, buyer claims swap | Falls back to the identity fingerprint (Q-02 resolution): the listing photo set vs the return photo set, human-adjudicated. Provable if the marks are distinctive; ambiguous if the item was photographed generically | Claim with both photo sets side by side; strength of match noted |
| Buyer refuses to photograph the item on return | Return cannot be verified. The return proceeds only where statutorily mandated (Trader + distance selling); otherwise the payout hold stays and the refund is withheld pending evidence | Prompt: "Photos of the item are required to complete this return" |
| Vintage instrument "not as described" — a refin sold as original | Not a return problem; an authenticity problem → 24.05.03 | Routed, not refunded |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Return abuse controls transfer from generic retail | Every marketplace has them | ❌ REJECTED — generic controls assume **fungibility**: the returned item is a SKU, and any unit of that SKU is the same. Used gear has no fungibility (D-14: qty=1, condition-as-price), so the returned item's *identity* must be proved, not assumed. Generic returns flows have nowhere to put a serial number and no concept of condition-as-value. The consequence is structural: **the platform's fraud controls for gear depend on the Gear Registry (15) existing**, which promotes that domain from a feature to a control. |
| DT-02 | The evidence needed to resolve a return dispute can be gathered when the dispute is filed | The way it is always done | ❌ REJECTED — this is the product's own thesis restated in a commerce context, and it is exactly as true. The serial, the condition photos, the declared faults and the delivery proof are only capturable **at listing and at dispatch**. By the time a dispute exists, the amp is in the buyer's possession and the only record is two people's memories — which is the reconstruction failure `problem-statement.md` says the whole product exists to prevent. A dispute system without listing-time capture is a system that asks people to remember. |
| DT-03 | A high return rate identifies an abusive buyer | Standard heuristic | ❌ REJECTED as a standalone signal — a buyer with five returns may be five sellers' victim, and in used gear (where condition is subjective and sellers are optimists) that is the *likely* explanation. The signal is only meaningful conditioned on **who won each dispute**, which means it depends on adjudication outcomes (24.03 CX-04) — labels the platform does not have on day one. Shipping the naive version punishes the honest buyer of misdescribed gear, which is the buyer the marketplace most needs to keep. |
| DT-04 | Gear without a serial (pedals, vintage, hand-built) is simply outside the swap-fraud control — the serial is the only anchor | The control was framed around serial continuity (DT-01) | ✅ CONFIRMED that the *binary* serial match is unavailable — but REJECTED the conclusion that the control vanishes. The same listing-time capture principle (DT-02) still applies to physical identity: distinctive wear, finish checking, and hardware are per-item fingerprints that a listing snapshot can freeze and a return can re-photograph. The result is a **weaker, human-adjudicated** match rather than a binary one, and its strength varies with how distinctive the item is — which is itself a usable risk signal feeding the payout hold (24.02.01). This resolves Q-02 at Level-1 depth; the exact fingerprint schema (how many photos, which angles are mandatory, image-similarity assist vs pure human review) is `[PENDING — /write-be-spec, domain 13 listing schema]`. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Serial + structured condition evidence at listing time is the control | DT-01/DT-02. It cannot be added at dispute time, so it must be a listing-schema requirement in domain 13 — a decision domain 24 depends on but does not own. |
| D-02 | Honest INAD is not fraud and must not route here | Condition is subjective in used gear; most INAD is disagreement, not abuse. Mediation (24.04.02) is the right lane. |
| D-03 | Return rate is only a signal conditioned on dispute outcomes | DT-03. |
| D-04 | Serial-less gear falls back to a photographic identity fingerprint (3+ marks) captured at listing, human-adjudicated on return | DT-04, resolves Q-02. Weaker than a serial match but the same capture-at-source principle; fingerprint distinctiveness is itself a risk signal. Schema owned by domain 13. |
