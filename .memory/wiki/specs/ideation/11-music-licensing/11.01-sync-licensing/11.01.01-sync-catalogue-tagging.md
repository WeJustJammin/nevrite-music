# Feature: Sync Catalogue Tagging & Metadata

> **Number**: 11.01.01
> **Parent**: [11.01 Sync Licensing](./11.01-sync-licensing-index.md)
> **Status**: [PARTIAL]
> **Last updated**: 2026-07-17

## Overview

Describes a recording in the vocabulary supervisors actually search in — mood, tempo, key, energy arc,
instrumentation, vocal presence, lyric theme, era, and sync-specific flags like "has a clean instrumental"
or "builds at 0:45". Without this layer a work is invisible to sync buyers no matter how well its splits
are documented, because nobody searches for a song they have never heard by its title.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Tags their own works; reviews and corrects machine-suggested tags; adds the lyric theme and era context a classifier cannot infer; marks whether an instrumental/clean version exists. Sees which tags are earning search impressions. |
| Producer | Full | Tags works they hold a master share in — usually the party who actually has the stems, so the only one who can truthfully flag "instrumental available" and mark structural timestamps. |
| Operator | None | No sync catalogue surface. A venue/studio operator does not own recordings in this capacity; if they do, they are wearing the Producer lens. |
| Fan | None | Not visible. The sync catalogue is a professional buyer surface; exposing it to fans would leak unreleased material. |

## Behavior

Tagging is offered as a byproduct of work already done elsewhere — a track that went through a session in
domain 07 arrives with contributors, stems and structure already known. The platform proposes tags; the
human corrects. **The lazy path must be the correct path** (personas.md, Producer anti-persona): if tagging
demands a separate trip to a web form, it will not happen, and the catalogue will be full of clearable works
nobody can find.

### Happy Path

1. A work reaches a taggable state (mixed/mastered, or explicitly published to the sync catalogue)
2. System proposes a tag set from audio analysis plus what the session already recorded (instrumentation from track names, tempo from the session, contributors from the split ritual)
3. Musician or Producer reviews the proposal — accepts, removes, adds
4. Human-only fields are prompted specifically: lyric theme, whether the lyric is licensable in a political/brand context, whether an instrumental exists
5. Work enters the sync index; owner sees a completeness score and what is still missing

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Audio analysis confidence is low (sparse, ambient, or genre-ambiguous work) | Proposals are withheld rather than guessed; manual tagging required | "We couldn't read this one confidently — tell us about it" with empty fields, not wrong pre-fills |
| A user with no ownership share tries to tag the work (e.g. a session sideman, or a Musician on a project they only played on) | Rejected — tagging authority follows an ownership share in the work (recording or composition), not participation in the session. Read-only for non-owners | Tag panel is view-only; "You played on this — only owners can edit its sync tags" |
| Only one co-owner tags; others disagree with the mood/theme | Tags are work-level, not per-owner — last write wins with a full edit audit trail. Whether a co-owner can formally contest (vs simply re-editing) is `[PENDING — /write-be-spec: co-owner tag-contest model]`; the audit trail is the Level-1 guarantee | Edit history showing who changed what and when; every field attributes its last editor |
| Work is re-tagged while it is already pitched or on hold (11.01.03 / 11.01.04) | Tags stay live and editable, but any supervisor who pitched or holds against the old metadata is flagged; asset-backed and structural flags (instrumental-available, "builds at 0:45") are frozen while a licence is executing so the buyer's edit assumptions cannot shift underneath them | "This work is in an active pitch — supervisors will see that its tags changed since they shortlisted it" |
| Work has no session provenance (a finished file uploaded straight to catalogue, not born from a domain 07 session) | No consolidation dividend — proposals rely on audio analysis alone; every session-derived facet (contributors, structure, tempo confidence) starts empty and manual | Completeness score opens near zero with the missing facets named; no false "we know this" pre-fills |
| Work is tagged but not clearable (11.02 says no one-stop) | Work is indexed but flagged; tagging does not imply availability | "Tagged — but not currently clearable. Fix: [clearance path]" |
| Owner tags aspirationally to win impressions (tags a mid-tempo song as "trailer") | Detected as tag/audio divergence; repeated divergence damages the account's catalogue standing (penalty severity is Q-03, deferred to `/ideate-validate`) | Warning on save; no silent rejection |
| Instrumental flagged as available but no instrumental asset exists | Flag is asset-backed, not self-asserted — cannot be set without the file | Flag disabled with "upload an instrumental to enable" |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Audio analysis running | Progress with an honest estimate; tagging is not blocked on it |
| Empty | Work has no tags | Empty state with "Suggest tags" CTA and the completeness score at zero |
| Populated | Tags present | Tag set grouped by facet, with source badges (suggested / confirmed / human-only) |
| Error | Analysis failed | Manual tagging fully available; failure is not a blocker |
| Partial | Machine tags present, human-only fields empty | Completeness meter with the specific missing facets named — never a generic "incomplete" |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Tags should be derived purely from audio analysis — supervisors search by sound, and asking humans to tag guarantees an empty catalogue | Industry precedent: every production-music library runs a classifier | ❌ REJECTED — the facets that actually win placements are the ones a classifier cannot hear: lyric theme, whether the lyric is safe in a brand context, and whether an instrumental exists. Analysis proposes; humans supply the unhearable. |
| DT-02 | Sync tagging is a *byproduct* opportunity, not a chore, because the platform is already in the room (D-18) | Thesis: consolidation puts the platform where the work happens | ✅ CONFIRMED — a work arriving from a domain 07 session already knows its tempo, instrumentation and contributors. This is the consolidation dividend applied to sync, and it is a genuine advantage over Musicbed/Artlist, who receive finished files with no session context. |
| DT-03 | Tag inflation will be the dominant abuse — owners will tag everything "trailer" and "epic" to chase the high-fee facets | Reasoning from the Musician anti-persona (inflates credits to manufacture reputation); the same incentive applies to tags | ✅ CONFIRMED — tag/audio divergence is machine-detectable, unlike credit inflation. This is a rare case where the abuse is cheaper to police than the underlying honest behaviour is to elicit. Needs a policy, not just a check. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Machine proposes, human disposes — tags are never auto-committed | An auto-tagged catalogue with no human confirmation is a reconstruction, which is the exact failure the thesis rejects (problem-statement.md root cause) |
| D-02 | Asset-backed flags (instrumental available) cannot be self-asserted | A supervisor discovering at licence time that the promised instrumental does not exist is a platform-credibility failure, not a user error |
