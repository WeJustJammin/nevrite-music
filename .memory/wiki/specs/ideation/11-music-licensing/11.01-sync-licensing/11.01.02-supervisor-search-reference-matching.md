# Feature: Supervisor Search & Reference-Track Matching

> **Number**: 11.01.02
> **Parent**: [11.01 Sync Licensing](./11.01-sync-licensing-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The buyer's front door: search the catalogue by feeling, not by name — mood, tempo, energy arc, lyric
theme, and above all "sounds like *this*", because supervisors brief in reference tracks they cannot
afford or cannot clear. Results are ranked with clearability as a first-class dimension, which is this
platform's structural advantage: a work that is one-stop today is worth more to a buyer with a Friday
deadline than a better work that needs three months of archaeology.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only | Cannot search the catalogue as a buyer. Sees *their own* works' standing: impressions, which facets surfaced them, which briefs they nearly matched. Never sees competing works' rankings — that would turn the catalogue into a leaderboard and drive tag inflation (11.01.01 DT-03). |
| Producer | Read-only | Same as Musician, scoped to works they hold a master share in. |
| Operator | None | No sync buying surface. |
| Fan | None | Not visible. The catalogue includes unreleased and shelved material; fan exposure would leak it. |

> **This feature's actual primary user has no persona.** The music supervisor / brand / agency buyer maps
> to none of the four ratified personas (D-19). Every row above is a spectator row. See parent domain Q-01
> — this is the sharpest instance of that gap in the whole domain, and the Role Lens is dishonest without
> saying so.

## Behavior

Two entry modes that converge on one matcher: **facet search** (mood/tempo/theme filters, the tag vocabulary
from 11.01.01) and **reference matching** (upload or link a track; find works that sit near it). Reference
matching is the mode supervisors actually use, because the brief they received was "like the Bon Iver thing
but we can't clear it."

Every result carries its clearance state from 11.02 inline — not as a detail-page fact. A result set that
does not say what is clearable is the incumbent experience.

### Happy Path

1. Buyer enters a reference track (upload, link, or a catalogue work) and optionally constrains facets — tempo range, no vocals, budget ceiling
2. System returns ranked works, each annotated with clearance state (one-stop / needs consent / encumbered), an indicative price band from 11.03, and any active hold from 11.01.04
3. Buyer auditions in-line, shortlists
4. Buyer filters to "one-stop only" — the result set collapses to what can be licensed this week
5. Buyer proceeds to hold (11.01.04) or quote (11.03.02)

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Reference track is itself in the catalogue | Excluded from its own results; near-duplicates surfaced instead | "Excluded the reference itself" — with an option to license it if it is clearable |
| Reference track is a major-label recording the buyer cannot clear | Matched against anyway — the reference is a query, not a work; nothing is stored beyond the embedding `[PENDING — /ideate-discover Step 5 deepening]` on retention | Normal results; no claim about the reference's own availability |
| Query matches nothing above the similarity floor | Empty result set, not a padded one | "Nothing close enough" + the nearest facet-relaxation the system would suggest — never silently widened results |
| Best matches are all encumbered or non-one-stop | Shown, ranked below clearable works, with the specific blocker named | "Best match — but needs 2 consents (est. 3 weeks)" alongside a clearable second-best |
| Work is under an exclusive hold to another buyer | Suppressed or flagged per hold type; see `11.01-sync-licensing-cx.md#CX-03` | "On hold until [date]" or absent entirely, depending on hold exclusivity |
| Buyer scrapes the catalogue via repeated queries | Rate-limited; catalogue enumeration is an attack, not a use case | Throttle notice — routed to `/create-prd-security` as an NFR |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Query submitted; reference embedding computed | Skeleton results; reference analysis progress shown separately since it dominates latency |
| Empty | No matches above floor | Honest empty state with a named relaxation suggestion |
| Populated | Matches returned | Ranked list with clearance, price band, and hold state on every row |
| Error | Matcher unavailable | Facet search degrades gracefully without reference matching — the cheap half must survive the expensive half |
| Partial | Reference analysis done, clearance recompute lagging | Results shown with clearance marked "checking" — never shown as clearable on stale data |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Clearability should be a *filter*, not a *ranking signal* — buyers want the best song and will do the work | Naive reading of how supervisors choose | ❌ REJECTED — a supervisor's binding constraint is the delivery date, not the song. Clearability *is* quality under deadline. Making it a ranking dimension is precisely how the provenance wedge (D-18) converts into buyer value; relegating it to a filter throws that away. This is the single most important design call in the sub-domain. |
| DT-02 | Reference-track matching is the real entry point; facet search is the fallback | Supervisors brief in reference tracks because that is how directors and clients communicate ("like this, but cheaper") | ✅ CONFIRMED — and it inverts cleanly into briefs (11.01.03): a brief is a standing reference query. Same matcher, opposite direction. See `#CX-02`. |
| DT-03 | Exposing "works that nearly matched" to owners (the Role Lens above) is harmless transparency | Symmetry with other marketplace analytics | ❌ REJECTED — it leaks buyer intent. "Your track nearly matched a brief for an alcohol brand" tells an owner what campaigns are in-market and who is looking. Aggregate-only, delayed, and never per-brief. Routed to Q-03. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Clearance state renders on every result row, inline | The differentiator is worthless if it lives on a detail page. Per DT-01, clearability is a ranking dimension and must be visible where ranking is consumed. |
| D-02 | Owners get aggregate search standing, never per-buyer or per-brief detail | Per DT-03, granular exposure leaks buyer intent into a population that includes competitors |
