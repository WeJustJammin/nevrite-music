# Feature: Deduction Categorization & Jurisdiction Rules

> **Number**: 23.02.02
> **Parent**: [Expenses & Tax Readiness](./23.02-expenses-tax-readiness-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The rule engine that decides what a musician can actually deduct, where they live. It supplies the category vocabulary that capture (23.02.01) offers, the apportionment rules for the genuinely mixed-use spend that dominates a musician's life, and the capital-versus-expense thresholds. It is the least glamorous feature in the domain and the one that decides whether the tax pack is an asset or a liability — because a wrong rule produces a wrong return that the **user** signs.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Declares their tax jurisdiction and gets a category set that matches it. Sees rule guidance at the point of categorizing — "musicians can typically claim X, here is the test" — not buried in a help centre. Their spend is the most apportionment-heavy of any persona. |
| Producer | Full | Same engine. Their distinctive need is the **contractor-payment** category (fees paid to contributors), which is both their largest deduction and, in some jurisdictions, a reporting obligation of its own — paying people creates duties, not just costs. |
| Operator | Config | Sets jurisdiction and little else. Their categorization runs through an accountant and a company return this sub-domain does not attempt (D-02). Config-only is a deliberate scope boundary, not an oversight. |
| Fan | None | Not visible — no deductions, no professional stake. |

## Behavior

A jurisdiction rule set defines: the category vocabulary, per-category apportionment rules, capital thresholds, and rate-based claims (mileage, per diem). Rules are **versioned by tax year** — a rule that changed in 2027 must not restate a 2025 categorization.

### Happy Path

1. Musician declares UK sole-trader jurisdiction.
2. Their capture surface offers a UK-shaped vocabulary: equipment, instruments, rehearsal, travel, subsistence, home-studio use, professional fees.
3. They categorize a £320 pedal as equipment; the engine flags it against the capital threshold and proposes asset treatment.
4. Guidance shows the rule that applies and the test it turns on.
5. The categorization carries a rule version, so a rule change next year does not silently rewrite this year's return.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| User has **two tax residencies** (touring musicians genuinely do) | Account-level jurisdiction is wrong as a model; rows may need per-jurisdiction treatment | `[PENDING — /ideate-discover Step 5 deepening]` — collides with 23.01.03 Q-03; the shared root is that "jurisdiction" is not a scalar |
| Jurisdiction not supported | Must fail honestly — a generic category list dressed as a rule set is worse than nothing | Explicit "not supported; export raw data instead" rather than a plausible-looking wrong answer |
| Rules change mid-year, or retroactively | Version by tax year; historic categorizations pin to the version in force | Historic figures do not move |
| User changes declared jurisdiction | Historic categories re-map; some orphan | Re-map proposed with orphans surfaced — never silently discarded |
| Guidance is read as tax **advice** | The liability line. Guidance describes the rule; it does not tell the user what to do | Framing and disclaimer — and this is a legal-review item, not a copy tweak |
| Home-studio apportionment | Jurisdiction-specific and genuinely complex (a room used for tracking that is also a bedroom) | Rule-guided input, not a free number |
| Category exists but the rule is ambiguous for musicians specifically | Real and common — the profession sits awkwardly in generic self-employment rules | Flagged for the accountant rather than guessed |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Rule set resolving | Categories load with the vocabulary; guidance can lag |
| Empty | No jurisdiction declared | Blocking prompt — capture cannot offer a meaningful vocabulary without it (`#CX-01`) |
| Populated | Rule set active | Category vocabulary + inline guidance |
| Error | Rule set unavailable | Capture still works with `uncategorized` rows; nothing is lost, categorization is deferred |
| Partial | Jurisdiction supported but a category's rules incomplete | Explicit gap — "we do not encode this rule; ask your accountant" |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | A generic category list works, and jurisdiction rules are a later refinement | The tempting sequencing — ship expenses now, add tax later | ❌ REJECTED: there is no neutral vocabulary. "Home studio apportionment", "per diem" and "capital allowance" are jurisdiction concepts with different definitions and different tests; a generic list produces categorizations that must all be redone once real rules arrive. Capture cannot ship jurisdiction-neutral (`#CX-01`). This is why candidates 02 and 03 were merged into one sub-domain (D-01). |
| DT-02 | A domain expert would expect **musician-specific rules**, not generic self-employment rules | Any accountant who works with musicians: the profession is full of genuinely odd, contested treatments — an instrument that is both a tool and an appreciating asset; a laptop that is a studio; clothing that is stage-wear (deductible in some jurisdictions only if unusable as ordinary clothing); a room that is a bedroom by night and a tracking room by day. Generic software gets these wrong or omits them, which is exactly why musicians pay specialist accountants. | ✅ CONFIRMED: the differentiation is **musician-specific rule encoding**, not a rule engine. A generic engine already exists in every accounting product; the niche knowledge is the moat, and it is knowledge work, not code. |
| DT-03 | Encoding tax rules makes WeJammin a tax adviser | Risk framing | ⏳ PARTIALLY CONFIRMED — the line is real but navigable, and it dictates the design. Describing a rule and its test ("here is what the authority says") is publishing; telling a user what to claim is advising. This is why the product stops at an accountant-ready pack (D-03) rather than filing. But the line is thinner than it looks: a category *suggestion* is arguably advice. Escalated as Q-02 for legal review; it constrains the UI, not just the copy. |
