# Feature: Chart Position Monitoring

> **Number**: 22.03.02
> **Parent**: [Playlist & Chart Tracking](./22.03-playlist-chart-tracking-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Tracking entries and positions on charts — Billboard, Official Charts, Spotify Viral/Top 50, genre
and territory charts — alongside the artist's own numbers. For the overwhelming majority of WeJammin's
users this feature will never fire, which is the honest starting point for judging what it's worth.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Sees chart entries and position history for their tracks against their stream curve; sets alerts on entry and peak. Realistically: most will only ever see this on niche, genre or territory charts, if at all. |
| Producer | Read-only | Sees chart performance for projects they're credited on. Chart entries are a credential in a producer's sales pitch (domain 05), which is the one place this feature earns its keep for them. |
| Operator | None | Not rendered. A chart position does not book a room; a local draw does (22.04). |
| Fan | None | Never rendered here. Public chart facts a fan might see on an artist profile are a domain 01/20 surface. |

## Behavior

Chart data arrives from a **licensed feed** (Q-02 in the parent index), not from a DSP connection —
this is the one feature in 22.03 whose data supply is a commercial deal rather than an integration.
The system records entry, position-per-period and exit, and renders them against the timeline.

Charts are periodic (weekly, mostly), lagged, and computed by **undisclosed methodologies** blending
streams, sales and airplay. Consequently this feature can report *what* a chart said and must never
explain *why* it said it.

### Happy Path

1. A tracked recording enters a chart; the feed reports it.
2. Entry event recorded with chart, position, period.
3. Alert fires: "Entered Official Charts Dance Top 40 at #31".
4. Position history accumulates weekly against the stream curve.
5. Exit recorded when the track leaves.

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Never charts (the overwhelming majority) | Feature stays empty for the whole user lifetime | Empty state that does not imply failure — "nothing here" must not read as "you're not good enough". A cruel empty state on a feature 99% of users never trigger is a real product harm |
| Charts on an obscure territory/genre chart | Recorded like any other | Framed as a genuine win, not as a consolation |
| Chart methodology changes | History becomes non-comparable across the boundary | Break annotated on the series; comparing across it is suppressed rather than silently allowed |
| Licensed feed lapses | Data stops; history retained | Terminal state per 22.01.03 |
| Track charts under an ISRC we didn't match | Invisible to us | Nothing — a 22.02.02 coverage gap surfacing here |
| Chart lag (reported days after the period) | Entry appears retroactively on the timeline | Dated to the chart period, not to ingestion — otherwise the annotation lands on the wrong day and implies a false cause |
| Two charts disagree | Both recorded; no reconciliation attempted | Shown side by side. They measure different things by different methods; "reconciling" them would invent a number neither publisher stands behind |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Feed sync | Skeleton |
| Empty | Never charted | Neutral, non-judgmental empty state |
| Populated | ≥1 entry | Position history + timeline annotations |
| Partial | Only some charts licensed | Explicit coverage statement — which charts we can and cannot see |
| Error | Feed unavailable | Retry; history retained |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Chart monitoring is a core analytics feature because incumbents all have it | Competitive reasoning | ❌ REJECTED for WeJammin's persona set: Chartmetric and Soundcharts serve **labels and A&R**, for whom charts are the job. WeJammin's primary persona is the multi-hyphenate working musician who "makes a living from a portfolio of small income streams" (personas.md) and will essentially never chart. Building chart monitoring for them is building a trophy cabinet for someone who doesn't compete. It is also the feature with the **highest cost floor** in the domain — chart data is licensed, so it has a bill before it has a user. Proposed `could` on that basis; a licensed feed for a feature 99% of users never see is a poor first purchase. |
| DT-02 | What would a domain expert expect that nobody mentioned? **The empty state is the product** for this feature | Reasoning about the real distribution of users | ✅ CONFIRMED: for nearly every user this feature is *only ever* an empty state, so the empty state is not an edge case — it is the feature's dominant rendering. Getting it wrong (implying failure, dangling an unreachable goal, nagging) actively harms the persona. Getting it right means it costs nothing to have and quietly rewards the rare user it fires for. This inverts the usual design priority and is worth stating explicitly before anyone specs it. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Chart events are dated to the **chart period**, not to ingestion | Charts report with lag. Dating to ingestion places the annotation on the wrong day and invites a false causal read of the stream curve. |
| D-02 | Conflicting charts are shown **side by side**, never reconciled | They measure different things by undisclosed methods. A reconciled number would be ours, not theirs, and no publisher would stand behind it. |
| D-03 | The empty state is designed as a **first-class surface**, neutral in tone | DT-02. It is the dominant rendering for nearly every user of this feature. |
