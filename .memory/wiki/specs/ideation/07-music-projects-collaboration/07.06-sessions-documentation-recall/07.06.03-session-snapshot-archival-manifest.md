# Feature: Session Snapshot, Archival & Environment Manifest

> **Number**: 07.06.03
> **Parent**: [Sessions, Documentation & Recall](./07.06-sessions-documentation-recall-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The machine state at the moment a session closed: the session file, every referenced media asset, and a manifest
of the environment needed to open it again — DAW and version, plugins and their versions, sample rate, channel
count. It answers the question that surfaces five years later when a sync opportunity requires an instrumental
and nobody can open the record.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only | Sees that their session is archived and whether it is actually reopenable. That second part is what they will care about in five years, and it is a claim no cloud storage has ever made honestly. Cannot create snapshots. |
| Producer | Full | The snapshot happens on their machine's state. Reviews the manifest, resolves missing media (`07.04.05`), and is the one who discovers — hopefully now rather than in five years — that a plugin they relied on is gone. |
| Operator | None | Not their business. Even in their room, the client's session file is the client's. |
| Fan | None | Not visible. |

## Behavior

At session close, the snapshot captures the session file plus every asset it references, and records a manifest of
the environment. The manifest is what distinguishes this from a backup: a zip of a session file is a set of bytes
that may or may not open, whereas a manifest is a *statement of what it needs* — and therefore something that can
be checked, now and later.

The honest framing is that **archival is a probability, not a promise** (DT-01). A session archived today may not
open in ten years for reasons entirely outside the platform's control: the plugin developer went out of business,
the licence server was switched off, the DAW dropped the format. The platform can record what was needed and warn
when the environment drifts. It cannot guarantee a reopen, and it must not imply it can.

Snapshot integrity is checked immediately (`07.04.05`) — a snapshot with missing media is a **broken archive**,
and it must say so loudly, because an archive that silently cannot be reopened is worse than no archive: it was
trusted, and the trust was the whole product.

> **Ratified 2026-07-22 (D-06).** The manifest is knowable **only on the machine, at capture time** (DT-02), and
> no non-web client on that machine is authorised (`07.09` D-05). So for the whole v1 window there is no
> automatic snapshot and no environment manifest: what remains is a manual archive upload — the "zip upload" the
> cross-cut note names — and per D-01 it must be labelled as exactly that. `Unverifiable` is the honest v1 state
> of every archive. Saying so is obligatory under domain D-06: this feature's entire value proposition is a
> claim about future reopenability, and a manifest-free archive cannot support it. Not re-scoped (domain D-10).

### Happy Path

> **Post-gate happy path — not v1 (D-06).** Steps 1–3 assume a client on the producer's machine and a session
> parse, neither of which exists in v1 (`07.09` D-05, `07.09.02` D-09). The v1 shape is: the producer uploads an
> archive by hand, checksums run (`07.04.05` D-06), and the archive is recorded with **no manifest** — so step
> 5's five-year reopen is a promise the v1 product does not make.

1. Producer closes the session; the bridge (`07.09`) snapshots the state
2. System captures the session file, all 340 referenced media assets, and the manifest (Logic 11.2, 14 plugins with versions, 48 kHz/24-bit)
3. Integrity and reference checks run (`07.04.05`); all references resolve
4. Snapshot archived against the session, marked reopenable
5. Five years later a sync request arrives for an instrumental; the snapshot opens, the plugins are flagged (two versions have moved on), and the session actually loads

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Referenced media missing (samples from a personal library) | The most common real failure (`07.04.05` DT-01). Named specifically. | "6 files referenced by this session aren't in the snapshot" + include affordance |
| Plugin no longer exists / developer gone / licence server dead | **Detectable, unfixable.** The platform cannot preserve a third party's software or its licensing. | "This session needs FabFilter Pro-Q 3 — you no longer have it" — honest, at reopen |
| Referenced sample is licensed third-party content | Storing it may itself be a licence breach (`07.04.05` Q-03) | Cross-links to `07.08.04` source declaration |
| Snapshot size (multi-GB per session, many sessions per song) | Collides with `07.04.01` DT-03's storage tension — snapshots are the largest single artifact class in the domain | `[PENDING]` — see `07.04.01` Q-01 |
| DAW format the platform cannot parse | Snapshot still stores the bytes; the manifest is unavailable. Honest degradation — **a stored zip is still worth having**, it just cannot be checked. | "Archived, but the environment couldn't be read" |
| Session snapshotted mid-work (crash, not a clean close) | Snapshot exists but may be incoherent | Marked as an unclean snapshot |
| Reopen attempted on a different machine with a different plugin set | The manifest diff is the whole value here | "You're missing 3 of the 14 plugins this session needs" |
| Archive verified at close, degrades later | Background sweep (`07.04.05`); alarm | Prominent alert |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Capturing | Session closing | Progress; multi-GB takes real time |
| Verifying | Capture complete | "Checking the archive…" |
| Reopenable | All checks pass | Archived; manifest visible; the honest claim is "should reopen" |
| Incomplete | Missing media | Named list; broken-archive warning |
| Unverifiable | Unknown DAW format — and, for the whole v1 window, **every** archive, because no client captures a manifest (D-06) | Bytes stored; manifest unavailable |
| Degraded | Environment drifted since capture | "2 plugins in this session are no longer available to you" |
| Error | Capture failed | Retry; **never mark archived on failure** |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | The platform can promise that an archived session will **reopen** | The implicit promise of the word "archival", and what a user will assume | ❌ **REJECTED** — and this must be said plainly in the product, not buried. A session depends on third-party software the platform does not control: plugins whose developers fold, licence servers that get switched off, DAWs that drop old formats, iLok dongles that die. The platform can store bytes and record requirements; it cannot make Waves reissue a 2019 plugin. What it *can* honestly offer: (a) the assets are here and intact; (b) here is exactly what this session needed; (c) here is what has drifted since. That is genuinely valuable — and it is a *probability*, not a promise. Overclaiming would be the worst kind of lie in this domain: discovered in five years, by someone who relied on it, at the moment they cannot fix it. Consistent with `07.03.03` D-05 and `07.05.02` D-04 — **the honest-claims pattern now appears three times in this domain and should be a global principle.** |
| DT-02 | The real value is the **environment manifest**, not the file storage | Reasoning about substitutability. Dropbox stores the file. What it cannot tell you is that this session needs Logic 11.2, these 14 plugins at these versions, at 48 kHz — which is *the* information required to know whether reopening is even possible, and it is knowable **only at capture time**, on the machine, while the session is open. It cannot be reconstructed later at any price. | ✅ CONFIRMED — the manifest is the differentiated half and the only half that is genuinely unrepeatable. It also has an immediate use long before the five-year horizon: **handoff** (`07.08.01`). "The mix engineer needs these 14 plugins to open your session" is a *today* problem that costs real time, and the manifest solves it. That reframes the feature from insurance (hard to sell) to a delivery tool (easy to sell) — which matters a lot for MoSCoW, since insurance features lose every prioritisation argument. |
| DT-03 | Snapshots should be taken at every session close | The natural default, and what "session snapshot" implies | ⚠️ **PARTIALLY REJECTED** — most session closes are not worth a multi-GB snapshot. A producer who opened the session, nudged a fader and closed it has produced nothing worth archiving, and archiving it anyway multiplies the domain's largest storage class by its highest-frequency event. Snapshots should be taken at **meaningful** closes — stage transitions (`07.01.03`), first close of a day, explicit request, or when the session materially changed (which the bridge can detect). This is a rare case where the domain's "capture everything" instinct is wrong: the marginal snapshot has near-zero provenance value and non-zero cost. Note the contrast with credits, where the marginal capture is *always* worth it because it is nearly free and unrepeatable. **Capture-at-source is about cheap unrepeatable facts, not about expensive redundant bytes.** |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | The platform **does not promise reopenability** — it promises intact assets, a recorded environment, and honest drift reporting | Per DT-01. Third-party software is outside the platform's control; overclaiming here is discovered in five years by someone who relied on it. |
| D-02 | The **environment manifest is the differentiated half** — and its first use is handoff, not insurance | Per DT-02 — it reframes the feature from unsellable insurance to a delivery tool. |
| D-03 | Snapshots at **meaningful** closes only, not every close | Per DT-03 — the marginal snapshot has near-zero provenance value and real cost. |
| D-04 | A broken archive **says so loudly** | An archive that silently cannot be reopened is worse than none — it was trusted. |
| D-05 | Unknown DAW formats degrade honestly — bytes stored, manifest unavailable, never a false verified claim | Consistent with `07.04.05` D-05. |
| D-06 | **No automatic snapshot and no environment manifest in v1 — the archive is a labelled zip upload.** DT-02's manifest is knowable only on the machine at capture time, and no non-web client is authorised (`07.09` D-05) | Owner ratification DQ-08.2 / DQ-08.4, 2026-07-22. D-01 already refuses to promise reopenability; without a manifest the platform cannot even report drift, so the v1 claim narrows to "the assets are here and intact" and must be worded that way — domain D-06 makes the narrowing obligatory, since an archive trusted for five years and then found unreadable is the exact unrecoverable breach it names. DT-03's "meaningful close" selection (Q-01) has no v1 bite either: there is no automatic capture to select. Not re-scoped; `07.09` keeps `Should`, unphased (domain D-10). |

| Q-01 | Per DT-03 — what makes a close "meaningful"?
