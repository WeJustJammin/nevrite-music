# Feature: Bounce Watch-Folder & Auto-Ingest

> **Number**: 07.09.01
> **Parent**: [DAW Bridge & Capture-at-Source](./07.09-daw-bridge-capture-at-source-index.md)
> **Status**: [PARTIAL]
> **Last updated**: 2026-07-17

> **Deep Think addition** — not in the sweep's candidate list (sub-domain D-01).

## Overview

A folder the producer bounces into, which becomes a version in WeJammin without an upload, a browser, or a
thought. It is the cheapest possible answer to `meta/personas.md`'s Producer constraint: the producer's existing
habit is "bounce to a folder", and the platform's job is to be that folder. **No new behavior is required of the
person whose behavior is hardest to change** — which is the only reason this has a chance of working.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only | Sees versions appear in the timeline. Never touches the mechanism, never installs anything, never knows it exists. This total passivity is the design — the multi-hyphenate benefits from provenance capture without any effort at all. |
| Producer | Full | Sets up the watch folder once (or accepts the default), then bounces exactly as they always have. Sees ingest status. Their entire ongoing interaction is: nothing. |
| Operator | None | Not their business. |
| Fan | None | Not visible. |

## Behavior

A local agent watches a folder. When a settled audio file appears, it uploads it, matches it to a song, infers
lineage from the session that produced it (`07.09.02`, parent CX-01), and creates a version (`07.04.01`).

The whole design rests on **requiring no new habit**. A producer already bounces to a folder — it is one of the
most ingrained behaviors in the craft. The platform inserts itself into that existing action rather than asking
for a new one. Compare the alternative: "when you finish a mix, open a browser, find the song, click upload,
select the file, wait, add a description." That flow is exactly the web form `meta/personas.md` says will not be
used, and every upload it loses is a version, a credit prompt and a lineage link the platform never gets.

The honest problem is that this requires **software on the producer's machine**, which `meta/constraints.md`'s
web-only surface does not describe (sub-domain Q-01).

### Happy Path

1. Producer installs the agent once, points it at `~/Bounces` (or accepts the default)
2. Works in Logic; bounces "Ghost Town mix 7" — **exactly as they have for fifteen years**
3. Agent sees the file settle, uploads it in the background, matches it to the Song, infers the parent from the session (`07.09.02`)
4. v7 appears in the timeline with lineage, author and timestamp; the roster is notified
5. The producer did nothing, learned nothing, and changed nothing

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| File still being written (DAW mid-bounce) | Wait for the file to settle before ingesting — a half-written bounce would be a corrupt version | Nothing until settled |
| Bounce cannot be matched to a song | Filename, session and timing all fail. Lands in an unmatched bin — **never dropped** | "3 bounces need a song" |
| Producer bounces 20 times in a session | Normal. All 20 ingest; none is canonical (`07.04.02` D-02). The timeline needs filtering, not a cap | 20 versions, filterable |
| Bounce is a test/experiment, not a keeper | Ingested anyway. Cheap, and "keeper" is not knowable at bounce time. Storage tension per `07.04.01` DT-03 | All present; canonical marks what matters |
| Offline (rural studio, no connection) | Queued locally, uploaded later. **Never lose the file** | Queue indicator |
| Watch folder is a synced folder (Dropbox/iCloud) | Real conflict — two sync agents fighting over one folder is a genuine mess and a common setup | Detected and warned at setup |
| Producer works on a locked-down studio machine where they cannot install software | **Common in commercial studios**, and fatal for this feature | No bridge; falls back to manual upload |
| Multiple producers, one shared studio machine | The agent is bound to whichever WeJammin account authorised it at setup. On a machine flagged as shared, it does **not** silently attribute — bounces land in a per-machine holding bin owned by no one until a producer claims them. Silent mis-attribution (crediting one producer's bounce to another) would be a provenance error introduced *by the provenance mechanism* — the worst possible failure, so the default is "attribute to nobody" not "attribute to the last login" | "Which of you bounced this?" — claim prompt before any version is created |
| Huge stem-pack bounce over poor studio upstream | Resumable chunked upload; a failed 4 GB upload at 90% is product-abandoning | Progress with resume |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Not installed | No agent | Manual upload only — the degraded baseline |
| Watching | Agent running | Quiet indicator; ideally invisible |
| Ingesting | File detected and settled | Background progress |
| Queued | Offline | Queue count; nothing lost |
| Unmatched | Cannot resolve a song | Bin needing one tap |
| Conflicted | Synced-folder collision | Warning at setup, not at runtime |
| Error | Upload failed | Retry; file retained locally, always |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | A watch folder is the **cheapest viable bridge** — it requires no new habit and no plugin API | `meta/personas.md`: the producer will not leave the session. A watch folder does not ask them to leave anything; it attaches to a behavior they already perform reflexively. It also needs no DAW-specific integration, no VST3/AU/AAX builds, no per-DAW plugin approval — one agent works with every DAW ever made, including ones that do not exist yet. **Maximum coverage for minimum surface.** | ✅ CONFIRMED — this should be the **first** bridge built, ahead of any plugin. It delivers most of the value (versions with lineage arriving automatically) at a fraction of the cost, and it degrades gracefully: without it, uploads are manual and the platform is a worse Dropbox but still functions. |
| DT-02 | A watch folder is enough on its own | The optimistic reading of DT-01, and it would be very convenient if true | ❌ **REJECTED** — a watch folder sees **files**, not **facts**. It knows a `.wav` appeared at 23:41. It does not know who was in the room, which take made the comp, that the loop came from Splice, or what the session's plugin manifest is. Those need session parsing (`07.09.02`), and the credit prompt needs a *surface* (`07.09.03`). So the watch folder is necessary and nowhere near sufficient: **it delivers `07.04.01` (versions with lineage) and almost nothing else on the seven-feature dependency list.** It is the right first step and it must not be mistaken for the destination — shipping it alone and declaring the bridge done would leave `07.06.02` with a blank prompt, which is the one outcome that matters most and the one it does not fix. |
| DT-03 | Installing a local agent is a small ask | The assumption underneath the whole feature | ⚠️ **PARTIALLY REJECTED — and it is the feature's real risk.** Three distinct problems the sweep never had to face because it never proposed a bridge: (a) **`meta/constraints.md` declares web as the only surface** — a local agent is a second surface, with its own builds, its own updates, its own signing and notarisation, and its own support burden, for a platform explicitly being built by one person (`meta/problem-statement.md`); (b) **commercial studios routinely lock down their machines**, so the producers with the most sessions — the highest-value users — may be the least able to install it; (c) a background agent watching a folder and uploading audio is a **legitimate security concern** for a studio handling confidential client material, and the honest answer to "what else does it read?" needs to be verifiable, not asserted. None of these is fatal. All of them mean the bridge is a **strategic commitment**, not a feature — and that is exactly why sub-domain Q-01 escalates it to the surface decision rather than resolving it here. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | The watch folder is the **first bridge**, ahead of any plugin | Per DT-01 — maximum coverage for minimum surface; works with every DAW including future ones. |
| D-02 | It requires **no new habit** — the platform attaches to "bounce to a folder", an existing reflex | The only reason it has a chance with the persona whose behavior is hardest to change. |
