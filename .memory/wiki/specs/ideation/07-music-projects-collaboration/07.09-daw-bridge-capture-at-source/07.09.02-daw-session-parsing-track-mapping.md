# Feature: DAW Session File Parsing & Track-to-Contributor Mapping

> **Number**: 07.09.02
> **Parent**: [DAW Bridge & Capture-at-Source](./07.09-daw-bridge-capture-at-source-index.md)
> **Status**: [PARTIAL]
> **Last updated**: 2026-07-17

> **Deep Think addition** — not in the sweep's candidate list (sub-domain D-01).

## Overview

Reading the DAW session file to learn what is actually in it: tracks and their names, referenced media, the comp
map, plugin versions, sample rate, tempo, markers. Then turning track names into contributor guesses — "Sam Drums
OH" is probably Sam, probably drums. **This is where facts come from.** The watch folder (`07.09.01`) delivers
files; this turns them into the pre-fill that makes `07.06.02`'s prompt a confirmation instead of a form.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only | Never sees the parse. Sees its consequences: credits pre-filled, lineage correct, missing media caught. Entirely passive, entirely benefiting. |
| Producer | Full | Sees what was parsed and corrects it. Correction is cheap (tap a wrong guess); typing from scratch is not. Their track-naming habits determine how good the guesses are, which they will never think about and which decides everything. |
| Operator | None | Not their business — a session file is the client's confidential content, in their room or not. |
| Fan | None | Not visible. |

## Behavior

The agent parses the session file that produced a bounce and extracts:

| Extracted | Feeds |
|---|---|
| Track names and structure | Contributor guesses → `07.06.02` pre-fill (parent CX-02) |
| Referenced media paths | Missing-media detection (`07.04.05` DT-01) |
| Comp map / playlist selections | Take lineage (`07.04.03`, its DT-02) |
| Plugin list and versions | Environment manifest (`07.06.03` DT-02) |
| Sample rate, bit depth, tempo | Spec validation (`07.08.02`) |
| Media origin paths | Source declaration prompts (`07.08.04` DT-02) |
| Session identity and history | Version lineage (`07.04.01` DT-01) |

**Six of the domain's seven bridge-dependent features get their data from this one parse.** That concentration is
what makes this feature disproportionately important and disproportionately risky.

> **Ratified 2026-07-22 (D-09).** **There is no parse in v1** — no non-web client is authorised to run one
> (`07.09` D-05), so none of the six dependents receive any of the rows above during the v1 window. The
> concrete downstream consequence is the one that must travel: `07.06.02`'s pre-fill sources in v1 are the
> session roll (`07.06.01`) and the roster (`07.03.01`) **only**, and `07.06.02` D-11 suppresses a card with
> neither. Q-03 — whether track names carry person signal at all — is now reopen-evidence item (b) on the gate.

The track-to-contributor mapping is the hardest and most valuable part, and it rests on a habit nobody thinks
about: producers name tracks like `Sam Drums OH`, `VOX Alex dbl`, `Gtr 2 - Jim`. That naming is an accidental
attribution record that has always existed and that no tool has ever read.

### Happy Path

1. Bounce ingests (`07.09.01`); the agent locates the session that produced it
2. Parses: 24 tracks, 340 media references, a comp map, 14 plugins, 48 kHz
3. Track names yield guesses — `Sam Drums OH` → Sam (on the roster) → drums
4. At close, `07.06.02` prompts: "Sam played drums, right?" — **pre-filled from a track name the producer typed for their own convenience three hours earlier**
5. Producer taps confirm; the credit is captured with zero admin, exactly as `meta/personas.md` demands

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Track named `Audio 1`, `Audio 2`, `Track 7` | **Extremely common.** No signal; no guess. Degrades to a blank prompt for that track — the outcome the domain most wants to avoid | Unguessed tracks; prompt falls back to asking |
| Track named `DRUMS FINAL FINAL` | Instrument guessable; person not | Partial guess |
| Name matches a roster member ambiguously (two Sams) | Do not guess. An ambiguous guess confidently rendered is worse than none | Asks |
| Encrypted/proprietary session format the parser cannot read | Parse unavailable; ingest still works (parent CX-01) | Version lands with weaker metadata |
| Session format changes with a DAW update | **The permanent maintenance burden** — see DT-03 | Silent degradation unless monitored |
| Wrong guess confirmed carelessly by a tired producer | **False credit in the graph** — `07.03.01` DT-02's abuse surface arriving by accident | See DT-02 — this is why confidence must be visible |
| Session references media on a network drive | Paths resolve to nothing portable | Flagged as missing (`07.04.05`) |
| Producer renames tracks between parse and prompt | Re-parse at prompt time rather than using stale hints | Fresh guesses |
| Track named after a **part**, not a person (`Kick In`) | The majority case in electronic production, where there are no people to credit | No contributor guess; instrument only |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Parsing | Session located | Background; nothing surfaced |
| Parsed | Extraction complete | Guesses ready for `07.06.02` |
| Partial | Some fields unreadable | What was extracted, honestly bounded |
| Unparseable | Unknown/encrypted format | "Couldn't read this session type" — never a silent failure |
| Stale | Session changed since parse | Re-parse |
| Error | Parse failed | Ingest unaffected |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | **Track names are an accidental attribution record that has always existed and no tool has ever read** | Reasoning about what is already true rather than what could be built. Producers name tracks `Sam Drums OH` for their own convenience, mid-session, without a thought — and have done so for thirty years. That is an attribution fact, created at the moment of creation, by the person who knows, at zero cost, **already**. `meta/problem-statement.md` says "no system is present at the moment of creation" — but the *data* has been sitting in session files the whole time. Nobody read it because nobody had a reason to. | ✅ CONFIRMED — **the most elegant finding in this domain.** It requires no new behavior from the persona whose behavior cannot be changed, because the behavior already happened, years ago, for unrelated reasons. It is the difference between asking a producer to document their session and simply *reading what they already wrote*. |
| DT-02 | Because the guesses come from real data, they can be presented confidently | The natural follow-on from DT-01's optimism | ❌ **REJECTED — and this is where DT-01's elegance becomes dangerous.** A track named `Sam Drums OH` might be Sam. It might be a track Sam was *supposed* to play and Dave played instead. It might be named after the mic position and mean nothing about a person. It might be a template from another session. **A confidently-rendered wrong guess, confirmed by a tired producer at 1am, writes a false credit into the graph that is the platform's entire moat** — `07.03.01` DT-02's abuse surface arriving by accident rather than malice, which is worse because nobody is watching for it. Consequences: (a) guesses carry **visible confidence**, and low-confidence guesses are presented as questions, not as pre-filled answers; (b) ambiguity **never** resolves to a guess — it asks; (c) the counter-attestation (`07.06.02` D-04) is what catches the error, which means it is load-bearing *specifically because* this feature is fallible. The pre-fill and the counter-attestation are a matched pair: neither is safe alone. |
| DT-03 | Session formats can be parsed reliably | The premise of the whole feature | ⚠️ **PARTIALLY REJECTED — and it is a permanent, under-appreciated cost.** DAW session formats are **proprietary, undocumented, and change without notice**: Pro Tools' is closed; Logic's is an opaque bundle; Ableton's is at least gzipped XML. Parsing them means reverse engineering, and every DAW update can break it **silently** — the parse does not crash, it just stops finding tracks, and the prompts quietly go blank. Nobody notices for weeks, and the platform's core capture mechanism has degraded invisibly. Three consequences: (a) it is an **ongoing maintenance commitment** for a solo-built platform (`meta/problem-statement.md`), not a build-once feature; (b) coverage will be partial forever, so every dependent feature needs a defined degraded mode; (c) the platform needs to **detect its own parser rot** — an unmonitored parser is a liability, because silent degradation of the capture mechanism is indistinguishable from users simply not being credited. This is the single largest hidden operational cost in domain 07. |
