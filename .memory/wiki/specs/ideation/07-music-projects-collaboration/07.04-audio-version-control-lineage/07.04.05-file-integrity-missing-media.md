# Feature: File Integrity & Missing Media Detection

> **Number**: 07.04.05
> **Parent**: [Audio Version Control & Lineage](./07.04-audio-version-control-lineage-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

Verifying that an asset is what it claims to be and that everything it depends on is actually present. Two
distinct failures: **bit-level integrity** (the file is corrupt, truncated, or has silently rotted) and
**missing media** (a session file references 340 audio files and 6 of them are not in the package — the single
most common reason a handoff fails). Integrity is the precondition of canonicality (parent CX-04): a version
that cannot be trusted must never become the one everyone ships.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only | Sees, in plain language, why the version they wanted to bless cannot be blessed. Never a checksum error — "this file is damaged and needs re-uploading" is the entire message an artist needs. |
| Producer | Full | Sees integrity status across the project; re-uploads to fix; sees exactly which referenced samples are missing from a session package, by name, so they can go find them. |
| Operator | None | Not their business. |
| Fan | None | Not visible. |

## Behavior

**Integrity**: every asset gets a checksum at ingest. Verified at ingest, before entering a handoff package
(`07.08.01`), and on a slow background sweep of canonical assets. Deliberately **not** verified on every play —
checking a multi-GB asset before every listen is prohibitive, and a musician trying to hear their song should
never be blocked by a hygiene check (parent rejected-pair R-03).

**Missing media**: a DAW session file is a *pointer document* — it references audio files that may live anywhere
on the producer's disk, including in a shared sample library that was never part of the project. This is why
"the session opens fine on my machine" and arrives at the mastering engineer with 6 missing files. Detection
means parsing the session's references and checking them against what was actually uploaded.

The design constraint everywhere here is **actionability**. "Integrity check failed" is useless. "3 files
referenced by this session are missing: `kick_sub.wav`, `vox_dbl_3.wav`, `strings_bus.wav` — they were on your
machine but never uploaded" is a message someone can act on in 30 seconds.

### Happy Path

1. Producer uploads a session package via the bridge (`07.09.01`)
2. System checksums every asset and parses the session file for media references
3. All 340 references resolve; checksums pass
4. Version is marked verified and becomes eligible to be nominated canonical (parent CX-04)
5. The package can be handed off (`07.08.01`) with real confidence it will open on the recipient's machine

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Session references files outside the project (shared sample library) | **The most common real case.** Detected and named specifically — the producer usually did not realise the library was not part of the project | "6 files come from your sample library and aren't in this project. Include them?" |
| Referenced sample is a **licensed third-party** sound | Detected as missing; including it may be a licensing act, not just a file copy | Cross-links to `07.08.04` (source declaration) — "this sample is from a library; check its licence before shipping it" |
| Checksum fails at ingest | Upload rejected; retry offered. Failing here is cheap and correct. | "This file didn't arrive intact — retry" |
| Checksum fails **later** on a version that passed at ingest (bit rot, storage fault) | The alarming case. Alarm to the owner and producer. If the asset is canonical, this is a five-alarm event (`07.04.02` D-05) | Prominent alert, not a quiet flag |
| Truncated audio that is still a valid file (a bounce that stopped early) | **Checksums cannot catch this** — the file is intact, it is just wrong. Needs duration comparison against the parent version. | "This mix is 12 s shorter than v6 — intentional?" |
| Session format the parser does not understand | Media reference check unavailable; checksums still run. Honest degradation. | "Can't read references from this session type — files checked, references unverified" |
| Verification of a 4 GB package | Background job; never blocks the upload from completing | Progressive status |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Pending | Asset ingested, not yet verified | "Checking…" — version usable meanwhile |
| Verified | All checks pass | Quiet verified indicator; eligible for canonical |
| Missing media | References unresolved | Named list of missing files with an action |
| Corrupt | Checksum failed | Prominent failure; ineligible for canonical |
| Unverifiable | Unknown session format | Honest partial state — never claim verification not performed |
| Error | Verification job failed | Retry; **never** silently mark verified |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | "Missing media" is a far more valuable check than checksum integrity, and is a **different problem entirely** | The candidate bundled them, but their failure rates differ by orders of magnitude. Bit rot on cloud object storage is rare. A session file referencing samples that live in the producer's personal library — and therefore do not travel with the package — is the *normal* case, and it is the number one reason a handoff bounces back. The checksum is hygiene; the reference check is the product. | ✅ CONFIRMED — and it drives a real dependency: reference checking requires **parsing DAW session formats** (`07.09.02`). Without that, this feature is reduced to checksums, which nobody would notice or pay for. Another feature that quietly depends on the DAW bridge. |
| DT-02 | A checksum proves the audio is correct | The natural reading of "file integrity" | ❌ **REJECTED** — a checksum proves the *bytes* are unchanged, not that the audio is *right*. A bounce that stopped 12 seconds early is a perfectly intact file with a perfectly valid checksum, and it is completely wrong. Catching it needs a *semantic* check — duration, sample rate and channel count compared against the parent version in the lineage (`07.04.01`). This is a second concrete payoff of lineage: without a parent to compare to, "12 seconds shorter" is not even a computable question. Integrity therefore means bytes **and** plausibility. |
| DT-03 | This feature is infrastructure hygiene and belongs in `/create-prd`, not in the product | Fair challenge — checksums are plumbing, and the Node Classification Gate asks whether a candidate is architecture in a product costume | ⚠️ **PARTIALLY CONFIRMED — and split.** The checksum *mechanism* and storage-durability guarantees are architecture, and are routed to `/create-prd-architecture`. But missing-media detection is **not** infrastructure: it is a music-domain product feature that requires understanding DAW session formats, sample libraries and what a handoff needs to contain — and it is user-visible, actionable, and one of the domain's clearest wins. The feature stays; its plumbing half is routed. This is the correct outcome of the gate: not "keep or kill" but "keep the product, route the mechanism". |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Integrity means **bytes and plausibility** — checksum plus semantic comparison against the parent version | Per DT-02 — a truncated bounce is intact and wrong. |
| D-02 | **Missing-media detection is the valuable half** and is a genuine product feature | Per DT-01/DT-03 — it is the number one reason handoffs bounce. |
| D-03 | Verification at ingest, before handoff, and on a background sweep — **never on playback** | Parent rejected-pair R-03 — a hygiene check must never stand between a musician and hearing their song. |
| D-04 | Every failure message names **specific files and a specific action** | "Integrity check failed" is useless; "these 3 files are missing from your upload" is 30 seconds of work. |
| D-05 | Unknown session formats degrade **honestly** — never claim a verification that was not performed | A false verified badge on a handoff is worse than no badge. |
