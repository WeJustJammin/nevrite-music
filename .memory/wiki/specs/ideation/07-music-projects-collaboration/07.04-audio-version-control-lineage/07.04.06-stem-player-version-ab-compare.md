# Feature: Stem Player & Version A/B Compare

> **Number**: 07.04.06
> **Parent**: [Audio Version Control & Lineage](./07.04-audio-version-control-lineage-index.md)
> **Status**: [PARTIAL]
> **Last updated**: 2026-07-17

## Overview

The tool for actually judging two versions: switch between v6 and v7 at the same playback position, at matched
loudness, instantly. Plus stem soloing/muting for hearing what a mix is made of. Nobody has ever approved a mix
by reading a changelog — the change summary (`07.04.01`) is metadata, the audio is the truth, and this is the
only feature in the sub-domain where a human actually forms the judgement that everything else records.

> **Scoping note**: the underlying audio playback and waveform engine is a **cross-cut** (sub-domain D-04) —
> it serves marketplace previews (05, 14), lessons (06), releases (12) and fan listening (20). What lives here
> is the version-comparison *workflow*: loudness-matched, position-locked switching. That workflow is
> project-specific and exists nowhere else in the product.

| Producer | Full | Uses it to *demonstrate* — "listen to v7 against v6, the vocal sits better now". This is a persuasion tool as much as an evaluation one, and today that argument happens over two files in a WhatsApp thread where the client cannot switch between them at the same position. |

## Behavior

Two versions load; playback position is shared; switching is instantaneous and gapless — **the switch must be
imperceptible**, because any gap or reposition destroys the auditory memory that makes the comparison possible.
A 300 ms stall between A and B means you are no longer comparing mixes, you are comparing a mix to a memory of
a mix, and the feature has failed at its one job.

**Loudness matching is on by default.** Louder is perceived as better — this is one of the best-established
facts in psychoacoustics and the entire reason the loudness war happened. Comparing an unmatched v6 and v7
means the louder one wins, regardless of merit. A comparison tool that does not loudness-match is not a
comparison tool; it is a bias amplifier. It must be defeatable (sometimes loudness *is* the change under
review), but the default must protect the judgement.

Stem soloing is the same engine over a stem set (`07.04.04`) rather than two mixes.

### Happy Path

1. Musician opens the song timeline and selects v6 and v7 to compare
2. Both load; loudness matching is applied and shown ("matched: v7 −1.8 dB")
3. Plays; hits the toggle at the second chorus; the switch is instant and at the identical position
4. Toggles back and forth four times; hears the vocal difference the producer described
5. Nominates v7 as canonical (`07.04.02`) — a decision made by listening, which is the only way it is ever made

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Versions have different lengths (v7 has a longer intro) | Position mapping breaks — the same timestamp is a different musical moment. Align by musical position where possible; disclose when not. | "These versions differ in length — positions may not align" |
| Loudness matching disabled by the user | Allowed and remembered; sometimes loudness is the change | Clear indicator that matching is off — never ambiguous |
| Comparing a mix to a master | Loudness and dynamics differ hugely by design; matching helps but the comparison is inherently apples-to-oranges | Advisory noting the type difference |
| Bandwidth cannot sustain two streams | The dominant real-world constraint: instant switching requires both versions decoded and ready, which means buffering both. On a phone tethered in a studio car park this is the whole problem. | Preload with progress; degrade to a lower-bitrate preview for comparison rather than failing |
| One version's audio is unavailable (integrity failure) | Comparison unavailable; explained, not blank | "v6 is unavailable — its file failed an integrity check" |
| Stem soloing a 24-stem set on a phone | 24 simultaneous decoded streams is not viable on most devices | `[PENDING — /ideate-discover Step 5 deepening]` — likely server-side mixdown of the solo selection |
| Comparing versions the user only partly has access to | Only permitted versions offered (`07.03.03`) | Restricted set, with the restriction explained |

| Unavailable | A version cannot load | Explained, with the working version still playable |
| Error | Playback failed | Retry |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | **Loudness matching must be on by default**, or the comparison is worthless | The best-established fact in audio psychoacoustics: louder is perceived as better, reliably, even by trained engineers who know about the effect. The entire loudness war is this bias playing out at industry scale. An A/B tool without matching does not just fail to help — it actively produces wrong decisions, and it produces them *confidently*, because the listener believes they judged the mix. | ✅ CONFIRMED — non-negotiable default. This single decision is most of what separates a professional comparison tool from a pair of play buttons, and it is invisible to anyone who does not know why it matters. |
| DT-02 | The switch must be **instantaneous**, and this is an architectural requirement, not a polish item | Auditory memory for timbral detail decays in a few hundred milliseconds. Any stall between A and B means the user compares a mix to a *memory* of a mix, and the comparison is worthless. This makes the switch latency a hard functional requirement — the feature has exactly one job and this is it. | ✅ CONFIRMED — with a consequence for `/create-prd-architecture`: both versions must be decoded and buffered simultaneously, which conflicts directly with the bandwidth reality of the actual usage context (a phone, in a studio, on bad wifi). This tension is real and unresolved; it likely forces preloaded lower-bitrate comparison streams, which then raises whether you can honestly judge a *mix* on a degraded stream. Escalated as Q-01. |
| DT-03 | This is a generic audio player and should therefore be folded entirely into the playback cross-cut | The Node Classification Gate's mechanism test, applied honestly — and the reason sub-domain D-04 exists | ⚠️ **PARTIALLY CONFIRMED — and split.** The *engine* (decode, waveform render, streaming, transport) is genuinely a cross-cut serving 05, 06, 12, 14 and 20, and is recorded as such. But the *comparison workflow* — position-locked switching, loudness matching, stem soloing against a lineage — is not generic playback and serves no other domain: nobody A/Bs two versions of a plugin listing. The feature stays here; the engine is routed. Same outcome as `07.04.05` DT-03: keep the product, route the mechanism. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | **Loudness matching on by default**, defeatable with a clear indicator | Per DT-01 — without it the tool produces confidently wrong decisions. |
| D-02 | Switch latency is a **hard functional requirement**, not polish | Per DT-02 — auditory memory decays in hundreds of milliseconds; a slow switch means the feature does not work at all. |
| D-03 | The playback **engine** is a cross-cut; the **comparison workflow** stays here | Per DT-03 and sub-domain D-04. |
| D-04 | Degrade to lower-bitrate comparison streams rather than failing, and **say so** | The real usage context has bad bandwidth; silent degradation would let someone judge a mix on a stream that cannot represent it. |
