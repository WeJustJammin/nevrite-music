# Feature: Order Management & Lifecycle

> **Number**: 13.06.02
> **Parent**: [Cart, Checkout & Orders](./13.06-cart-checkout-orders-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The order's life from payment to settled: paid → packed → dispatched → in transit → delivered → settled, plus every way it deviates. Gear orders run longer and fail differently from retail — a freight shipment takes weeks, an international one clears customs, a $40k instrument gets inspected, and the thing being shipped is irreplaceable, so "we'll send another" is never available.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full (own orders, both sides) | Tracks the amp they bought; as a seller, works a short queue. Wants to know where it is and when the money lands — the persona's stated pain is income scattered and invisible. |
| Producer | Full (own, both sides) | Longer international orders with customs holds. Needs the "stuck in customs for 11 days" state to be legible rather than a silent gap. |
| Operator | Full (own, both sides) | Runs an order queue at volume from a back office; needs bulk operations and a work-queue view, not an order-detail page per unit. |
| Fan | Read-only (own orders, buyer side) | Tracks what they bought. No seller side. Needs plain "where is it" answers; will not interpret carrier status codes or a customs hold. |

## Behavior

The order is authoritative once the listing hits `sold` (13.03.02 hands off here). It composes escrow state (CX-M01), fulfilment state (CX-M14), and the gear-specific detours: customs holds, freight scheduling, damage claims (13.07.04), and returns (13.08.01). **Settlement is the terminal state that matters** — it releases the seller's money and triggers ownership transfer (13.06.05).

### Happy Path

1. Payment captured; order created per vendor
2. Seller notified; packs and dispatches (evidence pack seals — 13.02.04)
3. Tracking flows; buyer sees progress
4. Delivered; inspection window opens
5. Window closes without dispute → settled → funds released → ownership transfers (13.06.05)

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Seller doesn't dispatch | Order stalls; buyer's money is held; escrow must time out | Auto-cancel + refund after a bounded wait; seller cancellation cost (CX-M08) |
| Held in customs for weeks | Not a failure — normal for international gear | Explicit "in customs" state with the honest answer: this can take weeks |
| Arrives damaged | Routes to 13.07.04 with the evidence pack as baseline | Claim flow, not a return flow — different remedy, different payer |
| Not as described | Routes to 13.08.01 against the disclosure record | Return flow |
| Freight delivery needs scheduling | The buyer must be present with a way to receive 200kg | Delivery appointment state — parcel logic doesn't apply |
| Buyer never confirms delivery | Inspection window can't wait forever | Auto-settle after a bounded period; the window is a right, not an obligation |
| Order settles, then a stolen report lands | Ownership already transferred; may need reversing | `[PENDING]` — 13.03.07 Q-02, unresolved and legally loaded |
| Partial cart failure | One vendor's order proceeds, another's doesn't | 13.06.01 Q-01 |
| Seller ships to the wrong address | Non-recoverable for a unique object | `[PENDING — /ideate-discover Step 5 deepening]` |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Order view | Timeline skeleton |
| Empty | No orders | "No orders yet" |
| Populated | Order active | Timeline with the current state and what happens next |
| Error | State transition fails | Never leave state ambiguous — money and a unique object are both in flight |
| Partial | In transit, no carrier update for days | Honest "no update since X" rather than a stale status implying progress |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | The order lifecycle is generic e-commerce and should be a cross-cut | CX-M01 owns escrow, CX-M14 owns fulfilment — what's left looks like a shell | ❌ REJECTED: what's left is the gear-specific *shape*. The states that matter here — customs hold, freight delivery appointment, high-value inspection window, damage claim against a sealed evidence pack — exist in none of the other commerce domains. Digital goods (14) settle instantly; services (05) settle on revision rounds; ticketing (19) settles at the event. The order composes CX-M01 and CX-M14 rather than reimplementing them, but the composition *is* domain content. |
| DT-02 | The inspection window is a buyer-protection convenience | It reads as a grace period, so it gets defaulted to a round number of days | ❌ REJECTED: it is the **structural counterweight to non-fungibility**, and its length is a real economic decision, not a default. In fungible retail a bad unit is replaced; here there is no second unit, so the only remedy is unwind — and unwinding after a $40k instrument has crossed a border is expensive and slow. Too short and the buyer cannot realistically assess (a vintage amp's fault may only appear after an hour at volume; a Producer needs to hear a compressor in a real mix, not in the hallway). Too long and the seller's money is hostage while an irreplaceable object sits in a stranger's house. **The window is also where the seller's cash-flow pain lives**, which is the Musician persona's stated problem ("income visible in one place") pointing the opposite way from buyer protection. This tension is unresolved and belongs to the owner. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | The order composes CX-M01 and CX-M14; it never reimplements them | Per DT-01 — the gear-specific shape is the composition. |
| D-02 | Every stall has a bounded timeout with an automatic resolution | Money plus a unique object in indefinite limbo is the worst state available. |
| D-03 | Carrier silence is reported as silence, never as a stale status | "No update since Tuesday" is honest; a status implying progress is not. |
