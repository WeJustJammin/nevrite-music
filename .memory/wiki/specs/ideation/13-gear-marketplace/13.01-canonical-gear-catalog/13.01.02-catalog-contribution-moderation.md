# Feature: Catalog Contribution & Moderation

> **Number**: 13.01.02
> **Parent**: [Canonical Gear Catalog](./13.01-canonical-gear-catalog-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The path by which a model that isn't in the catalog gets into it, and the review that stops the catalog rotting. Gear's long tail is boutique, vintage and one-off — no licensed dataset covers it, so the catalog must be grown by the people listing the gear. That makes contribution a listing-flow concern, not an admin chore, and makes moderation the thing standing between a useful catalog and a poisoned one.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full | Hits "model not found" while listing a boutique pedal, fills a short model form inline, keeps listing. Accumulating accepted contributions earns moderator standing on categories they demonstrably know. |
| Producer | Full | Same contribution path; disproportionately the source of studio/outboard models (converters, preamps, rare mics) that no consumer dataset carries. |
| Operator | Full | Contributes backline and PA models when building rental/venue inventory. Often the only source for road-worn or discontinued production gear. |
| Fan | None | Cannot contribute or moderate. Rationale: contribution requires gear expertise the persona explicitly lacks, and the catalog's blast radius (DT-02 in 13.01.01) makes open contribution an attack surface. Fan sees the catalog read-only. |

## Behavior

Contribution is inline in the listing flow (13.01.04 routes here on match failure), never a separate destination. A submitted model enters a review queue; merge/dedupe candidates are surfaced against existing records via CX-M17. Accepted contributions publish the model and unblock the pending listing.

### Happy Path

1. Seller cannot find their model during listing creation
2. System offers "Add this model" with make/category prefilled from their search
3. Seller supplies model name, year, and the required attributes for that category
4. System runs dedupe against near-matches and shows "did you mean" candidates
5. Seller confirms it is genuinely new; model enters review as `provisional`
6. Listing proceeds immediately against the provisional model; on acceptance the model goes canonical

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Contribution is a duplicate of an existing model under a different name | Dedupe surfaces it pre-submit; if it slips through, moderation merges and re-points the listing | "This looks like [existing model] — use that instead?" |
| Bad merge of two genuinely distinct models | Merge must be reversible with an audit trail — this poisons comps silently, the worst failure in the sub-domain | Moderator sees merge history; affected listings re-pointed on unmerge |
| Seller inflates spec to make their unit look better (claims a rarer variant) | Model-level spec is not per-unit; unit claims belong to 13.02 disclosure and are the seller's liability | Model page shows canonical spec; listing claims are separately attributed |
| Contribution queue outgrows moderation capacity | `[PENDING — /ideate-discover Step 5 deepening]` — provisional-publish keeps sellers unblocked, but the backlog policy is unresolved | `[PENDING]` |
| Seller abandons the form mid-contribution | Draft listing retains the partial model; no orphan model created | Draft resumable |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Dedupe check running | Inline spinner on the "is this new?" step |
| Empty | No contributions pending (moderator view) | "Queue clear" empty state |
| Populated | Contribution submitted | Provisional model badge on the model page |
| Error | Submission fails | Error with retry; listing draft preserved |
| Partial | Model accepted with incomplete attributes | "Spec incomplete" affordance inviting further contribution |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Contribution can be an admin-only back-office function | Simplest-first instinct | ❌ REJECTED: gear's long tail is unbounded and mostly boutique/vintage. Admin-only contribution means every long-tail listing blocks on a human, which kills the listing flow — the one thing that must never stall. Contribution must be inline and provisional-publish. |
| DT-02 | Open contribution needs a trust gradient, not a binary permission | Wikipedia/Discogs precedent + DT-02 in 13.01.01 (blast radius) | ✅ CONFIRMED: catalog corruption is silent and downstream. Earned category-scoped moderator standing (contributions accepted in a category → review rights in that category) matches how gear expertise actually distributes — a drum tech should not be merging vintage tube amps. |

## Decisions

| # | Decision | Context |
|---|----------|---------|
| D-01 | Contribution is inline + provisional-publish, never blocking | Per DT-01 — a blocked listing is a lost listing. |
| D-02 | Moderator standing is earned and category-scoped | Per DT-02 — gear expertise is narrow and deep, not general. |
| D-03 | Fan has no contribution access | Persona explicitly lacks the domain expertise; catalog blast radius makes open contribution an abuse surface. |
