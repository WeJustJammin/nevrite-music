# Feature: Listing↔Model Matching & Entity Resolution

> **Number**: 13.01.04
> **Parent**: [Canonical Gear Catalog](./13.01-canonical-gear-catalog-index.md)
> **Status**: [SURFACE] — **Deep Think addition** (not in the sweep's candidate list)
> **Last updated**: 2026-07-16

## Overview

The join that binds a seller's free-text intent ("62 Jazzmaster, refin") to a canonical model record. It is the single point where the catalog either earns its keep or becomes decorative: an unmatched listing has no comps, no facets, no alerts and no price guide entry. This is the mechanism, not the data — it decides what a listing *is*.

**Why this exists as a node**: the sweep listed the catalog (13.01.01) and contribution (13.01.02) but never the resolution step between them. Without it, the two are unconnected: one holds models, the other adds models, and nothing attaches a listing to either.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Full (as seller) | Types what they're selling; sees ranked model candidates; picks one, or escalates to "add this model" (13.01.02). As a buyer, never sees this — they only feel its absence when a listing doesn't show up in their facet search. |
| Producer | Full (as seller) | Same flow; hits match failure more often because studio outboard is thinner in any catalog than guitars. |
| Operator | Full (as seller) | Same flow, at volume — matching quality decides whether a bulk import (13.03.04) lands clean or produces hundreds of unmatched listings. |
| Fan | None | No listing surface, so no matching surface. Fan experiences matching only indirectly, as search results that are complete or aren't. |

## Behavior

Matching runs on every listing draft: seller text + optional decoded serial (13.01.03) + category → ranked candidate models with a match confidence. High-confidence single candidates auto-bind (reversibly); ambiguous ones prompt; zero candidates route to contribution. **A listing may publish unmatched** — matching must degrade, never block.

### Happy Path

1. Seller types "1962 Fender Jazzmaster sunburst" in listing creation
2. System returns ranked candidates, top one high-confidence
3. Seller confirms the model + variant/finish
4. Listing binds to the canonical model; facets, comps and price guide entry light up
5. Buyer's saved search for that model now matches this listing

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Zero candidates (boutique/one-off) | Route to 13.01.02 contribution; publish against a provisional model | "Can't find it? Add this model" |
| Multiple plausible candidates (reissue vs original) | Never auto-bind; force disambiguation | Candidate picker with distinguishing attributes surfaced (year, country, spec delta) |
| Seller picks the wrong model deliberately to ride a better comp set (a reissue listed against the original's model) | **Match is a claim.** Serial decode and mandatory disclosure (13.02) are the counterweights; mismatch is a domain-24 concern | Mismatch signals flagged; comps shown are the *bound* model's |
| Seller picks the wrong model accidentally | Rebindable post-publish with comp recalculation | "Change model" on the listing |
| Listing publishes unmatched | Allowed. Listing is searchable by text only; no comps, no facets, no alert matches | "Not linked to a catalog model — link it to appear in filtered searches and price data" |
| Bound model is later merged/unmerged by moderation | Listing re-points; comp set changes underneath a live listing | `[PENDING — /ideate-discover Step 5 deepening]` — whether the seller is notified of a comp shift mid-listing is unresolved |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Draft text entered | Debounced candidate spinner |
| Empty | No text yet | Model search field with category hint |
| Populated | Candidates returned | Ranked picker with confidence and distinguishing attributes |
| Error | Match service down | Manual model search fallback; unmatched publish permitted |
| Partial | Bound to model, variant unselected | "Which finish/variant?" prompt — comps narrow once resolved |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | Matching should block publish until a model is bound — an unmatched listing is a bad listing | Data-purity instinct; a clean catalog argues for it | ❌ REJECTED: the listing flow is the one flow that must never stall (same reasoning as 13.01.02 DT-01). A seller with a genuinely uncatalogued boutique pedal who is told "you cannot list this" leaves. Unmatched publish is degraded but permitted; the *incentive* to match is that matched listings get comps, facets and alert reach — carrot, not gate. |
| DT-02 | High-confidence auto-bind is safe | Efficiency instinct — fewer prompts, faster listing | ⚠️ CONFIRMED WITH CONSTRAINT: auto-bind is safe **only if reversible and only above a high threshold**, because a wrong bind is worse than no bind — it produces a *confidently wrong* comp set and a price guide entry that lies. The reissue-vs-original case is the canonical trap: high textual similarity, order-of-magnitude price difference. Reissues must be excluded from auto-bind. |

| # | Decision | Context |
