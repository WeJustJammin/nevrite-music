# Feature: Model Records, Taxonomy & Attribute Schemas

> **Number**: 13.01.01
> **Parent**: [Canonical Gear Catalog](./13.01-canonical-gear-catalog-index.md)
> **Status**: [SURFACE]
> **Last updated**: 2026-07-16

## Overview

The canonical record for a gear **model** — make, model name, year range, variant, finish, country of manufacture — plus the category tree it sits in and the per-category attribute schema that defines what facets exist. A guitar has scale length, pickup configuration and body wood; a microphone has polar pattern and transducer type; a cymbal has diameter and alloy. One flat attribute table cannot serve both, so the taxonomy carries the schema.

## Role Lens

| Role | Access | What They See/Do |
|------|--------|-------------------|
| Musician | Read-only | Browses/filters by category facets when hunting gear; lands on a model page showing spec, year range, variants and (via 13.04) what it's worth. Cannot edit a model directly — edits go through 13.01.02. |
| Producer | Read-only | Same as Musician; uses attribute facets more heavily for studio gear (converter channel count, preamp topology, impedance) where spec correctness decides whether the thing is usable at all. |
| Operator | Read-only | Reads model records to describe backline and studio inventory accurately in venue/studio listings (domain 16) and rental rate cards (13.10). |
| Fan | Read-only | Sees the model page as a browsable catalog entry when shopping for a first instrument. No facet-schema visibility, no edit path. |

## Behavior

A model record is a **type**, never a unit. It carries no condition, no price, no owner. Listings (13.03) and registered instruments (domain 15) both reference it. The category tree assigns each model an attribute schema; attributes are typed and unit-bearing (`scale_length: 25.5 in`), which is what makes facets rangeable rather than string-matched.

### Happy Path

1. Seller (or buyer) searches for "1962 Fender Jazzmaster"
2. System resolves to a canonical model record with year range, known variants and finish options
3. User sees spec attributes, variant picker, and links to active listings + price guide entry
4. User selects the exact variant/finish; that selection is what a listing or registry entry binds to

### Edge Cases / Failure Modes

| Scenario | What Happens | User Sees |
|----------|-------------|-----------|
| Model genuinely does not exist in catalog (boutique/one-off) | Route to contribution flow (13.01.02) rather than blocking | "Can't find it? Add this model" — inline contribution CTA |
| Manufacturer reissues a model under the same name decades later | Year range disambiguates; distinct model records with a "related model" link | Disambiguation picker: "1962 original" vs "1999 reissue" |
| A model spans a spec change mid-year with no name change | `[PENDING — /ideate-discover Step 5 deepening]` — likely variant-level, but the boundary between "variant" and "new model" is unresolved | `[PENDING]` |
| Attribute exists for one category but is requested in another (a "pickup config" facet on a snare drum) | Schema is per-category; the facet is simply absent | Facet not rendered |

### States

| State | Trigger | What User Sees |
|-------|---------|---------------|
| Loading | Model page requested | Skeleton with spec-table placeholder |
| Empty | Category has no models yet (cold catalog) | Empty state with "Add the first model" CTA |
| Populated | Model resolved | Spec table, variants, active listings, price guide link |
| Error | Catalog lookup fails | Error with retry; listing creation must not be blocked — fall back to unmatched listing (13.01.04) |
| Partial | Model exists but spec attributes incomplete | Spec table with "spec incomplete — contribute" affordance on blank rows |

## Deep Think Annotations

| # | Hypothesis | Source | Outcome |
|---|-----------|--------|---------|
| DT-01 | A single flat attribute table can serve all gear categories | Naive schema instinct; the same instinct D-14 rejected for the merged `listing` entity | ❌ REJECTED: guitars, mics, cymbals and rack gear share almost no attributes. A flat table reproduces the ~40-nullable-column failure D-14 named. Attribute schema must be per-category. |
| DT-02 | Catalog correctness is high blast radius, not just a data-quality nicety | Reasoning about downstream consumers | ✅ CONFIRMED: model identity feeds comps (13.04), alerts, facets, and the registry's unit identity (domain 15). A wrong merge of two similar models silently poisons every price the guide quotes. Moderation (13.01.02) is therefore a **must**, not a **could**. |
