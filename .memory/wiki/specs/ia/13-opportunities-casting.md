## Overview

Shard 13 owns opportunity publication, targeting, finite discovery, alerts, structured submissions/auditions, conflict-safe review, offers/counters, irreversible dispositions and typed downstream handoff. An opportunity is a terms container with independently fillable slots. It never treats credit as compensation, posting as consent, submission as rights transfer, graph proximity as authority, silence as withdrawal, or a won opportunity as downstream membership/rights truth.

## Features

- **04.01 Opportunity Posting & Targeting** — immutable curated types, per-slot lifecycle, ordered targeting, compensation/spec-work publication gate and trust-tiered eligibility.
- **04.02 Discovery, Matching & Alerts** — finite explainable board, availability/travel/material fit and strictly bounded user-created alerts.
- **04.03 Submission & Audition** — assembled entity submissions, cited evidence, rights-bounded audition tasks, paperwork-layer blind review and policy-respecting pitches.
- **04.04 Triage, Shortlist & Decisioning** — recoverable triage, disagreement-preserving shortlist, immutable-fuse offers and honest urgent-fill cascades.
- **04.05 Outcome, Response & Handoff** — per-submission close-out obligation, response signals, idempotent typed handoff and private applicant history.
- **04.06 Band & Member Wanted** — specialized membership outcome with 90-day decide-by and no Operator surface.
- **04.07 Open Calls** — festival/showcase/competition calls with explicit decide-by, no submission fees and no Fan voting.

## Acceptance Criteria

- **AC-OPP-01 — Draft opportunity:** Given Actor resolves an explicit acting party and attributed decider through Shard 01 with post-administration authority, and the post is in `draft`; any prefilling context must be readable and may never prefill compensation, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Poster chooses explicit acting identity/decider, immutable type, slots, date/location, decide-by, compensation and criteria; context may prefill facts except compensation, and (6) return Draft/container/slot versions persist; if the flow cannot complete, A silent or absent acting identity, unresolvable decider authority or an unreadable context returns `VALIDATION_FAILED` or `FORBIDDEN` with nothing persisted; a stale acting context returns `ACTING_CONTEXT_STALE` and a superseded draft returns `VERSION_CONFLICT`; the draft stays editable and the actor may re-resolve identity and retry.
- **AC-OPP-02 — Publish/re-publish:** Given Post is in `draft` with immutable type, slot schemas, date semantics, decide-by, complete compensation and criteria present, and poster/decider authority resolves at the current Shard 01 version; the gate rule version pins at publication and no admin force-publish path exists, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Gate validates type schema, compensation six facets, unpaid/spec-work legitimacy, criteria and target policy; no admin force-publish, and (6) return Frozen terms/rule-set version publishes or exact gaps return; if the flow cannot complete, Any gate failure — missing compensation facet, applicant-side fee, credit-as-pay, unbounded negotiable, illegitimate unpaid or spec-work terms, or a protected criterion on a labour type — returns `PUBLICATION_GATE_FAILED` naming the exact gaps and publishes nothing; changing type on re-publish returns `TYPE_IMMUTABLE` and offers the clone/new-post path; a live post keeps its pinned rule set, admins may only unpublish, and the poster may correct the gaps and re-run the gate.
- **AC-OPP-03 — Edit live terms:** Given Poster holds current authority on a published post and submits a material live edit — downward compensation or tighter criteria — against the current terms version; the live post remains bound to its pinned gate rule set, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Downward compensation or tighter criteria creates new terms version, re-gates and marks every existing submission `terms_changed` with Stay/Withdraw, and (6) return Applicant notices and terms version commit; silence keeps applicant; if the flow cannot complete, A material edit failing re-gating returns `PUBLICATION_GATE_FAILED` and no successor terms version is created; an edit against a superseded terms version returns `VERSION_CONFLICT`; no applicant is ever silently withdrawn — every active submission is marked `terms_changed` with a readable delta and a Stay/Withdraw choice, silence preserves candidacy, and an applicant who cannot see a delta may still withdraw.
- **AC-OPP-04 — Configure targeting cascade:** Given Poster holds post authority and orders cascade stages against a terms version whose targeting has not yet frozen; trusted-network stages resolve against the Shard 11 verified-credit graph, never follows, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Poster orders invite/trusted-network/qualified-local/broad stages; trusted network uses verified-credit graph, not follows, and (6) return Cascade stages, timing and audience predicates freeze; if the flow cannot complete, An out-of-order or unresolvable audience predicate returns `VALIDATION_FAILED` and writes no stage; a follows-based trusted-network definition is rejected; editing a frozen cascade returns `VERSION_CONFLICT` and requires a new terms version through OPP-03; degraded Shard 11 evidence narrows the reachable audience honestly rather than fabricating one, and the poster may re-order and re-freeze.
- **AC-OPP-05 — Browse/search board:** Given Viewer requests the board; targeting entitlement, viewer blocks/restrictions and own-acting-party exclusion resolve before ranking, and Fan or logged-out viewers receive the safe projection without professional compensation or protected filters, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Viewer sees finite, exhaustible, fit-first results with one-sentence reasons, declared compensation, freshness and own-party posts excluded, and (6) return Stable session result/cursor and “new” count returned; if the flow cannot complete, Unavailable matching or evidence sources degrade the result with a named explanation and keep posts and candidates reachable, never a false mismatch or reject; a board cache older than sixty minutes is stamped with its age and stripped of fit claims rather than blanked or spun; results stay finite, exhaustible and session-stable and the viewer may request the accumulated new set explicitly.
- **AC-OPP-06 — Save alert intent:** Given User explicitly creates the subscription and holds fewer than twenty live intents; policy computes the tier from type floor, time-to-close, context-raised status and material confidence, clamped by the user's own ceiling, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) User explicitly creates bounded subscription; no silent intent. Policy computes tier from type/time/context/material evidence and user ceiling, and (6) return Intent/version/delivery budget commits; if the flow cannot complete, An implicit or system-inferred intent is never created; exceeding the intent cap or supplying an unbounded query returns `VALIDATION_FAILED` and writes no intent; a poster-declared urgency override is rejected and Critical falls back to the computed tier; delivery beyond two lifetime sends per user and post is suppressed rather than queued, and the user may edit or delete the intent at any time.
- **AC-OPP-07 — Assemble submission:** Given Submitting person or Band resolves an acting identity, targets an `open` slot on the current terms version, satisfies its eligibility criteria and is not a reviewer on that slot; evidence is cited by reference and per-date availability is confirmed deliberately, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Submitting person/Band chooses exact slot, cites selected evidence, confirms per-date availability and bounded answers; no one-click/bulk/template apply, and (6) return Submission version/claim/evidence refs commit; if the flow cannot complete, Failed eligibility returns `ELIGIBILITY_FAILED` naming the criterion; an evidence or calendar source outage degrades the assembler with a visible gap instead of blocking or fabricating fit; a second submission for the same entity, post and slot supersedes the prior version or returns it idempotently rather than creating a duplicate candidate card; one-click, bulk or template submission is refused, and the applicant may complete the missing confirmations and resubmit.
- **AC-OPP-08 — Complete audition task:** Given Applicant holds a live submission on a slot carrying an `audition_task` whose scope, rounds, retention, payment and rights passed the spec-work gate and are disclosed before any work begins; strong cited evidence may waive the task entirely, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Applicant sees scope, rounds, retention, payment and rights before work; resumable upload; strong evidence may waive task, and (6) return Task attempt/media/evidence state commits; if the flow cannot complete, A task exceeding one unpaid evaluation-only round, claiming use rights or omitting return/destroy on non-selection is refused at source by the spec-work gate and no attempt is accepted; an interrupted upload resumes from its last durable part rather than restarting; a failed attempt leaves prior attempts and evidence intact so the applicant may retry until the decide-by.
- **AC-OPP-09 — Submit unsolicited pitch:** Given An eligible professional targets a party whose current published `target_pitch_policy_version` evaluates to `open`, `open_with_criteria` with every required criterion satisfied, or `referral_only` with a current graph-verifiable referral; every open-mode policy declares an integer `disposition_sla_days` from 7 through 30; Fans may not pitch, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) re-evaluate the current policy at submit, enforce its typed criteria/referral/rate-policy versions, pin the winning policy/evaluation and compute `disposition_due_at = submitted_at + disposition_sla_days`, and (6) return the ordinary target-anchored Submission with pitch source, policy-evaluation and disposition-deadline commits; if the flow cannot complete, no policy, expired/unreadable policy or `closed` mode returns `PITCH_POLICY_CLOSED`; a moved policy returns `PITCH_POLICY_CHANGED` with safe requirements and writes nothing; an absent or out-of-range SLA returns `PITCH_SLA_INVALID`; unmet criteria, missing referral, rate limit, ineligible actor or Fan returns a typed refusal without queue leakage. Policy-violating volume routes to Shard 06; no stale evaluation, inherited setting or later policy change can rewrite an admitted pitch's deadline.
- **AC-OPP-10 — Triage candidate:** Given Reviewer holds an assignment with Shard 01 activity and domain authority and is not a candidate on that slot; `reject` additionally requires fully loaded queue, evidence, criteria and media, and `hold` requires a closed blocker, named owner and resolve-by no later than the slot decide-by, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized non-candidate reviewer selects advance/reject/hold; reject disabled on incomplete evidence/queue; hold requires blocker/owner/resolve-by, and (6) return Recoverable vote or irreversible disposition rule applied; if the flow cannot complete, A reviewer who is also a candidate is excluded automatically, overriding every grant, and receives `REVIEW_CONFLICT` without leaking the queue's existence or contents; an incomplete queue or evidence disables reject and returns `EVIDENCE_INCOMPLETE` while advance and hold stay available and recoverable; a hold missing blocker, owner or resolve-by returns `VALIDATION_FAILED`; bulk triage without a criterion live at submit and an exact count is refused, and the reviewer may retry once the queue loads.
- **AC-OPP-11 — Shortlist/review:** Given Authorized non-candidate reviewers assess submissions already advanced on an open slot; each review is recorded independently against its own rubric and the shortlist persists until an acceptance closes the slot, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized reviewers independently assess; disagreement remains visible and is never averaged; shortlist survives until acceptance, and (6) return Review records/shortlist version commit; if the flow cannot complete, A candidate reviewer returns `REVIEW_CONFLICT` and is excluded; scores are never averaged into an authority value, so disagreement is preserved and returned rather than resolved by the system; a concurrent shortlist edit returns `VERSION_CONFLICT` leaving prior reviews intact, and reviewers may re-read and re-record.
- **AC-OPP-12 — Issue offer:** Given Decider authority re-resolves at issue time on a slot that is not yet `filled`, final terms and every delta against the published post are explicit, the compensation gate re-runs and passes, and the fuse plus live parallel-offer count are set; handoff mode was fixed at publication and cannot be chosen now, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Decider supplies exact final terms/delta, compensation gate, fuse, parallel-offer disclosure and target handoff mode, and (6) return Irrevocable active offer version commits; if the flow cannot complete, A failed compensation re-gate returns `PUBLICATION_GATE_FAILED` and issues no offer; lost decider authority returns `FORBIDDEN` or `ACTING_CONTEXT_STALE`; an already-filled slot returns `SLOT_ALREADY_FILLED`; once active the offer is issuer-irrevocable inside its fuse except for a named external cause recorded on the offer, so the decider's only recourse is fuse expiry or recording that cause.
- **AC-OPP-13 — Counter/accept/decline:** Given Candidate owns the submission carrying an `active` offer and responds inside its fuse window; acceptance additionally requires an available full post-to-offer delta and still-valid confirmed availability, and a counter is issued as a new reverse-direction offer with its own gate, fuse and delta, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Candidate sees full delta; counter is reverse offer; acceptance ordered by platform receipt and atomically checks availability; decline may use structured reason, and (6) return Winning offer/slot transition and downstream outbox commit; if the flow cannot complete, An expired fuse returns `OFFER_EXPIRED` and a slot filled by an earlier receipt returns `SLOT_ALREADY_FILLED` with a named cascade or filled outcome, never an ambiguous "too late"; when the delta cannot be computed accept is disabled while decline stays usable; acceptance is ordered by server receipt sequence and never device timestamp, so a losing acceptance mutates nothing and receives its disposition; a candidate holding a live offer must decline rather than withdraw.
- **AC-OPP-14 — Run urgent-fill cascade:** Given Poster supplies an explicit ranked candidate list on an unfilled slot and each cascade step issues an ordinary offer with a bounded fuse and honest parallel-offer disclosure; platform confidence may inform display but never re-orders the poster's list, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Poster ranks candidates; platform issues bounded-fuse parallel/serial offers honestly; platform confidence never outranks list, and (6) return First accepted by receipt wins; named cascade losses close; if the flow cannot complete, An unranked list or an undisclosed parallel offer returns `VALIDATION_FAILED` and issues no cascade step; the first acceptance by server receipt fills the slot and every remaining cascade recipient receives a named cascade-loss outcome and disposition rather than silence; expired steps return `OFFER_EXPIRED` and the poster may continue down the ranked list until the decide-by.
- **AC-OPP-15 — Disposition applicants:** Given A post submission has reached a closable state or an admitted unsolicited pitch is open and carries its pinned deadline; no prior disposition exists, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) commit the first irreversible per-submission disposition: winning acceptance fans out ordinary slot outcomes; an authorized target may individually or exact-count bulk-close only eligible open unsolicited pitches as neutral `not_pursuing`; at `disposition_due_at` the system records `no_response` for any still-open pitch, and (6) atomically commit disposition attribution/source, notice and response-signal effect; if the flow cannot complete, `DISPOSITION_EXISTS` preserves the first truth. Bulk scope excludes held, shortlisted, offered, accepted and already-dispositioned pitches; a bulk/individual/expiry race is compare-and-set per submission. Target-authored `not_pursuing` counts as a response; system-authored `no_response` closes and notifies the pitcher but adds target response debt. Delist/delete never discharges an obligation; applicants cannot nudge or self-close.
- **AC-OPP-16 — Execute handoff:** Given A durable acceptance event exists, the publication-fixed handoff mode and target are readable, and the acceptance fact manifest is assembled; creating membership, authority, rights ownership or a final split additionally requires the owning downstream domain's consent, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Outbox creates/joins/proposes exact downstream target fixed at post time; acceptance remains valid if handoff retries/fails, and (6) return Handoff state/back-references/cast-credit triggers converge; if the flow cannot complete, Downstream failure returns `HANDOFF_FAILED` and never rolls back acceptance — retries reuse the fact manifest idempotently, escalating at fifteen minutes on the standard path and sixty seconds when urgent or the date is under 48 hours; an absent downstream target closes the slot as won and yields an external handoff artifact rather than a fabricated project or membership; a Band winner with unresolved cast carries that state forward with no member fan-out, and divergence stays visible to owner and winner.
- **AC-OPP-17 — Review pipeline history:** Given Viewer is the applicant reading its own submissions or the post owner reading its own pipeline; entries are immutable, survive post deletion, and any hide action is viewer-local rather than a deletion, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Applicant sees own immutable age/state/diffs/onward links and may hide locally; poster sees private owner-scoped pipeline, and (6) return Viewer-specific history projection returned; if the flow cannot complete, A request outside the viewer's own scope returns `FORBIDDEN` and never exposes queue position, other candidates or reviewer notes; a hide is reversible by the viewer because it deletes nothing; an unavailable projection returns a typed unavailable state with the immutable entries preserved for retry.
- **AC-OPP-20 — Configure target pitch policy:** Given The actor controls the target party or holds a current Shard 01 mandate with `pitch_policy:write`; the proposed mode is one of `open`, `open_with_criteria`, `referral_only`, `closed`; every open mode supplies integer `disposition_sla_days` from 7 through 30 plus a current rate-policy version, criteria mode supplies a nonempty typed criteria set and referral mode supplies an allowed graph-referral class and maximum age, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) publish an immutable effective version that supersedes the prior target-local version; absence, expiry, retirement or unreadability remains closed and no policy inherits across targets, and (6) return the published policy version and evaluation hash; if the flow cannot complete, `FORBIDDEN` without target authority, `PITCH_SLA_INVALID` for absent/out-of-range open-mode SLA, `VALIDATION_FAILED` for another mode/payload mismatch or unsafe criterion, `VERSION_CONFLICT` when another version published first, and `ACTING_CONTEXT_STALE` when the mandate moved. Closing or expiry blocks new drafts/submissions but does not delete admitted queue items, change their pinned deadlines or remove policy evidence; a Shard 06 restriction can close reachability without mutating policy history.
- **AC-OPP-18 — Fill band membership:** Given Band representative acts under a current Shard 01 mandate on a membership-type slot carrying its explicit 90-day decide-by, and an accepted candidate's membership proceeds through Shard 01 membership governance rather than a service engagement, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Band posts specialized role; accepted candidate transitions through Shard 01 membership/governance, not service engagement, and (6) return Membership proposal/outcome link commits; if the flow cannot complete, A representative without mandate, or any attempt to infer member consent, returns `FORBIDDEN` and creates no membership; a Shard 01 governance refusal leaves the acceptance intact, records the outcome as won with membership pending and returns `HANDOFF_FAILED` for idempotent retry; unresolved cast is carried forward explicitly with no member fan-out.
- **AC-OPP-19 — Run open call:** Given Organizer holds post authority and publishes a call with an explicit decide-by and stated submission and judging rules; applicant-side fees are unrepresentable in the schema and Fan voting is absent from the judging rules, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Organizer publishes fee-free no-Fan-voting call with explicit decide-by and submission/judging rules, and (6) return Open-call lifecycle uses ordinary slots/submissions/dispositions; if the flow cannot complete, A missing decide-by or judging rule returns `VALIDATION_FAILED`, and an attempted applicant fee or Fan-vote mechanism fails the gate with `PUBLICATION_GATE_FAILED` and publishes nothing; once published the call runs on ordinary slots, submissions, offers and dispositions so every applicant still receives a per-submission close-out, and the organizer may correct and republish before the first submission.

### Global Interaction Rules

- Commands carry `actor_person_id`, `acting_party_id`, `acting_context_version`, `idempotency_key`, `expected_version?`, `request_id` and post/slot/terms version.
- Post/container state derives from slot states. Every submission, offer and disposition is scoped to one slot.
- Acting identity, poster and decider are separate attributed facts. Authority resolves through Shard 01 at each high-consequence action.
- Targeting resolves before matching. Protected-characteristic criteria are unrepresentable for labour-class types and jurisdiction-gated for performance types.
- Applicant calendar conflicts and availability are private; only candidate-confirmed availability state reaches poster.
- Missing evidence/provider/calendar/material signals fail open to submission/matching degradation, never fabricate fit or reject.

## Edge Cases

| Case | Required result |
|---|---|
| Type change requested after publish | Reject unconditionally; clone/new post path offered. |
| Compensation decreases live | Re-gate, notify every applicant with delta, mark terms-changed; no silent withdrawal. |
| Rules change after publish | Live post remains on pinned rule set; re-publish uses current gate. |
| Matching source unavailable | Keep reachable candidate/post with degraded explanation; no false mismatch/reject. |
| Applicant submits concurrently twice | Same entity/post/slot supersedes or idempotently returns current; no duplicate candidate card. |
| Reviewer is candidate | Automatic exclusion overrides all grants; no queue existence/details exposed. |
| Queue/evidence partially loads | Reject disabled; advance/hold remain recoverable where safe. |
| Two offer acceptances race | First server receipt atomically fills slot; loser receives named cascade/filled outcome. |
| Handoff fails after acceptance | Acceptance remains; idempotent retry/escalation, never rollback. |
| Post deleted with open applicants | Delist only; submissions/obligations/history persist until disposition. |
| Offer candidate withdraws | Live offer requires decline; pre-offer alone permits withdrawal. |
| Downstream target absent | Close as won and provide external handoff artifact; no fabricated project/membership. |
| Band win has unresolved cast | Handoff carries unresolved-cast state; no member fan-out. |
| Board cache older than 60 minutes | Stamp age and remove fit claims; never blank/spinner. |
| Target has never configured pitching | Resolve `closed` before composition; no draft or queue lookup is created. |
| Policy changes while a pitch is being composed | Submit returns `PITCH_POLICY_CHANGED` with the new safe requirements and writes nothing; the author must review and explicitly resubmit against the new version. |
| Shard 06 closes target reachability | New composition/submission fails closed without rewriting target policy history or revealing the restriction reason; existing submissions remain ordinary queue records. |
| Target bulk-closes 400 admitted pitches | Require fully loaded explicit filter, displayed exact count, policy/queue versions and neutral `not_pursuing`; exclude held, shortlisted, offered, accepted and dispositioned pitches; persist and notify once per submission with resumable idempotency. |
| Bulk close races an individual advance or offer | Per-submission compare-and-set decides independently; an advanced/held/offered pitch is excluded or returns its current state, and bulk retry never overwrites it or sends a false `not_pursuing` notice. |
| Deadline expiry races a target disposition | First immutable disposition commit wins. Target `not_pursuing` before the deadline counts as response; system `no_response` at/after the deadline counts as debt. Loser returns `DISPOSITION_EXISTS`; exactly one notice and signal fact exist. |
