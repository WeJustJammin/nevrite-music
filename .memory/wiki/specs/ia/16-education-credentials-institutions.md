# Shard 16 — Courses, credentials, institutions and special practice

**Status:** Complete
**Surface:** Astro hybrid web/PWA with React islands
**Source:** [Architecture design](../2026-08-02-architecture-design.md) · [Decomposition plan](decomposition-plan.md)

## Overview

Shard 16 owns governed course authoring, catalog sales, course entitlements, consumption, third-party exam-board alignment and the future academy teaching-operations boundary. It does not issue platform credentials, infer musicianship, admit health/therapy records, merge course entitlements with lesson credits or activate institution administration before consumer launch is ready.

### Scope Reconciliation

| Reconciliation item | Result |
|---|---|
| In-scope source documents loaded | 9 |
| Child capabilities reconciled | 7 |
| Course chain | Authoring/publishing, catalog/pricing/enrollment, consumption/completion |
| Third-party education evidence | Exam-board syllabus mapping, deadlines and externally issued result records |
| Deferred institution capability | Academy/multi-teacher operations behind post-consumer `/evolve-feature` gate |
| Excluded capabilities | Platform certificates/badges and music-therapy practice |
| Launch age boundary | Adult authors and purchasers only; minors cannot buy, consume UGC courses or enter academy flows |

### Product and Governance Decisions

| Area | Locked decision |
|---|---|
| Marketplace admission | Governed adult-author intake. Admission mode is a versioned setting, but publication always requires identity, rights, metadata, media and policy gates. |
| Course completeness | A paid course publishes only a complete declared edition. Later additions are free living-entitlement updates; unfinished promises are not sold. |
| Repertoire | Authors may reference lawful repertoire; third-party recordings, notation or editions are not hosted without verified rights. |
| Course support | Course purchase is asynchronous and creates no author Q&A or response obligation. A separate lesson/service offer may be linked. |
| Offline media | Deferred. Launch delivery is authorized streaming; progress and approved text metadata may cache, governed media may not. |
| Credentials | Shard 02 displays approved third-party evidence. WeJammin never issues a skill certificate, badge, grade or trust mark. |
| Exam boards | Absent at US consumer launch. Future board support is additive, per-board and per-syllabus-version; grades are never normalized. |
| Institutions | Multi-teacher academy operations are fully deferred until consumer readiness and explicit `/evolve-feature`. |
| Therapy | Music-therapy/clinical records, treatment goals, outcome instruments, insurance billing and PHI are prohibited from this product estate. |

## Acceptance Criteria

- **AC-EDU-CI-01 — Eligible adult author creates course:** Given An authenticated adult party holds current author admission under the versioned admission-mode setting and names an explicit individual course owner plus the active authoring-policy version, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Resolve acting party and admission; create private draft with explicit individual owner and policy version, and (6) return Draft exists; no catalog projection; if the flow cannot complete, A minor or unverified adult returns `ADULT_REQUIRED` and an unadmitted party returns `ADMISSION_REQUIRED`, in both cases with no draft created; a replayed idempotency key returns the original draft rather than a second course; admission is an eligibility gate only and cannot waive the later hard publication predicate.
- **AC-EDU-CI-02 — Author structures and uploads lessons:** Given The course is in `draft` or `review_pending`, the actor holds owner or revision-scoped contributor capability, and every upload intent declares purpose, MIME type, size and checksum against the expected draft version, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Save immutable outline revisions; create governed upload intents; transcode/scan asynchronously without losing draft state, and (6) return Media becomes playable or retryable with reason; if the flow cannot complete, A malformed or undeclared upload returns `UPLOAD_INVALID` before any object is reserved; a stale expected version returns `VERSION_CONFLICT` with the current version and diff and never silently overwrites a same-field edit; a failed scan or transcode leaves the draft and already-successful assets intact, marks the asset `failed` or `quarantined` explicitly, and keeps publication blocked until a new attempt succeeds.
- **AC-EDU-CI-03 — Author previews and publishes:** Given The candidate revision declares a complete outline in which every advertised section and lesson exists, all required media are `playable`, one preview and at least one paid lesson exist, title, instrument, level, audience, price, tax class and refund-policy version are set, contributor and repertoire rights are attested, and no blocking moderation restriction applies, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Render learner projection; verify complete declared edition, price, preview, playable lessons, metadata, rights and moderation state, and (6) return Revision publishes atomically or returns typed failures; if the flow cannot complete, Any unmet gate returns `PUBLISH_GATE_FAILED` naming the failing item and the revision stays unpublished; media still processing returns `MEDIA_NOT_READY` and missing rights returns `RIGHTS_REQUIRED`; an external embed never satisfies the media or rights gate; publication commits revision, state, audit and outbox atomically or not at all, so no partial catalog projection appears.
- **AC-EDU-CI-04 — Adult learner discovers course:** Given The requester passes territory and age eligibility for the catalog projection and the course has a `published` revision with an eligible offer for that territory; only published allowlisted fields are readable, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Apply publication, territory, age and availability filters; show price, preview, author and read-only verified-credit projection, and (6) return Eligible catalog result or honest absence; if the flow cannot complete, An ineligible territory or age, or an unpublished course, yields honest absence or `COURSE_UNAVAILABLE` rather than a partial paid projection; a stale catalog projection exposes its freshness instead of presenting removed material as available; no failure path discloses drafts, buyer lists, paid media or learner progress.
- **AC-EDU-CI-05 — Adult learner buys course:** Given An authenticated adult buyer with no active entitlement for this course selects an `active` offer eligible in their territory, and checkout has frozen buyer, course, eligible revision, amount, currency, territory, tax class and refund-policy version before payment is initiated, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Freeze offer/tax/refund terms; reconcile hosted payment; idempotently grant product-scoped entitlement, and (6) return Paid entitlement or no grant/no charge; if the flow cannot complete, An existing entitlement returns `ALREADY_OWNED` before payment and opens the library; an offer or revision that changes mid-checkout fails before charge with no post-charge substitution; an unreconciled provider outcome stays `PAYMENT_PENDING`, grants nothing, and is never reported as no charge until provider state is known; a duplicate webhook or replay returns the original single purchase and entitlement.
- **AC-EDU-CI-06 — Buyer purchases course-plus-lessons:** Given An authenticated adult buyer selects a bundle whose course component and Shard 15 teacher or academy-scoped rate line are both currently valid, and payment reconciles exactly once before one application transaction attempts both grants, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) One checkout atomically grants a course entitlement and Shard 15 teacher/academy-scoped credit event, and (6) return Both grants commit or both fail; if the flow cannot complete, If either the course entitlement or the Shard 15 credit grant fails, the whole application transaction rolls back, the purchase stays unfulfilled and enters automated reconciliation or refund, and no half bundle or orphan credit exists; the surface reports known provider state rather than claiming nothing was charged.
- **AC-EDU-CI-07 — Entitled learner consumes course:** Given The learner holds an `active` entitlement with an eligible revision-access row for the requested revision and the target media is `playable`; playback is issued as a short-lived signed access that confers no further authority, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorize current entitlement/revision, stream media, save monotonic per-lesson progress and open preconfigured Shard 15 practice, and (6) return Resume state persists without completion pressure; if the flow cannot complete, A missing, revoked or refund-pending entitlement returns `ENTITLEMENT_REQUIRED` and playback stops while recorded progress is retained; unprocessed media returns `MEDIA_NOT_READY`; a stale concurrent device update cannot move the furthest confirmed position backward; network failure preserves confirmed progress and offers honest retry with no nag, shame or failure classification.
- **AC-EDU-CI-08 — Author updates or withdraws course:** Given The actor is the course owner acting on the current course version, or a moderator or rights reviewer acting under a scoped rights, safety or legal case; any new revision must satisfy the same publication predicate as the original, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Publish new immutable revision or delist future sales; preserve prior-buyer access except scoped rights/safety/legal takedown, and (6) return Catalog changes without arbitrary entitlement loss; if the flow cannot complete, Delisting stops new sales and discovery while preserving existing buyers' eligible access; a scoped removal restricts the smallest lawful revision, lesson, media or territory and shows prior buyers an honest unavailable state with a safe reason instead of silent disappearance; a stale course version returns `VERSION_CONFLICT`; no update retroactively changes frozen purchase terms.
- **AC-EDU-CI-09 — Buyer requests refund:** Given The requester owns the purchase, the purchase is `paid` and not already refunded, and the frozen refund-policy version from the purchase snapshot plus server-side authorized consumption evidence are both available for evaluation, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Evaluate frozen 14-day policy, material consumption under 20%, defect/misrepresentation evidence and mandatory-law overrides, and (6) return Refund revokes access; progress/practice facts remain private; if the flow cannot complete, A change-of-mind request outside 14 calendar days or above 20% material consumption returns `REFUND_INELIGIBLE` with the evaluated policy version, and the buyer may escalate verified defect, misrepresentation or mandatory-law override to review; the decision locks purchase and entitlement versions so concurrent playback fails after revocation; author diagnostics never decide eligibility.
- **AC-EDU-CI-10 — Author reviews course diagnostics:** Given The requester owns the course, the requested buckets are older than the configured delay, and each bucket's cohort meets the configured privacy threshold, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Produce delayed, thresholded aggregates for starts, lesson drop-off and returns; exclude named learner progress and musicianship claims, and (6) return Diagnostic report, never engagement target; if the flow cannot complete, A cohort below the privacy threshold withholds the bucket and states the withholding rather than exposing individuals; named learner exports, cross-course learner ranking and private-practice joins are refused outright; no degraded path substitutes an engagement target, skill claim or teacher-performance judgment for the withheld bucket.
- **AC-EDU-CI-11 — Future teacher creates exam goal:** Given Board support is enabled for the named board and territory through a reviewed registry entry with a sourced syllabus version, and the teacher holds authority over the learner's education record; at US consumer launch the registry is disabled and the surface is absent, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) If board support is enabled, pin board/instrument/grade/syllabus version and external session/deadline, and (6) return Component plan exists without synthetic equivalence; if the flow cannot complete, A disabled or unlisted board returns `BOARD_UNSUPPORTED` and the surface stays absent rather than becoming an empty or nagging setup prompt; no board or grade is normalized to a common level, so an unavailable syllabus cannot be substituted; a later syllabus revision leaves the existing goal pinned and requires an explicit audited teacher-initiated migration with a previewed component mapping.
- **AC-EDU-CI-12 — Teacher records exam result:** Given The recorder is the learner or an authorized teacher, and the entry declares issuer, board, subject, grade, date and provenance with an explicit `self_reported` or `issuer_verified` evidence state; profile display additionally requires the learner's Shard 02 visibility consent, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Record self-reported or third-party-evidenced result with issuer/provenance and consented Shard 02 projection, and (6) return Honest evidence state; no platform-issued credential; if the flow cannot complete, A missing issuer or provenance is rejected and no result is stored (this shard's closed error enum defines no entry-validation code; the typed code is unstated here); the platform never promotes `self_reported` to `issuer_verified` on its own, and issuer revocation or expiry supersedes the record with provenance rather than deleting it; without Shard 02 consent the result stays private, and no path substitutes a platform-issued credential.
- **AC-EDU-CI-13 — Future academy configures operations:** Given The `InstitutionGate` is `enabled` through approved post-consumer `/evolve-feature` evolution and the actor holds a current Shard 01 organization mandate; the launch value is `disabled` and no consumer-launch route depends on this flow, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Post-consumer gate resolves organization mandate, roster, terms, rates, rooms and academy-scoped liabilities, and (6) return Institution workspace exists only after evolution gate; if the flow cannot complete, While the gate is `disabled` or `design_only` every command returns `INSTITUTION_DISABLED` and no schema, workspace or authority is provisioned; a CMS or feature setting toggled without the evolution gate is denied by the domain gate; organization authority is never inferred from a domain name, email domain, login provider or admin role.
- **AC-EDU-CI-14 — Future teacher joins/leaves academy:** Given The institution gate is `enabled`, an explicit organization mandate with capabilities and effective dates exists, and the teacher consents; the teacher's personal identity, profile, credentials and private book remain outside the mandate's scope, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Join by mandate without transferring personal identity; preserve academy student/credit continuity and isolate private practice, and (6) return Roster changes without profile capture or data leakage; if the flow cannot complete, Without the gate or a valid mandate the change returns `INSTITUTION_DISABLED` or `NOT_AUTHORIZED` and the roster is unchanged; departure ends roster authority only and deletes neither the teacher's identity nor the academy's student and credit continuity; any read reaching a teacher's private students, learner practice diaries or unrelated course consumption is denied.
- **AC-EDU-CI-15 — User requests certificate/badge:** Given Any authenticated actor may reach this path; the shard states no state or authority precondition because no issuance aggregate, route, template or event exists, so the request is always evaluated as an unsupported capability rather than an authorization question, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Reject platform issuance and direct user to external evidence recording where applicable, and (6) return No artifact, score or credential-block contamination; if the flow cannot complete, The request returns a typed unsupported response and produces no artifact, score, badge or certificate in any role including platform administrator; projection schemas cannot join course completion into Shard 02 credential blocks, and no approved CMS block or content-type registry entry can manufacture credential authority.
- **AC-EDU-CI-16 — User submits therapy/clinical data:** Given Any authenticated submission reaching an education request schema is subject to purpose and schema controls before persistence; no health-purpose field, clinical schema, payer, diagnosis or claim contract exists to be authorized, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Purpose/schema controls reject health-purpose fields and route ordinary non-clinical tuition to Shard 15, and (6) return No PHI or clinical record enters storage, logs or analytics; if the flow cannot complete, A declared health-purpose field returns `PROHIBITED_HEALTH_DATA` and is rejected before persistence, logging or analytics; free text or an upload classified as likely clinical purpose is quarantined for a limited restricted-reviewer workflow without copying content into logs or analytics; ordinary non-clinical tuition in a care or community setting is routed to Shard 15 as a lesson or group class.

### Global Interaction Rules

- Course, revision, price offer, entitlement, lesson credit, progress, practice, exam evidence and institution mandate are distinct facts.
- Publication, purchase, refund, entitlement revocation and takedown use frozen policy versions, idempotency keys and immutable audit.
- Verified credits establish work provenance, not teaching quality; absence is never a negative signal.
- Course completion is descriptive. It cannot produce a badge, score, public rank, inferred skill or teacher-performance judgment.
- Configuration uses governed Shard 03 setting definitions with typed scope, approval, audit and fail-safe defaults. Settings cannot bypass age, rights, payment, authorization, privacy or prohibited-data invariants.

## Accessibility

- Course outline, editor, catalog, checkout status, player, transcript, progress, exam-component view and future academy grids are fully keyboard operable with visible focus and stable headings.
- Media requires captions/transcripts where speech conveys instruction; audio-only examples require equivalent labels/context. Player controls expose names, state, elapsed/total time, speed and captions without gesture-only operation.
- Upload/transcode/publish progress uses text status and resumable actions; errors identify the affected lesson without relying on color.
- Completion and progress avoid shame, streak pressure, confetti-only meaning, forced motion and comparative ranking.
- Exam readiness uses named components and text states rather than color or a single visual percentage.
- Timed payment/session actions warn before expiry and preserve safe input; reduced-motion and high-contrast preferences apply.
- Future academy tables provide linearized summaries, sortable headers and accessible conflict/error announcements before activation.

## Edge Cases

| Scenario | Required behavior |
|---|---|
| Upload/transcode fails repeatedly | Draft and successful assets remain; retry uses new attempt, quarantine is explicit, publication stays blocked. |
| Two contributors edit same field | Optimistic conflict with current version/diff; never silent overwrite. |
| Course changes during checkout | Purchase commits only frozen eligible offer/revision or fails before charge; no post-charge substitution. |
| Duplicate payment/webhook | One purchase and one entitlement; reconciliation is idempotent and auditable. |
| Bundle's lesson-credit grant fails | Whole application transaction rolls back and payment remains unfulfilled/refundable; no half bundle. |
| Buyer owns course already | Block before payment and open library; cannot create duplicate entitlement. |
| Course is delisted | Existing buyers retain eligible access; new sale/discovery stops. |
| Lesson removed after purchase | Prior-buyer revision remains reachable unless scoped legal/rights/safety removal requires honest unavailable state. |
| Refund races playback | Refund decision locks purchase/entitlement version; post-revocation access fails, recorded progress remains. |
| Two devices report progress | Furthest confirmed position wins; stale updates cannot move resume backward. |
| Learner abandons | Quiet resumability, no nag/shame or failure classification. |
| Author has fewer than privacy threshold learners | Diagnostics withhold sensitive buckets rather than exposing individuals. |
| Copyright complaint targets one lesson | Restrict affected media/lesson/territory first; preserve unrelated course material where lawful. |
| Board revises syllabus | Existing goal stays pinned; teacher may explicitly migrate with component mapping and audit. |
| Unsupported board or US launch | Feature is absent, not an empty/nagging setup surface. |
| Academy setting is toggled before evolution | Domain gate denies; a CMS/feature setting cannot provision schema or authority. |
| Certificate template is requested through CMS | Registry rejects unsupported content type; CMS cannot manufacture credential authority. |
| Therapy note hidden in ordinary text/upload | Purpose controls, DLP/moderation signal and reviewer workflow quarantine/reject without logging content. |
| Deletion intersects purchase/audit | Public/profile projections erase as required; financial/legal minimum and immutable audit follow retention policy; media access ends safely. |
