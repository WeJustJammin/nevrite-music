# Shard 08 — Credit reporting, exchange and disclosure

> **Architecture Source**: [2026-08-02-architecture-design.md](../2026-08-02-architecture-design.md)
> **Decomposition Source**: [decomposition-plan.md](decomposition-plan.md)
> **Document Type**: Feature domain
> **Status**: Complete — design and deepening approved under standing owner autonomy

## Overview

Shard 08 converts authorized Shard 07 contribution records into purpose-specific reports, portable files, DDEX RIN packages, gear-credit disclosures and structured AI-involvement statements. It never changes credit truth, provenance rung, rights, ownership, split, payment or union status. Every output is a versioned snapshot with explicit omissions, validation gaps, source versions and stale detection.

### Scope Reconciliation

| Check | Result |
|---|---|
| Source boundaries loaded | 4 |
| Source documents loaded | 4 |
| Child capabilities reconciled | 4 |
| Added or removed feature boundaries | 0 |
| Union reporting | Deferred; data capture remains reusable, but no filing/submission claim ships without approved US institutional/legal contract |
| Gear publication | Owner-selected opt-in; inherited credit confidentiality is a hard ceiling |
| AI disclosure | Voluntary platform capture; recipient-specific export/release requirements may block that destination, never ordinary credit capture |
| Split handling | Medium complexity; no deep-dive file required |

## Features

- **02.07 Union & Performer Session Reporting** — future US AFM/SAG-AFTRA-oriented report assembly from immutable session/credit facts, with human certification and no inferred membership.
- **02.08 Credit Export & DDEX RIN Emission** — frictionless complete portability, validation-aware RIN generation, embargo-safe scope, loss declarations, immutable emission snapshots and stale/re-emit workflow.
- **02.09 Gear ↔ Credit Linkage** — optional contribution-granular equipment references derived as a byproduct, inherited confidentiality and item-following discography.
- **02.10 AI Contribution Disclosure** — self-authored, versioned, structured AI-involvement entries as an orthogonal contribution axis with no platform detection or threshold.

### Delivery Phases

| Phase | Enabled boundary |
|---|---|
| Consumer launch | Complete own-credit portability export; structured AI disclosure capture/export; internal validation and stale-emission records |
| Later domain activation | DDEX RIN emission after identifier/taxonomy/recipient adapter gates; gear linkage after Shard 23 item identity; union report assembly after approved US forms |
| Explicitly disabled | Automated union submission, AI detection, platform-defined AI threshold, gear prompts in session capture and any output that leaks embargoed/confidential credits |

## Acceptance Criteria

- **AC-CXR-01 — Export own credit history:** Given Authenticated party with a current acting context selects an output kind and a scope it is authorized to see; the export is reachable directly by that party and is never a support-gated path; and the source Shard 07 projection resolves at an exact snapshot version rather than through unrestricted graph tables, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authenticated party selects authorized scope and machine-readable/human-readable formats; every visible own credit is included regardless of tier, and (6) return Immutable export snapshot plus manifest/hash generated; if the flow cannot complete, `SOURCE_STALE` where a source credit version moves during generation, so no mixed-version artifact is ever emitted and the party retries against the new snapshot; `ARTIFACT_GENERATION_FAILED` leaves the request `failed` with the selected scope preserved for idempotent retry, and a worker failure after a storage write quarantines the unreferenced blob rather than sealing a manifest over it. Own embargoed credits are included with their actual confidentiality state, and the artifact stays private and non-share-by-default.
- **AC-CXR-02 — Preflight RIN package:** Given The requester holds export authority over the selected scope, the exact DDEX profile version is loaded, and a named recipient profile with its disclosure requirements resolves at an effective version; preflight is read-only over the source and reads authorized Shard 07 projections only, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Generator validates party/work/recording identifiers, role mapping, credit tier, embargo, recipient profile and disclosure requirements without mutating source, and (6) return Gap list groups blocking, warning and lossy conditions; if the flow cannot complete, `PROFILE_UNAVAILABLE` where the DDEX or recipient profile version cannot be loaded, since no gap list is fabricated against a default profile. Unresolved identifiers, unresolved role mappings and confidentiality return as `blocking` gaps and representational loss as `lossy`, leaving the request `draft` rather than failing. A record the requester cannot see is absent from the gap list entirely, because a hidden record is never reported as an omission.
- **AC-CXR-03 — Generate RIN package:** Given A preflight has run against this scope, the user confirms the exact source snapshot, every `blocking` gap is resolved or its record excluded, and any low-tier inclusion is supplied as an explicit per-credit override; only authorized, non-confidential records enter the selection, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) User confirms exact snapshot and explicit low-tier overrides; only authorized, non-confidential records emit, and (6) return Package, validation report and source-version manifest sealed; if the flow cannot complete, `SOURCE_STALE` where the confirmed snapshot no longer matches, so nothing is emitted at mixed versions; `RECIPIENT_REQUIREMENT_UNMET` where a destination disclosure requirement is unsatisfied; `ARTIFACT_GENERATION_FAILED` leaves the artifact `failed` until an idempotent retry reseals the manifest. Representation the profile cannot carry emits an explicit loss declaration rather than flattening silently, and there is no bulk low-confidence shortcut — each override is per credit with a warning and an audit entry.
- **AC-CXR-04 — Review stale emission:** Given An active emission record exists for a prior artifact, and a credit amendment, retraction or AI-disclosure change has landed against one of its snapshotted credit versions; a score-only collusion demotion does not stale an emission and does not satisfy this precondition, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Amendment/retraction makes matching emission stale; exporter sees changed credits and may create a new package, and (6) return New emission supersedes internally; external acceptance remains recipient-owned; if the flow cannot complete, A re-emission creates a new immutable artifact linked to the prior emission and cannot claim recipient supersession unless the adapter returns delivery evidence, so a recipient rejection leaves the new artifact generated or emission-attempted and the prior external copy unclaimed. Where the recipient adapter is unavailable the emission remains internally superseded with no external-acceptance claim, and the exporter is notified rather than the artifact being silently patched.
- **AC-CXR-05 — Generate portability receipt:** Given A generated artifact exists whose manifest, checksum, source versions, omissions and degradation notes are already recorded, and the requester owns the export request that produced it, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) User receives format/version, scope, omissions, degradation notes, checksums and generated-at metadata, and (6) return Receipt remains downloadable with export audit; if the flow cannot complete, A receipt is never issued over an incomplete manifest: `ARTIFACT_GENERATION_FAILED` returns and the export is retried rather than a receipt asserting content it cannot verify. A download failure leaves a persistent accessible retry route, the receipt stays downloadable alongside the export audit, and an expired short-lived URL is re-issued without regenerating the artifact.
- **AC-CXR-06 — Prepare union session report:** Given An approved US union form profile is loaded at an effective version with its gate state permitting a draft, the eligible user holds reporting authority over the session, and the session and performer facts exist as captured immutable records; union membership, rates and classifications are human inputs and are never inferred into this precondition, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Eligible user maps captured facts to an approved US form profile, fills missing declarations and reviews every derived value, and (6) return Draft report only until feature/institution gate enabled; if the flow cannot complete, `PROFILE_UNAVAILABLE` where no approved form profile is effective, since no report may be drafted against an unapproved form. Missing declarations surface as fields for the human to fill and are never derived from session facts. The artifact stays `draft` while the feature or institution gate is disabled, and no submission path is reachable from this flow.
- **AC-CXR-07 — Certify union report:** Given A drafted report renders to an exact artifact with its source versions pinned; the human signer holds signing authority and has confirmed membership, jurisdiction, rates and fields; and the consequence disclosure has been shown and explicitly acknowledged before the signature is taken, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Human signer confirms membership, jurisdiction, rates/fields and consequence disclosure; platform never certifies correctness, and (6) return Signed report version and evidence retained; no silent submission; if the flow cannot complete, `VERSION_CONFLICT` or `SOURCE_STALE` where the rendered artifact or a source version moved between review and signature, so a signature is refused rather than bound to a different artifact. A profile or rate change leaves the existing report immutable and requires a new draft against the new profile before certification. Certification never implies submission: automated submission stays disabled until the provider and legal gate exists, and no submitted status is written without adapter delivery evidence.
- **AC-CXR-08 — Link gear to contribution:** Given The contribution credit already exists, because the link is a byproduct and never a session-close prompt; the actor is that credited party or a Producer whose mandate covers the contribution; and the target resolves to exactly one registered Shard 23 item version or saved chain, with the author and source method supplied, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Credited party/authorized Producer selects registered item or saved chain after contribution exists; no session-close prompt, and (6) return Optional link records source, author and inherited visibility; if the flow cannot complete, `VALIDATION_FAILED` on a session-level link, an unresolved item version, or a missing author or source method, and `FORBIDDEN` where the actor is neither the credited party nor a mandated Producer. The link inherits the source credit's confidentiality as a hard ceiling and can never widen it; where item identity is not yet available no link is created and the credit is left entirely unaffected.
- **AC-CXR-09 — Publish gear discography line:** Given The item owner has opted that item in to public display, and every link entering the projection has a source credit that is public and still visible at projection time; opt-in is per item and is never inherited from a credit's visibility or from a prior owner's choice, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Item owner chooses opt-in public display; projection includes only links whose source credit is public and still visible, and (6) return Viewer-safe item projection generated; if the flow cannot complete, A source credit that becomes embargoed or confidential purges its line within the Shard 07 restrictive-visibility SLA rather than rendering stale, and because the projection is derived only, that purge alters no credit and no link. A direct request for a purged line gets the `EMBARGOED_NOT_FOUND` behaviour, so no count, total or error reveals that a line was removed.
- **AC-CXR-10 — Transfer registered gear:** Given Ownership has already changed in Shard 23, which is the source of truth for this flow, and the credit links exist against the item version rather than against the prior owner, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Ownership changes in Shard 23; credit links remain with item while prior owner's private session access does not transfer, and (6) return New owner sees public/authorized item history only; if the flow cannot complete, Shard 08 never writes the ownership change and refuses any attempt with `FORBIDDEN`, so a failed or reversed Shard 23 transfer simply leaves the links where they were. The prior owner's private session access does not transfer and no re-derivation grants it. A projection rebuild failure leaves the previous authorized projection in place rather than exposing a wider set to the new owner.
- **AC-CXR-11 — Add AI involvement entry:** Given The actor is the contributor of the target contribution and is disclosing only their own involvement; the entry validates against the loaded `AIInvolvementKindV1` vocabulary version with a scope of whole or partial and optional bounded free-text fields. No threshold test and no binary AI label is a precondition, because neither exists in this shard, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Contributor describes only own contribution using versioned kind/scope/tool/model fields; no threshold question or binary “AI” label, and (6) return Immutable disclosure version linked to contribution; if the flow cannot complete, `FORBIDDEN` on any attempt to disclose for another contributor, and `VALIDATION_FAILED` on a kind outside the loaded vocabulary version or a free-text field over its character bound. A refused entry leaves the contribution with zero entries, which renders as not disclosed and never as a human-origin claim, and no detection attempt is made to fill the gap.
- **AC-CXR-12 — Amend/retract AI disclosure:** Given An active `ai_disclosure_version` exists that the acting contributor authored, the supersession carries a stated reason, and the expected version is supplied; only the original author has standing, so no admin, Producer or worker path satisfies this precondition, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Contributor supersedes own entry with reason; history remains and affected exports become stale, and (6) return New active version and audit event committed; if the flow cannot complete, `FORBIDDEN` for any actor other than the authoring contributor and `VERSION_CONFLICT` where the active version moved. The prior version is never deleted — it remains in the audit chain while only the new active version drives projections — and every export or emission carrying the superseded disclosure is marked stale for the exporter to regenerate at their own discretion.
- **AC-CXR-13 — Evaluate destination requirement:** Given A named destination policy version is effective with its source evidence recorded, and the structured disclosure for each in-scope contribution is readable; evaluation is applied by an export or release adapter at destination time and never at credit capture time, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Export/release adapter applies named recipient policy to structured disclosure; missing data is a gap, never proof of human origin, and (6) return Destination-specific pass/block/warning with policy version; if the flow cannot complete, `RECIPIENT_REQUIREMENT_UNMET` blocks that destination alone, leaving the core credit, the portability export and every other destination available and valid, and `PROFILE_UNAVAILABLE` where no policy version is effective blocks the destination rather than passing it by default. A field the destination requires and the disclosure does not carry is reported as a gap and never treated as proof of human origin, and the evaluation rewrites neither the disclosure nor the credit.
- **AC-CXR-14 — View disclosure:** Given The viewer is authorized to see the underlying contribution and the active `ai_disclosure_version` for it resolves; the provenance rung is fetched separately and is neither a precondition for nor an input to this projection, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized viewer sees factual entries and source; provenance rung remains separate and never warrants human-only performance, and (6) return Accessible disclosure projection rendered; if the flow cannot complete, `FORBIDDEN` where the viewer cannot see the underlying contribution, since the disclosure inherits that authorization and never widens it. A contribution with no entries renders explicitly as not disclosed with no human-origin badge and no inference drawn from absence, and a projection failure renders the disclosure unavailable rather than falling back to an empty set that would read as a disclosure of nothing.

### Global Interaction Rules

- Commands carry `actor_person_id`, `acting_party_id?`, `acting_context_version`, `idempotency_key`, `expected_version?`, `request_id` and exact source snapshot version.
- Output generation reads authorized Shard 07 projections, never direct unrestricted graph tables.
- Every generated artifact declares schema/profile version, source versions, omissions, validation outcome, degradation and checksum.
- Confidentiality is applied before selection, counts and artifact assembly. A missing hidden credit is not listed as omitted.
- Output status distinguishes `draft`, `validated`, `generated`, `emitted`, `stale`, `superseded` and `failed`; file creation is not external acceptance.

## Contracts

### Core Types and Errors

| Contract | Definition |
|---|---|
| `OutputKind` | `portability_json \| portability_csv \| portability_pdf \| ddex_rin \| union_report \| gear_discography \| disclosure_projection` |
| `ArtifactState` | `draft \| validating \| blocked \| generated \| emitted \| stale \| superseded \| failed` |
| `GapSeverity` | `blocking \| warning \| lossy` |
| `AIInvolvementKindV1` | `generation \| assistance \| modelling \| separation \| correction`; open/additive only through new vocabulary version |
| `StandardError` | `VALIDATION_FAILED, FORBIDDEN, ACTING_CONTEXT_STALE, VERSION_CONFLICT, IDEMPOTENCY_MISMATCH, SOURCE_STALE, EMBARGOED_NOT_FOUND, PROFILE_UNAVAILABLE, RECIPIENT_REQUIREMENT_UNMET, ARTIFACT_GENERATION_FAILED` |

### Export and Emission

| Contract | Invariant |
|---|---|
| `CreatePortabilityExport` | Includes all credits visible to requesting party, including imported/self-asserted/contested and embargoed own credits, with their actual states; never a support-gated path. |
| `PreflightRIN` | Uses exact DDEX/profile version; unresolved identifiers/roles and confidentiality are blocking; representational loss is explicit. |
| `GenerateRIN` | Low-tier credits excluded by default and listed as gaps; explicit per-credit override allowed with warning and audit. Provenance rung may be included as extension/receipt but DDEX loss remains declared. |
| `RecordEmission` | Snapshots recipient, timestamp, schema/profile, credit IDs and per-credit versions, package hash and delivery evidence. |
| `MarkEmissionStale` | Credit amendment, retraction or disclosure change stales matching active emissions; score-only collusion demotion does not. |
| `ReemitArtifact` | Creates a new immutable artifact linked to prior emission. It cannot claim recipient supersession unless adapter returns evidence. |

### Union, Gear and AI Disclosure

| Contract | Invariant |
|---|---|
| `BuildUnionReport` | US form profile maps session/performer facts only; union membership, rates, classifications and declarations require human input/confirmation. |
| `CertifyUnionReport` | Exact rendered artifact, signer authority, source versions and consequence disclosure are signed. Automated submission remains disabled until provider/legal gate. |
| `LinkGearCredit` | Link targets one contribution credit and one Shard 23 item/version; session-level link forbidden. Author and source method required. |
| `ProjectGearDiscography` | Public only when item owner opted in and source credit is public; confidentiality changes purge projection. Link follows item, not prior owner. |
| `RecordAIDisclosure` | Actor may disclose own contribution only. Zero or more structured entries; absence means “not disclosed,” never “human.” |
| `EvaluateDisclosurePolicy` | Applies named external policy/version without rewriting disclosure or credit; destination may block while core credit remains valid. |
| `RecordGearItemIdentity` / `RecordGearOwnershipTransfer` | Protected inbound commands, and the only way registered gear identity and ownership enter this shard (DEC-098). Shard 23 calls them, each carrying the registered item and version, the current holder, an effective time, an expected version and an idempotency key. This shard materialises the identity `LinkGearCredit` resolves against and the ownership change `ProjectGearDiscography` re-derives from; it never writes canonical identity or an ownership change itself and refuses any such attempt with `FORBIDDEN`. Where item identity has not been recorded no link is created and the credit is left entirely unaffected. |

| `output_gap` | Request, source object/version, code, severity, safe message, remediation route; hidden records never represented. |

Entries are JSON objects inside `ai_disclosure_version.entries`.
