# Shard 38 — Promotion and marketing

**Status:** Complete
**Surface:** Responsive web/PWA
**Source:** [Architecture design](../2026-08-02-architecture-design.md) · [Decomposition plan](decomposition-plan.md)

## Overview

Shard 38 owns campaign planning, pitch assembly and history, governed target references, private relationship CRM, smart links, pre-save authorization, honest campaign attribution, paid-promotion planning, creator-seeding campaign briefs, payola controls, optional social publishing, coverage verification, event/tour marketing and versioned campaign EPKs. It consumes release truth from [[specs/ia/22-release-distribution|Shard 22]], fan consent boundaries from [[specs/ia/37-fanbase-direct-to-fan|Shard 37]], ticket conversion facts from [[specs/ia/35-ticket-products-sales|Shard 35]], creator engagements from [[specs/ia/14-services-marketplace|Shard 14]] and platform delivery/time-lock primitives from [[specs/ia/00-infrastructure|Shard 00]].

### Scope Reconciliation

| Item | Result |
|---|---|
| In-scope source documents | 41 |
| Child capabilities | 27 across 21.01–21.09 |
| Campaign boundary | One typed campaign root supports release, tour and event campaigns; crowdfunding and sync remain separate consumers/evolution paths |
| Outreach boundary | Assemble, alarm, archive and optionally send through verified entity-owned identity; never pretend to submit DSP editorial forms |
| Directory boundary | Curated/licensed/consented professional references only; no scraping, no gatekeeper accounts and no export of platform directory data |
| CRM boundary | Entity-owned structured contact history with unconditional export; free-text third-party notes remain disabled under B5 |
| Attribution boundary | First-party clicks are measured; downstream DSP behavior is correlation; on-platform ticket conversion is observed but not multi-touch credited |
| Paid promotion boundary | Planner only; no ad-account integration, agency operation, fan-data audience export or third-party advertising/data sale |
| Placement boundary | Guaranteed placement and payment-for-airplay are prohibited; paid consideration/brokerage remains disabled pending counsel and provider-terms review |
| Publishing boundary | Calendar is durable; provider posting is capability-gated with manual fallback and never required for planning |
| Public artifact boundary | Coverage strength derives from artifact class/retrievability; EPK displays strength, not pitch provenance |

### Architecture Decisions

| Area | Locked decision |
|---|---|
| Campaign model | `campaign.kind` is `release`, `tour` or `event`, with typed anchor and rule pack. Derived deadlines name rule provenance and fail closed when rule data is unavailable. |
| Planning | Beats are offset-anchored unless explicitly pinned. Asset gates derive from dependencies and distinguish validated, externally observed and self-attested readiness. |
| Date cascade | Hypothetical preview is non-mutating. Commit requires source-object date authority and step-up authentication; escaped external actions become drafts/tasks, never auto-sends. |
| DSP editorial | Platform assembles verified metadata, warns and archives; artist completes submission in the DSP/distributor surface. No inferred submission or outcome-success claim. |
| Outreach channels | Press, blog and podcast share one direct-pitch shape. Specialist-radio outreach uses externally anchored dates and manual outcomes; commercial-radio integration/spin monitoring is deferred. |
| Outbound identity | No shared WeJammin marketing sender. Platform send requires a verified entity-owned domain/identity and open reputation gate; otherwise user exports/copies and sends externally. |
| Pitch protection | Global target opt-out works without account and fails closed. Atomic per-target and per-sender budgets are versioned platform policy; payment never buys additional budget. |
| Pitch quality | No merge-field mass personalization. Quality warnings may be overridden only with friction and a separate bounded override budget. Silence becomes a terminal outcome after policy window. |
| Embargo/exclusive | Embargo and premiere promises are structural constraints with scope, counterparties and wall-clock lift. Conflicting exclusives block; lift is irreversible; notices reveal only what each actor needs. |
| Target directory | Sources are licensed, editorial or target-consented professional submissions with provenance, confidence and staleness. No scraped contacts. Small-n response data is absent while B2 is closed. |
| Private CRM | Pitching creates entity-owned contacts automatically. Only structured facts/outcomes ship; no free-text notes under B5. Private contacts survive directory merge/removal and export in open format. |
| Smart links | Destinations derive from release/event facts; manual destinations are labeled unmanaged. Remembered fan preference beats device inference. Pages perform no audience capture. |
| Pre-save | Narrow provider authorization per DSP/release, visible to fan, revocable and expiring. Authorization never becomes marketing consent. Failures are explicit and netted from reports. |
| Attribution | No fingerprinting or cross-site tracking. Exact first-party click and same-session on-platform conversion may be measured; DSP streams and ad-platform model outputs retain correlation/model labels. |
| Truth labels | Every report value is typed as measured, observed conversion/reversal, provider-confirmed, provider-modelled, correlated external or self-attested; consumers cannot strengthen the label. |
| Link retirement | Hard delete is unavailable. Link can remain, redirect to canonical home or show a retired state; default is canonical redirect. Trafficked retired links raise policy review. |
| Paid ads | WeJammin supplies budget/channel/creative plan and imports user-provided reports with provenance. It does not connect ad accounts, spend money or build audiences from fan data. |
| Creator seeding | Shard 38 owns disclosure-locked brief, campaign rights and post-publication verification; [[specs/ia/14-services-marketplace|Shard 14]] owns engagement and payment. Amplification rights are explicit. |
| Payola | Classifier is intent-based, immutable and fail-closed. Guaranteed placement, pay-for-airplay and consideration-shaped unclassifiable offers are blocked. No platform-sponsored ranking at this stage. |
| Social publishing | Optional provider adapters publish only when provider/app-review capabilities are current. Disconnect is detected before schedule; failures appear on calendar; manual export remains complete fallback. |
| Coverage | Manual-first capture plus on-demand link verification. Monitoring may suggest only from licensed/permitted sources. No page-content archive without rights. Verification is `verified`, `verified_at_timestamp` or `claimed`. |
| Event marketing | Per-date readiness, staggered on-sale and tagged links derive from first-party show/ticket facts. Soft-seat detection is advisory, evidence-based and never auto-spends. |
| EPK | Campaign-scoped immutable versions auto-populate from canonical credits/assets. Claimed credit remains labeled. Share uses revocable recipient-scoped links; old versions resolve to retained/expired state, never accidental 404. |
| Configuration | Rule packs, deadlines, caps, confidence decay, attribution windows, retention, thresholds, schedule limits and capability flags are typed versioned settings, never hardcoded logic. |

Every mutation includes acting-party mandate, expected revision, client idempotency key and audit correlation. Public link, opt-out and EPK endpoints are rate-limited and response-invariant where existence is sensitive. External-provider outcomes include `accepted`, `confirmed`, `failed` and `unknown_reconciling`; timeout is never transformed into success.

## Data Models

| Entity | Key relationships and constraints |
|---|---|
| `promotion_campaign` | Entity-owned typed root linked to one release/tour/event anchor; immutable kind after activation |
| `campaign_rule_pack` / `rule_entry` | Versioned provider/channel rules with source, verified-at, expiry and hard/soft deadline semantics |
| `campaign_grid_item` | Derived or manual item, offset/pin mode, deadline class, provenance and readiness dependency |
| `campaign_beat` / `beat_revision` | Typed content intent, channel renderings, source object, schedule and immutable published revision |
| `cascade_preview` / `escaped_action` | Proposed date graph, source revisions and drafted external follow-up tasks |
| `embargo_constraint` / `exclusive_claim` | Scoped wall-clock reveal and unique active premiere promise per asset/territory/channel window |
| `pitch` / `pitch_revision` | Durable cross-campaign target interaction with ask, content and immutable send/export revision |
| `pitch_budget_lease` / `target_suppression` | Atomic quota allocation and global target opt-out keyed by protected contact hash |

## Edge Cases

- Rule pack expires before campaign save: existing plan remains viewable with stale warning, but new derived deadlines and anchor commits fail closed.
- Two co-managers edit one beat: expected revision rejects later stale save; user compares revisions instead of receiving a silent field merge.
- Release/tour anchor changes twice: second preview starts from committed first version; escaped tasks dedupe by affected external action.
- Provider requirement changes after DSP pitch assembly: readiness invalidates and shows changed rule; platform never claims prior external submission became invalid.
- Target opts out while budget lease exists: dispatch rechecks suppression before provider handoff, releases lease and records no spend.
- Two senders race for final global target slot: one atomic lease wins; losing draft remains intact and consumes no sender budget.
- Entity domain loses verification before scheduled send: send blocks and becomes exportable; no fallback to shared WeJammin identity.
- Directory target merges or requests removal: private CRM retains entity-owned structured history through alias/tombstone without exposing removed directory data.
- Contact erasure request intersects entity CRM: B5/legal retention policy routes scoped review; no unsupported guarantee or silent deletion is made.
- Smart-link destination rots: landing page removes dead action, alerts owner and keeps durable URL/click history.
- Pre-save release date moves/cancels: grant status updates; fan sees change and expired/cancelled authorization is revoked. No email unless separately authorized for that service purpose.
- Provider accepts pre-save but callback times out: state becomes reconciling; retry uses same idempotency key and report excludes unknown from success.
- Attribution session spans multiple campaign links: report shows each observed click and the configured eligible conversion link without claiming causal credit.
- Refund occurs after ticket conversion report: conversion and cost-per-net-ticket projection reverse additively; original observation remains.
- Ad report imports modelled conversions as measured: schema rejects unlabeled row; user must select provider/model provenance.
- Creator removes seeded post after payout: scheduled verification records failure for Shard 14 case; Shard 38 does not claw money itself.
- DSP terms change while promotion offer active: cached verdict invalidates; continuation blocks pending reclassification and contract/counsel policy decides committed spend.
- Social provider revokes scope near due time: preflight blocks, calendar shows failure/manual package and no unsupported retry storm starts.
- Coverage URL content changes: prior observation remains `verified_at_timestamp`; it does not retain fixed `verified` strength.
- Monitoring false positive: suggestion can be dismissed and never becomes coverage or public badge automatically.
- Venue leaks embargo off-platform: platform records observed breach and propagation evidence but never represents notice as a binding contract unless source shard says so.
- Soft-date sales data is sparse, stale or mostly external: diagnosis withheld or click-only, never confident spend recommendation.
- EPK link is forwarded: recipient-scoped policy can show forwarding warning, expire/revoke access and identify link label; platform makes no impossible non-copying guarantee.
- Old EPK version contains withdrawn asset: version resolves to explicit access-withdrawn state while unaffected metadata remains; accidental 404 is prohibited.
