# Shard 17 — Real-time jamming and remote sessions

**Status:** Complete
**Surface:** Web/PWA orchestration plus separately admitted specialized audio runtime
**Source:** [Architecture design](../2026-08-02-architecture-design.md) · [Decomposition plan](decomposition-plan.md)

## Overview

Shard 17 owns remote-session intent, pairwise latency evidence, playability, authenticated monitoring, talkback/cue policy, local-first capture, non-destructive alignment, attendance observations, preflight, overdub and interruption continuity. It is a Phase-2 train: the consumer web stack may orchestrate sessions, but it cannot claim musical-grade transport, capture or device control without a separately approved specialized runtime, provider, cost and security gate.

### Scope Reconciliation

| Reconciliation item | Result |
|---|---|
| In-scope source documents loaded | 30 |
| Child capabilities reconciled | 20 |
| Top-level capabilities | Latency/playability; peer discovery; monitoring; talkback/cues; capture/recall; preflight; overdub; continuity |
| Consumer launch | No real-time audio, remote monitoring or specialized runtime dependency |
| Phase-2 entry | Approved runtime/provider, measured thresholds, relay/egress budget, privacy/counsel profile and infrastructure verification |
| Minor boundary | Minor participation, UGC audio, paid remote work and recording remain disabled until the indivisible minor gate |

### Architecture Decisions

| Area | Locked decision |
|---|---|
| Runtime boundary | Astro/Hono/Supabase own orchestration, authority, durable facts and governed files; an admitted specialized runtime owns device/audio/transport operations. |
| Timing model | Live takes use one declared conductor/reference elected before take start. It cannot change mid-take; loss ends the live take rather than silently promoting. |
| Playability | Pairwise verdict includes BPM ceiling, instrument scope, confidence, freshness and evidence basis. Unknown is first-class; worst pair bounds a room. |
| Thresholds | Versioned performance-policy settings hold researched/validated tables; consumers cannot invent thresholds. Red informs and offers overdub, never blocks. |
| Discovery privacy | Opt-in coarse market/metro discovery only. Precise home location is never published; pairwise probing requires mutual session intent. |
| Monitoring | Identity-bound, expiring session grants; no anonymous listener. Revocation cuts in-flight stream. Performer objection is visible/audited and advisory by default. |
| Capture | Local-first; network stream is never master. Network loss never stops durable local recording. |
| Alignment | Offset/drift model remains beside immutable audio; measured residual is shown, never a confidence score or baked edit. |
| Overdub | First-class, globally usable mode. Versioned bed package is reference; provenance grade distinguishes delivered file from observed performance. |
| Provenance | Attendance records observed authenticated endpoint/audio windows, never automatic credit or a claim that a human played. |
| Commerce | Shard 14/05 owns paid terms. This shard records preflight, latency, hold, interruption, delivery and withholding facts without inventing billing outcomes. |

## Acceptance Criteria

- **AC-RTS-01 — Producer creates remote session intent:** Given The actor holds Shard 09 project and acting-party authority, every named participant is an adult, and the intent declares mode, schedule, recording disclosure with an approved jurisdictional basis, and the current runtime-admission and performance-policy versions, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Resolve project/acting authority, mode, participants, schedule, recording disclosure, policy/runtime versions, and (6) return Private intent created; no transport yet; if the flow cannot complete, A minor participant returns `MINOR_DISABLED` and no intent is created; a recording mode without an approved jurisdictional basis returns `DISCLOSURE_REQUIRED` and the session cannot connect in recording mode rather than silently downgrading disclosure; missing project or party authority returns `NOT_AUTHORIZED`; a refusal provisions no transport, relay or paid capacity.
- **AC-RTS-02 — Participant runs scheduled preflight:** Given The participant is named on the session intent and an admitted specialized runtime for the declared mode holds a short-lived session, endpoint and purpose credential; preflight runs ahead of the scheduled start and records facts about that endpoint only, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Specialized runtime checks authorized device, storage, sample rate, local path, network and mode capabilities, and (6) return Timestamped pass/fail/not-run/stale facts with fixes; if the flow cannot complete, No admitted runtime returns `RUNTIME_DISABLED` and an incompatible version returns `RUNTIME_INCOMPATIBLE`, each recorded as an honest `not_run` fact rather than a pass; a busy device returns `DEVICE_BUSY` and insufficient headroom returns `DISK_INSUFFICIENT` with its specific remediation; results past the freshness window read as `stale` and a dependent flow returns `PREFLIGHT_STALE`; preflight never blocks and never guarantees the future.
- **AC-RTS-03 — Participants measure pairwise path:** Given Both endpoints hold mutual session intent or explicit consent to probe, an admitted runtime is available at each end, and exchanges are bounded in count and rate under the current versioned performance policy, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Exchange bounded probes through admitted runtime; report directional estimate interval, app/device/network decomposition, confidence and freshness, and (6) return Honest measured/unknown evidence; if the flow cannot complete, Absent mutual intent or consent the probe returns `NOT_AUTHORIZED` and stores no observation; asymmetry or clock ambiguity yields an uncertainty interval or `PATH_UNKNOWN` and never converts RTT/2 into directional certainty; a measurement failure is recorded as unknown with remediation and an overdub route, never as green, zero or a false precise radius; raw path observations expire at the approved bounded retention.
- **AC-RTS-04 — User discovers possible partners:** Given The searcher and every candidate have opted into coarse metro or market discovery, the query supplies region, role or instrument and availability, and any verdict shown is a centrally owned pair verdict that is fresh and authorized for this requester, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Search opt-in coarse region/instrument/availability; use centrally owned pair verdict where fresh and authorized, and (6) return Candidates shown without precise location guarantee; if the flow cannot complete, A verdict-service outage fails open by listing candidates with playability hidden or explicitly stale rather than fabricating a verdict; no result exposes exact coordinates, address, IP or route history, and query precision, rate limits and authorization defeat binary-search location inference; an empty pool is stated honestly and never widened by relaxing the privacy projection.
- **AC-RTS-05 — Participant joins room:** Given The joiner is an authenticated adult human named on the intent with a current acting party and grants, has been shown the recording state before connection, and holds an admitted runtime capability for the session mode, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authenticate human, acting party, grants, recording disclosure and runtime capability before connecting, and (6) return Named roster entry or typed denial; if the flow cannot complete, A forwarded link without login and an identity-bound session grant is denied with no anonymous route; a missing or mismatched capability returns `RUNTIME_DISABLED` or `RUNTIME_INCOMPATIBLE`; undisclosed recording returns `DISCLOSURE_REQUIRED` and a minor returns `MINOR_DISABLED`; a room block or restriction stops admission and new grants, and every denial is typed and creates no roster entry.
- **AC-RTS-06 — Producer starts live take:** Given One conductor and reference is elected before take start, the room is at the expected version with no take already `rolling`, every recording endpoint has proven durable local storage, and cue, talkback, capture policy and the transport clock epoch are frozen, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Freeze conductor, timing model, participants, cue/talkback/capture policy and transport clock epoch, and (6) return Take rolls only when every recording endpoint is durable; if the flow cannot complete, A missing or unelected conductor returns `CONDUCTOR_REQUIRED`; an endpoint that cannot prove durable local storage returns `DURABLE_CAPTURE_UNAVAILABLE` or `DISK_INSUFFICIENT` and capture does not start there, with no silent best-effort recorder; a take already rolling returns `TAKE_STATE_CONFLICT`; the conductor and timing model cannot change within the epoch, so loss ends the take instead of promoting silently.
- **AC-RTS-07 — Performer adjusts cue:** Given The actor is the performer whose own cue mix is being changed and is present in the session, the self-monitoring path is local, and any monitoring profile is written only on an explicit save, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Mix authorized sources locally; self-monitor locally; explicit profile save only, and (6) return Performer-owned cue state; no producer override; if the flow cannot complete, A producer or any other role attempting to override this performer's cue returns `NOT_AUTHORIZED` and the mix is unchanged; a source the performer is not authorized to hear is excluded rather than silently muted; a profile whose source-role mapping cannot be resolved lists the unmapped entries instead of silently approximating them; unsaved changes remain session-local.
- **AC-RTS-08 — Producer uses talkback:** Given The actor holds producer or an equivalently granted talkback capability in this session and the talkback channel is structurally excluded ahead of the capture tap; momentary press-and-hold is the default and latch is conspicuous and explicit, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Route capture-excluded channel; momentary default, visible latch, transient ducking over cue, and (6) return Reachable performers without recorded talkback audio; if the flow cannot complete, A ducking failure never mutes talkback speech and ducking overlays but never mutates the cue; a stuck latch shows a persistent live indicator and offers an emergency release; a talkback path that cannot prove capture exclusion is refused rather than opened, so talkback audio never enters a capture asset or master under any failure.
- **AC-RTS-09 — Producer admits monitor listener:** Given The actor is the producer or session owner, the invitee is an authenticated identity, and the grant declares listen and comment capabilities plus a mandatory expiry window bound to this session; performers see the named presence and their objections are recorded, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Grant identity-bound role/window/quality/comment capabilities; notify performers and record objections, and (6) return Visible expiring roster or denied access; if the flow cannot complete, Link possession without login and an identity-bound grant returns `LISTENER_GRANT_REQUIRED` and no anonymous stream exists; revocation closes in-flight transport immediately; a listener authorization outage fails closed and stops the stream while roster and history remain; a recorded performer objection is visible, immutable and advisory, resolved by the producer rather than auto-removing the listener.
- **AC-RTS-10 — Listener records timestamped note:** Given The note author holds a separate comment capability on a current unexpired listener grant, the take is `rolling` or has just ended, and a point anchor is used only where delay compensation is bounded, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Stamp against delay-compensated position/range; queue until take end; transfer durable ownership to Shard 09/Projects, and (6) return Note appears after take under explicit comment grant; if the flow cannot complete, A listen-only grant returns `COMMENT_GRANT_REQUIRED` and no note is created; an unknown or unbounded delay anchors the note to an explicit time range instead of a false point; notes queue while rolling and never interrupt the take; a discarded take removes the orphan note projection once Shard 09 owns the durable annotation lifecycle.
- **AC-RTS-11 — Participant disconnects/rejoins:** Given The participant already holds an attendance row and a rolling local capture on this endpoint, and reconnection re-authenticates the same human and acting party against the same session and transport epoch, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Keep local capture rolling; record named gap; preserve cue/profile; re-auth/re-sync before stream resumes, and (6) return One attendance with gap segments; if the flow cannot complete, Local capture continues throughout and network loss never stops recording; the gap is recorded as named fragments on the one attendance row rather than a duplicate contributor; a failed re-authentication leaves the participant outside the room with the local file intact; a scheduled end passing while disconnected prompts at plus thirty minutes and never automatically destroys work.
- **AC-RTS-12 — Conductor/producer drops:** Given A live take is `rolling` under an elected conductor inside a transport epoch, and any deputy powers were predeclared before the loss occurred, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) End current live take on conductor loss; predeclared deputy may manage room after take; local files finalize safely, and (6) return No silent timing or authority succession; if the flow cannot complete, Conductor loss ends and finalizes the current take rather than promoting a successor silently, and a new conductor requires explicit election that starts a new epoch and take; producer loss alone does not stop endpoint recording and, without delegated authority, no new take starts; a deputy exercises only predeclared room powers and gains no commerce or rights authority.
- **AC-RTS-13 — Producer stops/finalizes take:** Given The take is `rolling` or `interrupted`, the actor holds take control, and the specialized runtime holds the local files; finalization is uninterruptible once begun and must yield a playable file, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Specialized runtime finalizes one file per take/endpoint, latches signal/clip facts and creates upload state, and (6) return Playable local files even before upload; if the flow cannot complete, A take outside a finalizable state returns `TAKE_STATE_CONFLICT`; a runtime crash recovers the local journal and chunks where integrity proves and otherwise reports a loud `lost` or `partial` state rather than fabricating success; storage nearing exhaustion warns in remaining minutes and permits a deliberate stop and finalize without silently reducing fidelity.
- **AC-RTS-14 — Participant uploads/withholds/discards:** Given The actor owns this endpoint capture asset, the take is finalized, and no live room is currently active on that endpoint; upload is the participant's choice and the platform never compels it, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Pause uploads during live room; resume immutable chunks afterward; distinguish pending/uploaded/withheld/discarded/lost, and (6) return Asset state is explicit and attributable; if the flow cannot complete, An interrupted upload resumes from provider-confirmed immutable chunks at the next authorized open with bounded backoff and reads `UPLOAD_INCOMPLETE` until confirmed, never being silently abandoned; a declined asset records a visible `withheld` state distinct from `discarded` and `lost` and attributed to the participant; attendance seals independently and the commerce or dispute layer decides consequence.
- **AC-RTS-15 — System aligns uploaded tracks:** Given The alignment method and reference were committed at preflight, at least one uploaded track and its reference are available, and nominal sample-rate reconciliation precedes offset and drift estimation, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Validate committed method/reference; estimate offset/drift at multiple anchors; save non-destructive model and residual, and (6) return Aligned, unaligned or partial tracks; audio preserved; if the flow cannot complete, A missing or unusable reference returns `ALIGNMENT_UNAVAILABLE`, keeps the original downloadable and marks the track unaligned; zero placement and baked destructive correction are forbidden; a re-run preserves manual nudge and does not move placed tracks unless a late reference triggers an announced re-alignment; interruption fragments align independently and preserve their gaps.
- **AC-RTS-16 — Participants close session record:** Given The session has ended, transport-clock segments, gaps and audible seconds exist for this participant, and the participant completes their own observed row with role and instrument drawn from the controlled vocabulary inside the 24-hour window, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) One composed close flow presents own observed rows and declared role/instrument; seal after 24h, and (6) return Immutable observation; Shard 02 decides credit meaning; if the flow cannot complete, An unconfirmed row seals at session end plus 24 hours as an observed record labelled self-attested rather than being lost; endpoint timestamps cannot author duration against the transport clock; a request for another participant's audible-second detail is denied and the producer receives only a purpose-limited summary; no failure path converts the observation into credit, which Shard 02 alone evaluates.
- **AC-RTS-17 — Producer creates overdub request:** Given The actor holds Shard 09 project authority for this round and supplies an immutable bounce, tempo and bar map, two-bar count-in, markers, brief, fidelity and version; the observed-attendance slot is optional and chosen before any pass, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Freeze bed package, round brief, fidelity, version, deadline wrapper and optional observed-attendance slot, and (6) return Performer receives immutable reference package; if the flow cannot complete, An incomplete bed package is refused before the round is published so no performer receives a partial reference; a delivered package cannot be recalled, so recipient, version, fidelity and time are recorded instead; a new bed version supplies a section and bar-map diff rather than mutating the in-flight bed.
- **AC-RTS-18 — Performer submits overdub passes:** Given The performer is the named recipient of a current overdub request, holds an authorized bed version, has passed overdub preflight for storage, sample rate, monitoring path, bed stamp and local calibration, and has measured local round-trip latency with its uncertainty, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Measure local round-trip, record/check passes, choose keepers, resumably deliver against bed version, and (6) return Delivery-grade or observed-playing evidence with residual; if the flow cannot complete, A pass recorded against a superseded bed returns `BED_VERSION_CONFLICT` yet remains deliverable against the old version under a visible superseded and bar-map label; local checks for silence, clipping, bleed and sample-rate mismatch surface while the performer can still fix them; an unattended pass records `delivered_file` provenance and never claims `observed_endpoint_audio`; no failure path judges feel or quantizes the performance.

| RTS-16 | Participants close session record | The session has ended, transport-clock segments, gaps and audible seconds exist for this participant, and the participant completes their own observed row with role and instrument drawn from the controlled vocabulary inside the 24-hour window. | One composed close flow presents own observed rows and declared role/instrument; seal after 24h. | Immutable observation; Shard 02 decides credit meaning. | An unconfirmed row seals at session end plus 24 hours as an observed record labelled self-attested rather than being lost; endpoint timestamps cannot author duration against the transport clock; a request for another participant's audible-second detail is denied and the producer receives only a purpose-limited summary; no failure path converts the observation into credit, which Shard 02 alone evaluates. |
| RTS-17 | Producer creates overdub request | The actor holds Shard 09 project authority for this round and supplies an immutable bounce, tempo and bar map, two-bar count-in, markers, brief, fidelity and version; the observed-attendance slot is optional and chosen before any pass. | Freeze bed package, round brief, fidelity, version, deadline wrapper and optional observed-attendance slot. | Performer receives immutable reference package. | An incomplete bed package is refused before the round is published so no performer receives a partial reference; a delivered package cannot be recalled, so recipient, version, fidelity and time are recorded instead; a new bed version supplies a section and bar-map diff rather than mutating the in-flight bed. |
| RTS-18 | Performer submits overdub passes | The performer is the named recipient of a current overdub request, holds an authorized bed version, has passed overdub preflight for storage, sample rate, monitoring path, bed stamp and local calibration, and has measured local round-trip latency with its uncertainty. | Measure local round-trip, record/check passes, choose keepers, resumably deliver against bed version. | Delivery-grade or observed-playing evidence with residual. | A pass recorded against a superseded bed returns `BED_VERSION_CONFLICT` yet remains deliverable against the old version under a visible superseded and bar-map label; local checks for silence, clipping, bleed and sample-rate mismatch surface while the performer can still fix them; an unattended pass records `delivered_file` provenance and never claims `observed_endpoint_audio`; no failure path judges feel or quantizes the performance. |

### Global Interaction Rules

- The normal-web monthly p95 `<2s` SLO is not an audio-latency promise. Every live/audio route declares its own transport and device budget.
- No paid relay, specialized runtime, TURN/media provider or egress commitment is provisioned before the Phase-2 setup/evolution cost gate.
- Browser and Supabase Realtime presence are coordination hints, never musical transport, transport clock, durable attendance or capture authority.
- Every participant is an authenticated human. Acting as a band/organization is recorded separately; shared credentials never establish person-to-track proof.
- Session recording state is disclosed before connection. Jurisdictions requiring a stronger basis remain blocked by counsel policy rather than silently recording.
- Captured facts remain distinct from credit, contract fault, payment, aesthetic quality and musicianship.

## Accessibility

- All orchestration, preflight, roster, cue, talkback, transport, upload, alignment and overdub controls are keyboard operable with visible focus and stable labels.
- Rolling/not-rolling, muted/live talkback, listener presence, conductor, disconnection, recording and degraded-quality states use persistent text/icon/state announcements, never color alone.
- Screen-reader live regions announce only high-priority state transitions; meters expose bounded textual summaries without flooding.
- Momentary talkback has keyboard press-and-hold plus accessible latch alternative with unmissable state and explicit release.
- Cue controls expose source-relative labels, value and reset; profile mapping failures are listed, never silently approximated.
- Network/playability expresses BPM, latency interval, freshness and confidence in plain language; unknown/degraded states remain distinct.
- Reconnect restores focus/context and announces “still recording” before secondary messages.
- Audio-only collaboration cannot be the sole access path for critical consent, warnings, notes or session control; equivalent text UI exists.

## Edge Cases

| Scenario | Required behavior |
|---|---|
| Specialized runtime/provider unavailable | Live/monitor disabled honestly; intents and overdub planning remain; no browser fallback claims musical grade. |
| Path cannot be measured | Unknown with remediation/overdub; never green, zero or false precise radius. |
| Discovery verdict service unavailable | Candidate discovery fails open with playability hidden/stale; room admission/preflight remains honest. |
| Multi-player one bad pair | Worst pair bounds room verdict; no averaging. |
| Conductor drops mid-take | Current take ends/finalizes; no silent succession; deputy/conductor election starts a new epoch/take. |
| Producer drops but conductor remains | Live take may finish; local capture continues; deputy only exercises predeclared room powers. |
| Endpoint loses network | Local capture continues; one take gains gap fragments; reconnect re-auths and restores cue/profile. |
| Disk durability unavailable | Capture cannot start on that endpoint; no silent best-effort recorder. |
| Upload interrupted for days | Resume verified chunks on next authorized open; state remains pending/withheld/lost, never silently abandoned. |
| Participant declines upload | Withheld is visible; attendance fact seals independently; commerce/dispute layer decides consequence. |
| Talkback latch stuck or ducking fails | Persistent live indicator and emergency release; talkback remains audible and never enters capture. |
| Listener link forwarded | Login plus identity/session grant required; no anonymous stream; revoke disconnects current socket. |
| Note delay unknown | Anchor to explicit time range; never false point precision. |
| Alignment fails | Preserve/download original; mark unaligned; never place at zero or bake destructive correction. |
| Bed changes during pass | In-flight bed immutable; deliver against old version with visible superseded/bar-map label. |
| Shared acting entity joins | Each human authenticates separately; acting party recorded, person-to-endpoint observation remains individual. |
| Recording basis not approved in jurisdiction | Session cannot connect in recording mode; policy does not silently downgrade disclosure. |
| Scheduled end passes while disconnected | Local capture continues; prompt at +30 minutes, never automatic destructive stop. |
