## Overview

Shard 09 is the private working record for songs, releases, project membership, creative documents, rosters, access, immutable audio lineage, review, sessions, mix/master workflow and delivery readiness. It owns workspace containers and pointers, not credits, rights, splits, payments, releases or distribution truth. V1 is web/PWA-first: manual uploads, session/roster prefill and in-app/web-push capture operate without a local DAW agent.

## Features

- **07.01 Song, Release & Production Board** — minimal song containers, release membership/sequencing, fixed production stages and non-blocking milestone debt.
- **07.02 Songwriting & Composition Workspace** — immutable idea inbox, lyric line attribution and transposable chord/arrangement charts.
- **07.03 Contributors, Access & Confidentiality** — per-song roster/claim events, scoped invitations, role-derived vault access, sensitivity and NDA gates.
- **07.04 Audio Version Control & Lineage** — immutable version records, mutable canonical slots, take/comp lineage, exact-version tempo/key descriptor corrections and authority-aware release-origin proposals, stem standards, integrity/plausibility and A/B comparison.
- **07.05 Review, Feedback & Approval** — timestamp/range comments, safe share links, Producer triage, version-pinned approvals and advisory revision counting.
- **07.06 Sessions, Documentation & Recall** — first-class sessions, close/capture arbitration, labelled archives and combined track/channel/recall sheets.
- **07.07 Mix & Master Workflow** — reference briefs, variant matrix, objective loudness reporting and purpose-labelled/parallel deliverables.
- **07.08 Delivery, Readiness & QC** — pinned recipient packages, narrow objective QC, target-specific debt ledger and source declarations.
- **07.09 DAW Bridge & Capture-at-Source** — future watch-folder/parser/local capture surfaces behind explicit evidence gate; no non-web client in v1.

## Acceptance Criteria

- **AC-PRJ-01 — Create/manage song:** Given Acting party holds song or project owner authority for the owning party and a title is supplied; a lifecycle or archive move additionally requires the song to be in a state the transition is legal from — `active` and `shelved` interconvert, `shelved` moves to `archived`, and `unadministered` returns to `active` only through restored Shard 01 authority, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Title-only creation; owning party required; lifecycle and stage separate; non-empty song archives but never hard-deletes, and (6) return Song version and owner/context audit commit; if the flow cannot complete, `VALIDATION_FAILED` for a missing title, `FORBIDDEN` for an actor without owner authority, `ACTING_CONTEXT_STALE` or `VERSION_CONFLICT` when the acting context or expected song version has moved; a duplicate proposal stays scoped to the owner and never auto-merges, a non-empty song archives rather than hard-deleting, and if the owner account disappears the song becomes unadministered or authority transfers through Shard 01 while all records remain.
- **AC-PRJ-02 — Assemble release:** Given Actor holds owner authority on the release container, every song being added is readable to that actor, the sequence position is free within the release, any pinned master names an exact readable `audio_version`, and the release membership version is supplied, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Owner adds song membership edges, sequence, variant and pinned master; release never copies song/version truth, and (6) return Ordered membership version saved; readiness re-derived; if the flow cannot complete, `FORBIDDEN` for an actor without release owner authority, `VALIDATION_FAILED` for a duplicate sequence position, `VERSION_CONFLICT` when a competing ordering edit committed first, `CANONICAL_UNSET` when the named master pin has no target and `INTEGRITY_FAILED` when that target is compromised — the pin never falls back to latest; a refused membership edit leaves the prior ordering and its derived readiness projection unchanged.
- **AC-PRJ-03 — Move production stage:** Given Actor holds song owner or Producer stage authority within the song's profile, the target stage is a member of the fixed versioned `ProductionStage` set, and the current stage pointer version is supplied, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized actor selects fixed stage; deadlines/capture prompts remain advisory and non-blocking, and (6) return Stage event and completeness debt update; if the flow cannot complete, `VALIDATION_FAILED` for a stage outside the fixed set — arbitrary admin or user stages are never accepted — `FORBIDDEN` for an unauthorized actor and `VERSION_CONFLICT` when the stage pointer moved first; advisory deadlines and capture prompts never block the move, and an unmet milestone records non-blocking completeness debt instead of refusing the transition.
- **AC-PRJ-04 — Capture idea or edit creative doc:** Given Actor holds an authorized creative-record role on the song — owner, Producer, or a contributor acting for itself — and supplies the document's expected version for a lyric or chart edit; an offline idea capture requires only the authenticated acting context and its local timestamp, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Offline idea is immutable and nameless; lyrics/charts version independently with line attribution/section anchors, and (6) return Artifact/version/origin and local timestamp preserved; if the flow cannot complete, `FORBIDDEN` for an actor without a creative-record role, `VALIDATION_FAILED` for a line attribution or section anchor that does not resolve, `VERSION_CONFLICT` when a competing document version committed first; an offline idea replays under its original idempotency key and its immutable, nameless origin and local timestamp survive that replay, and a refused edit never rewrites a prior version, which remains independently addressable.
- **AC-PRJ-05 — Manage roster:** Given Actor's current per-song union of roles carries the `roster:write` capability, the subject resolves by explicit disambiguation to a party, unclaimed shell or entity — name search alone never binds an existing party — and the roster projection version is supplied; ending involvement requires an involvement currently in `active`, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized role adds party/shell/entity plus canonical/pending role; roster event emits Shard 07 claim; removal separates involvement from attribution, and (6) return Roster projection, claim command and notices commit; if the flow cannot complete, `FORBIDDEN` without `roster:write`, `VALIDATION_FAILED` for an ambiguous subject, `ROLE_UNRESOLVED` when the Shard 07 taxonomy is unavailable — the event still commits a bounded literal and claim while derived access fails closed until the role profile resolves — and `VERSION_CONFLICT` on a competing roster edit; ending involvement revokes derived access immediately but can never delete roster, credit or version history, and claim retraction is a separate Shard 07 or Shard 06 path.
- **AC-PRJ-06 — Invite contributor:** Given Actor's current per-song union of roles carries the `may_invite` capability, the invitation names its roster event entries, an intended recipient binding and an expiry, the requested disclosure tier is supported by the named material — T1 requires a non-confidential pinned rough and T2 requires a current NDA terms version — and the recipient is not under contact suppression, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Invite discloses context before signup through T0/T1/T2 ladder; asset access binds verified identity/NDA, not bearer link, and (6) return Delivery state, typed response and scoped grant recorded; if the flow cannot complete, `FORBIDDEN` without `may_invite`, `VALIDATION_FAILED` for a tier the named material cannot support, `NDA_REQUIRED` when a T2 grant is requested before verified identity and NDA acceptance; a forwarded invite yields T0 context only and the bearer never inherits T1 or T2 access, and decline, expiry, suppression or delivery failure records a typed response while roster attribution survives the invitation.
- **AC-PRJ-07 — Access vault asset:** Given The requesting identity holds at least one live roster role on the song whose `role_version` carries a `vault_role_class` at or above the asset's `SensitivityClass`, is not blocked, has accepted the current NDA terms version where the asset requires one, and the asset blob is in a readable residency rather than tombstoned, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Policy intersects all current song roles with asset sensitivity and accepted NDA version; denied access is explained, and (6) return Short-lived stream/download grant or explicit denial; if the flow cannot complete, `FORBIDDEN` or `ACCESS_REVOKED` with an explained denial that names the required action without leaking hidden asset names, `NDA_REQUIRED` when acceptance is missing, `ROLE_CLASS_UNASSIGNED` when the role carries no `vault_role_class` — access floors to `review`, anything above it is denied with an explanation and a `pending_role_alias` never reaches a higher class — and `ASSET_NOT_FOUND` for an unreadable target; revocation mid-stream fails new reads immediately and invalidates the active grant and signed URL, while bytes already downloaded can neither be recalled nor represented as protected.
- **AC-PRJ-08 — Upload audio version:** Given Actor holds an upload-authorized roster role on the song, the uploaded bytes have reached quarantine and settled to a stable size and checksum, the command carries its idempotency key, and the version type is human-confirmed rather than silently applied from the filename suggestion; an author is always named, with unknown authorship recorded as visibly unconfirmed, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Manual upload settles, hashes and creates immutable record/bytes residency; parent inferred or asked; no silent type/canonical choice, and (6) return Version sequence, lineage and integrity state commit; if the flow cannot complete, `UPLOAD_UNSETTLED` while the blob is still uploading or settling, `INTEGRITY_FAILED` when the checksum or plausibility check fails and the version terminates in `integrity_failed`, `VALIDATION_FAILED` for missing required metadata and `FORBIDDEN` for an unauthorized uploader; a duplicate or replayed offline upload deduplicates by hash and idempotency key and differing metadata becomes an attributed correction rather than an overwrite, and ambiguous parentage commits the version as root or sibling and asks for lineage later — never blocking and never inventing a parent.
- **AC-PRJ-09 — Nominate canonical:** Given Actor holds canonical-nomination authority on the song within its profile, the target `audio_version` is visible to that actor and carries a passing integrity state, the stage, variant and format slot exists and its reservation or proxy state permits this actor, and the expected slot version is supplied for compare-and-set, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized actor deliberately sets/clears one stage/variant/format slot against exact version; pointer moves, log is immutable, and (6) return Slot version and roster notification commit; if the flow cannot complete, `VERSION_CONFLICT` when the expected slot version has moved, `FORBIDDEN` for an actor outside the slot's reservation or song profile, `CANONICAL_UNSET` when the named target is missing — the system refuses to guess and no upload ever auto-selects itself — and `INTEGRITY_FAILED` when the target is compromised, which raises a blocking alarm and preserves the existing pointer until an explicit clear or replacement rather than falling back to latest; re-nominating the same target is idempotent and clearing a slot is always permitted.
- **AC-PRJ-10 — Compare versions/stems:** Given The requesting identity resolves vault access for every version or stem in the comparison set under the same role, sensitivity, block and NDA intersection as PRJ-07, and each target's bytes are in a streamable residency; no revision or slot precondition applies because playback is read-only, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized user streams lower-bitrate fallback if needed, loudness-matches by default and sees degraded state, and (6) return Playback has no canonical/evidence side effect; if the flow cannot complete, `FORBIDDEN`, `ACCESS_REVOKED` or `NDA_REQUIRED` for any target the identity may not stream and `ASSET_NOT_FOUND` for an unreadable blob; when the full-rate stream is unavailable the player falls back to a lower bitrate and announces the degraded state rather than failing silently, and no failed, offline or degraded comparison writes canonical, evidence or analytics state.
- **AC-PRJ-11 — Comment/review version:** Given Actor may read the exact immutable `audio_version` under its own review scope — a roster role or a pinned share-link policy — the comment audience is fixed before text entry, and the anchor resolves to a point or range inside that version; an edit is legal only within five minutes of authoring and only while no reply or triage exists, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Comment anchors point/range to immutable version with fixed audience; explicit carry follows direct lineage only, and (6) return Comment/version/audience hash commits; if the flow cannot complete, `FORBIDDEN` when the actor may not read the version or reaches outside its own audience, `VALIDATION_FAILED` for an anchor that falls outside the version, `VERSION_CONFLICT` when the comment body history moved first; past the five-minute window an edit is refused and only an attributed correction or retraction remains — retraction hides the body but preserves state and history — and a carried comment whose mapping is uncertain enters the unplaced list with original playback rather than rendering a guessed marker.
- **AC-PRJ-12 — Share private review:** Given Actor is the version's creator or holds share authority on the song, the named `audio_version` is readable to that actor, and the link carries its recipient binding, watermark policy, analytics mode and expiry; a public link additionally requires the actor to have been shown and to have acknowledged its explicitly weaker identity, analytics and watermark guarantees, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Creator issues per-recipient or explicitly weaker public link pinned to version, expiry, watermark and disclosed analytics mode, and (6) return Link, recipient policy and revoke authority recorded; if the flow cannot complete, `FORBIDDEN` for an actor without share authority, `VALIDATION_FAILED` for a per-recipient link missing its recipient binding or policy fields, `ASSET_NOT_FOUND` when the pinned version is unreadable; revocation invalidates active URLs, tokens and future streams immediately while downloaded bytes cannot be reclaimed, and a roster-authenticated human who opens the link resolves to the project identity without link analytics so the creator sees an explained non-count rather than a silent gap.
- **AC-PRJ-13 — Triage feedback:** Given Actor holds the Producer role on the song within its profile, the comments being triaged are open and inside that actor's review scope, and every accept or reject carries an author-visible reason, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Producer clusters/flags contradictions and accepts/rejects with reason; assistant never resolves creative conflict, and (6) return Triage state and author-visible reason commit; if the flow cannot complete, `FORBIDDEN` for an actor without the Producer role, `VALIDATION_FAILED` when a decision arrives without its reason, `VERSION_CONFLICT` when a competing triage decision committed first; contradictory feedback is clustered and flagged for the Producer and never resolved by the assistant, so an unadjudicated creative conflict stays open and visible rather than being auto-closed.
- **AC-PRJ-14 — Approve version:** Given The signer belongs to the gate's configured approver set for the song, or is a recorded proxy for such a member, the exact `audio_version` under approval is readable to the signer, and both its open-comment snapshot hash and the approver-set version resolve at signing time, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Configured approver/proxy signs exact version/open-comment snapshot; later version requires new approval, and (6) return Append-only approval evidence recorded; if the flow cannot complete, `FORBIDDEN` for a signer outside the configured approver set, `VALIDATION_FAILED` when the version or open-comment hash cannot be pinned, `VERSION_CONFLICT` when the approver-set version moved between read and sign; a proxy signature is recorded as visibly weaker rather than refused, and a later version never inherits an approval — it requires a new one — while the existing append-only evidence is never rewritten.
- **AC-PRJ-15 — Create/close session:** Given For creation, an authenticated actor confirms an inferred or manual session and exactly one owner derives from the creating context, with attendance asserted by a human because no one is ever auto-present; for close, the session is active and the actor holds session-owner or Producer authority; for reopen, the same session closed within the last six hours, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Human confirms inferred/manual session, attendance and owner; close commits before capture asks and supports bounded reopen, and (6) return Session state/version and close event commit; if the flow cannot complete, `FORBIDDEN` for an actor who is neither session owner nor an authorized Producer, `VALIDATION_FAILED` when no single owner resolves or a reopen falls outside the six-hour window, `VERSION_CONFLICT` on a competing close; the close transaction commits before any capture ask is dispatched so a dispatch failure never rolls the close back, and a reopen re-arms the moment but never recalls asks already dispatched.
- **AC-PRJ-16 — Complete close prompt:** Given A committed session close event has dispatched a capture ask to this actor within the moment's tier budget — Tier 1 contributor asks fire independently and non-blockingly, and the single Tier 2 heavyweight ask fires only for the Producer and only when its prefill is non-empty — and v1 prefill is drawn from the session roll, roster and manual project facts only, never from DAW parsing or source-path observation, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Tiered moment asks prefilled contributor facts, then at most one Producer heavyweight ask; silence/dismissal accrues debt only, and (6) return Stable ask/answer IDs; session remains closed; if the flow cannot complete, `VALIDATION_FAILED` for an answer that does not match its stable ask ID or expected payload shape and `FORBIDDEN` when an actor answers another party's ask; silence or dismissal is never an error — it accrues completeness debt only, the session stays closed, and the same stable ask and answer IDs remain answerable later so an unanswered ask never becomes a false completion.
- **AC-PRJ-17 — Build handoff package:** Given The chosen delivery target is backed by a platform-owned `recipient_spec_version` — an unowned target is unavailable — the actor holds package authority on the song or project, and every canonical slot the spec requires resolves at resolve time to an exact readable `audio_version` that is then pinned, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) User chooses owned recipient spec; canonicals resolve then pin; exact required assets only; integrity blocks, other gaps warn, and (6) return Immutable package manifest/artifact and validation report; if the flow cannot complete, `CANONICAL_UNSET` when a required slot has no target, `INTEGRITY_FAILED` when a pinned asset's checksum fails, which blocks the package and names the exact file and action while every other gap only warns, `SOURCE_STALE` when a source version changes during the build, which forces a rebuild rather than producing a mixed-version package, and `FORBIDDEN` for an unauthorized actor; a partly written artifact is quarantined unsealed so the canonical request retries idempotently from the pinned manifest.
- **AC-PRJ-18 — Run QC/readiness:** Given The actor may read the song or package under evaluation, a delivery target backed by an owned recipient spec version is selected because readiness is always target-specific and no global score exists, and the sources under check are readable at their current versions, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Target-specific objective checks and actionable debt derive on demand; unverifiable is distinct from passed, and (6) return Live readiness projection or pinned package result; if the flow cannot complete, `FORBIDDEN` when the actor may not read the subject and `ASSET_NOT_FOUND` for an unreadable source; a check the platform cannot compute renders `unverifiable` and is never reported as passed, an inaccessible dependency renders as an `opaque_dependency` gap that reveals no protected field, name or count, and a warning dismissed once stays dismissed for the same project and check version.
- **AC-PRJ-19 — Declare source use:** Given Actor holds a contributor or higher role on the song and may read the asset or section being annotated, and the declaration names a state from the `none`, `unknown`, `declared` and `not_reviewed` set, supplying source kind and details whenever the state is `declared`; declaration is voluntary and manual in v1 because no DAW prompt or automatic source detection exists, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Authorized contributor appends sample/interpolation/AI source fact to asset/section; unknown/not-reviewed/none remain distinct, and (6) return Declaration version and downstream clearance reference emitted; if the flow cannot complete, `FORBIDDEN` for an actor without a contributor role on the song, `VALIDATION_FAILED` for a state outside the enum or a `declared` entry missing its kind and details, `ASSET_NOT_FOUND` for an unreadable target; removing a declaration supersedes rather than deletes and returns the state to the honest `not_reviewed` default, and a refused declaration never mutates rights, clearance or split state, which are owned downstream.
- **AC-PRJ-20 — Activate DAW bridge:** Given The actor is the song or project owner, the four-part architecture evidence gate is recorded as reviewed — costed agent build, signing and support model; a threat model proving least filesystem read scope; per-DAW real-session validation with legal review of the parsing format; and product evidence justifying a permanent desktop surface — the requesting agent reports a supported signed version, and a revocable device grant with an allowed-roots attestation is presented; no v1 build satisfies this gate, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Owner may enable only after architecture evidence gate, supported-agent version and least-read-scope proof; unavailable in v1, and (6) return Signed device grant/agent state or gated denial; if the flow cannot complete, `BRIDGE_DISABLED` for every v1 request, returned with the evidence-gate explanation and no hidden desktop dependency; once the gate passes, `FORBIDDEN` for a non-owner, `VALIDATION_FAILED` for an unsupported or unsigned agent version, and a denial for any device grant whose allowed-roots attestation exceeds least-read scope — activation is a new architecture decision propagated downstream and a feature flag alone can never authorize it.
- **AC-PRJ-21 — Open/close revision round:** Given A `revision_agreement` exists for the song — without one the surface is hidden and `RoundState` stays `disabled` — the actor holds the Producer role because rounds are producer-writable and contributor-readable, opening requires an accepted triage batch to open against, and closing requires a delivered new immutable `audio_version` for that round, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Producer opens a round against an accepted triage batch and closes it on delivery of a new immutable version; the count informs and never blocks or bills; a batching window accumulates drip-fed feedback into one round, and (6) return Round version, contents manifest and both-party-visible count commit; if the flow cannot complete, `FORBIDDEN` when a contributor attempts to write, `VALIDATION_FAILED` when no accepted triage batch or delivered version is supplied, `VERSION_CONFLICT` on a competing round edit; an unreadable count renders `RoundState` as `error` with retry and never as a zero count, exhaustion is visible to both parties and never blocks so no work is refused and nothing is billed, a trivial correction opens no round, and a disputed count or scope classification routes to Shard 06 with the round contents manifest as evidence because the platform never classifies scope itself.
- **AC-PRJ-22 — Maintain mix brief:** Given Actor holds an authoring role on the song's mix brief and each reference resolves by kind — an `external_link` carries an external URI because commercial references are stored as links only and the platform never hosts or streams third-party playback, while a `platform_version` names an in-platform unreleased version owned by the same party; no production stage, approval or contract state gates the brief, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Author adds reference pointers with timestamped annotations and optional prose; a reference-only brief is complete; contradictory references are surfaced, never adjudicated, and (6) return Living brief version and annotation commit; no stage gate; if the flow cannot complete, `FORBIDDEN` for an actor without authoring rights, `VALIDATION_FAILED` when a reference's kind and payload disagree or when third-party audio is offered for in-platform hosting, `VERSION_CONFLICT` when a competing brief edit committed first; contradictory references are both surfaced with their annotations and never adjudicated by the platform, a reference-only brief with no prose is complete rather than incomplete, and a mid-mix revision is expected — the change appends to the attributed history rather than being refused.
- **AC-PRJ-23 — Author recall sheet:** Given The session the sheet belongs to exists and the actor's role reaches the session's sensitivity class, which the sheet inherits; authoring is actor-initiated at any time before the paper is lost, is never prompted and never rides along with the session close or capture prompt, and a prior session's sheet may be supplied as the template that is the primary completion mechanism, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) One combined track sheet, channel map and recall sheet document carries a derived half and an analogue half; a photograph of the paper sheet is a complete first-class artifact; optional typed derived rows may be generated from a pinned session snapshot and optional typed analogue rows may be copied from a prior template or entered manually; authoring is never prompted and never rides along with the close/capture prompt, and (6) return Sheet version with attributed row edits, source refs and inherited session sensitivity; if the flow cannot complete, `FORBIDDEN` when the actor's role does not reach the session's inherited sensitivity class, `VALIDATION_FAILED` for an unreadable or unsupported paper photograph or for a row whose discriminant and payload do not match, `VERSION_CONFLICT` when a competing sheet edit committed first; a photograph-only sheet is valid and complete, no OCR or extraction is performed or implied, and a failed template copy leaves both source and target sheets unchanged.
- **AC-PRJ-24 — Grant/revoke Operator recall projection:** Given The actor is the Producer or session owner with `session:share_recall_projection`, the recipient resolves to one verified Operator party, and the grant pins an exact recall-sheet version belonging to that session, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize, (4) enforce revision and idempotency, (5) Create, renew or revoke an expiring per-recipient grant whose server-derived projection includes only analogue microphone, signal-path, patch and room fields with sheet-local line references, and (6) return Grant version and projection-policy hash; if the flow cannot complete, `FORBIDDEN` for a non-owner/non-Producer or an unbound recipient, `VALIDATION_FAILED` when the sheet version belongs to another session or the expiry is invalid, and `VERSION_CONFLICT` when the grant moved first. A successor sheet version is not readable until explicitly re-granted; revocation invalidates tokens and new reads immediately; the paper asset, derived rows, track/channel names and refs, songs, creative text, attendance and other session context are never projected.
- **AC-PRJ-25 — Review release-origin version descriptor correction:** Given A pending correction proposal names one exact `audio_version`, one `VersionDescriptorField`, the prior value hash, corrected value/reason, release origin and shared correction ID; the reviewer is that version's owner or a Producer whose current roster role carries explicit `version:edit_descriptors` authority on that exact version; and the command supplies expected proposal and descriptor revisions, when the actor invokes this flow, then the system MUST (1) validate inputs, (2) authenticate and resolve acting context, (3) authorize against the exact audio version rather than the Song or release, (4) enforce revision and idempotency, (5) accept by appending an attributed `version_descriptor_correction` or reject by recording reviewer/reason without changing the version projection, and (6) return one terminal proposal outcome and emit `project.version-descriptor-correction.changed.v1` without descriptor values. If the flow cannot complete, `FORBIDDEN` leaves the proposal pending when reviewer authority is absent or revoked; `VERSION_DESCRIPTOR_TARGET_STALE` leaves it pending when the expected prior value or descriptor revision moved; `DESCRIPTOR_PROPOSAL_CONFLICT` returns the already committed winner when review raced. Acceptance updates linked release projections through Shard 22; rejection leaves the initiating release-local correction intact and changes no other release. No path writes a Song attribute, overwrites history or exposes project content to a release-only actor.

### Global Interaction Rules

- Commands carry `actor_person_id`, `acting_party_id?`, `acting_context_version`, `idempotency_key`, `expected_version?`, `request_id` and song/project scope.
- Container ownership, workspace access, contribution credit, rights ownership and payment are independent state machines.
- Records are immutable/versioned; mutable pointers such as stage/canonical/access projection have append-only movement logs.
- Non-blocking capture creates explicit completeness debt; missing/unknown/unverifiable never becomes false completion.
- Confidentiality/sensitivity authorization precedes listing, counts, search, streaming, URLs, comments, analytics and packages.
- V1 surfaces never imply DAW observation, environment verification, missing-media parsing or automatic source detection.

## Accessibility

- Boards automatically switch to dense semantic tables at high counts; drag interactions have keyboard reorder/actions and announced results.
- Creative documents preserve headings, line/section anchors and attribution in reading modes; charts provide transposed text views.
- Waveform comments and A/B comparison have time inputs, transcript/linear comment lists and keyboard-complete playback controls.
- Access denial names required action without leaking hidden asset names; NDA/consequence text precedes acceptance.
- Close prompts are short, focus-stable and never trap dismissal; silence/unverified/debt states use dignified text, not red failure styling.
- Readiness/QC/package gaps are ordered semantic lists with exact affected file/action and unverifiable distinct from passed.
- Offline/conflict/degraded playback states are announced and preserve work; no visual graph is required to understand lineage.

## Edge Cases

| Case | Required result |
|---|---|
| Owner account disappears | Song becomes unadministered or authority transfers through Shard 01; records remain. |
| Role taxonomy unavailable | Roster/claim commits literal; access fails closed until role profile resolves. |
| Invite forwarded | T0 context only; T1/T2 access binds intended/verified identity, not bearer. |
| Access revoked mid-stream | New reads fail immediately; active grant/token invalidated; downloaded bytes cannot be recalled. |
| Duplicate/offline upload | Hash/idempotency deduplicates record; differing metadata becomes attributed correction, not overwrite. |
| Parent lineage ambiguous | Version commits as root/sibling and asks later; never blocks or invents parent. |
| Authorized release-origin descriptor correction | Append once under the shared correction ID and update the exact version projection; no proposal and no Song mutation. |
| Release-origin actor lacks exact-version descriptor authority | Create one pending proposal; reveal no project content to the submitter beyond safe status. Release-local correction remains effective. |
| Proposal target or authority changes during review | Expected revisions fail closed with `VERSION_DESCRIPTOR_TARGET_STALE` or `FORBIDDEN`; proposal remains pending for an authorized explicit decision and no partial correction is appended. |
| Two reviewers decide one proposal concurrently | One expected-version transition wins; loser receives the committed terminal outcome. Acceptance appends once; rejection never overwrites the initiating release-local correction. |
| Canonical target compromised | Alarm and explicit unset/replacement; no silent fallback to latest. |
| Comment carried with low confidence | Unplaced list with original playback; no guessed marker. |
| Link opens under roster account | Resolve to project identity without link analytics; creator sees explained non-count. |
| Session auto-closes then resumes | Reopen within six hours; dispatched asks remain, close batch rules prevent duplicate moment. |
| Package source changes during build | `SOURCE_STALE` and rebuild; no mixed-version package. |
| Unknown DAW/archive format | Preserve bytes and label manifest/parsing unavailable; never verified. |
| Integrity check fails | Block package and name exact file/action; other QC warnings remain non-blocking. |
| V1 source declaration lacks DAW prompt | Voluntary manual declaration only; not-reviewed remains honest default. |
| Local agent requested in v1 | `BRIDGE_DISABLED` with evidence-gate explanation; no hidden desktop dependency. |
| Roster role carries no `vault_role_class` | Access floors to `review` and returns `ROLE_CLASS_UNASSIGNED` with an explained denial above it; a `pending_role_alias` never reaches a higher class. |
| Revision rounds exhausted | Exhaustion is visible to both parties and never blocks; no work is refused and nothing is billed. |
| Small fix requested | No round opens; the count is advisory and a trivial correction never consumes one. |
| Round count or scope disputed | Routes to Shard 06 with the round contents manifest as evidence; the platform never classifies scope itself. |
| No revision agreement exists | The revision surface is hidden; rounds are off by default. |
| Brief references contradict | Both are surfaced with their annotations; the platform never adjudicates between them. |
| Brief revised mid-mix | Normal and expected; the brief is living and carries an attributed change history. |
| Recall sheet exists only as a photograph | Valid and complete; no structured extraction or OCR is performed or implied. It yields an empty Operator projection because the photograph itself is never projected. |
| Recall projection grant is revoked during an Operator read | New chunks/requests fail `ACCESS_REVOKED`; active tokens and caches are invalidated. Bytes already rendered cannot be recalled, and no successor sheet version becomes readable. |
| Analogue row contains a creative track/channel reference | Projection replaces the internal reference with a sheet-local line ref and omits labels/free text not admitted by the projection policy; it never leaks the source name or ID. |
